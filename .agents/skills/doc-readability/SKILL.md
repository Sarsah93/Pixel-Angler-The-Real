# 문서 가독성 규칙

## 0. 원칙

문서는 "다음 세션의 나(또는 다른 에이전트)"가 **스크롤로 훑는 화면**이다.
정보 밀도보다 **스캔 가능성**이 우선 — 같은 내용이면 빈 줄과 목록이 있는 쪽이 이긴다.
(2026-08-10 사용자 지시 — "섹션은 잘 나눴는데 띄워쓰기가 안 되어 가독성이 떨어진다".)

## 1. 빈 줄 (가장 자주 어기는 것)

- 제목(`#`/`##`/`###`) **앞뒤로 빈 줄 1개**. 제목 바로 다음 줄에 본문을 붙이지 않는다.
- 문단과 문단, 목록 블록과 다음 블록 사이 **빈 줄 1개**.
- 볼드 소제목(`**1. 항목**`) 방식으로 항목을 나눌 때는 **항목 사이마다 빈 줄** — 붙이면 벽이 된다.
- 표 앞뒤로 빈 줄 1개 (없으면 렌더가 깨지는 뷰어도 있다).

## 2. 한 줄 = 한 가지

- 한 줄에 여러 주제를 `·`/`/`/`+`로 잇지 않는다 — **3개 이상 나열이면 목록으로 분해**.
- 줄 길이 상한 **≈ 200자**. 넘으면 이어쓰기 들여쓰기(2칸)로 줄바꿈하거나 하위 불릿으로 쪼갠다.
- **한 줄짜리 거대 블록 절대 금지** — 여러 차수·여러 주제를 한 문단에 압축하지 않는다.
  (실사례: 구 IMPLEMENTATION_PLAN 3행 = 20~80차 히스토리가 **한 줄 8,183자** — 2026-08-10 제거.)

## 3. 블록인용(`>`) 사용 제한

- `>`는 **짧은 주의·인용·정책 고지(1~4줄)에만** 쓴다.
- 항목 나열·구현 순서·체크리스트를 blockquote로 만들지 않는다 — `>` 연속 5줄 이상 = 벽.
  일반 목록(`-`, `1.`) + 빈 줄로 바꾼다.
- blockquote 안에 목록·볼드 소제목을 중첩하는 구조는 금지 (구 "다음 착수" 섹션 사례 — 2026-08-10 해체).

## 4. 히스토리 위치 (스킬 `work-log`와 연동)

- 긴 서술은 **워크로그 1곳**. `AGENTS.md` §9·`IMPLEMENTATION_PLAN.md`에는 **요약 3~5줄 + 링크**.
- "최종 업데이트" 류 헤더에 히스토리를 **누적하지 않는다** — 최신 1건 + 원장 포인터만.
- 같은 내용이 두 문서에 길게 있으면 한쪽을 링크로 바꾼다.

## 5. 차수 요약 양식 (PLAN·AGENTS §9)

```markdown
### ✅ 직전 완료 (NN차, YYYY-MM-DD) — 한 줄 제목

- 핵심 변경 1 (1~2줄)
- 핵심 변경 2
- 검증: … · 빌드 4/4 · typecheck 0
- 상세: [워크로그 NNN](../docs/wiki/03-WORKLOG/….md)
```

- 불릿 3~5개, 각 1~2줄. 워크로그 링크 필수.
- "다음 착수" 항목은 blockquote가 아니라 **볼드 소제목 + 하위 불릿 + 항목 간 빈 줄**로.

## 6. 자기 검사 (쓰고 나서 30초)

- [ ] 200자 넘는 줄이 있는가 → 분해 (표 셀은 예외 허용)
- [ ] `>` 연속 5줄 이상이 있는가 → 목록으로
- [ ] 제목/블록 사이 빈 줄 누락 → 추가
- [ ] 히스토리가 요약 문서에 길게 들어갔는가 → 워크로그로 이동 + 링크

빠른 점검 명령 (긴 줄 탐지):

```powershell
$l=[IO.File]::ReadAllLines("<파일>"); $i=0; $l | %{ $i++; if($_.Length -gt 200){ "L$i ($($_.Length))" } }
```
