## 0. 왜 다시 쓰나 (사용자 원문)

285차 비평(이 차수의 뿌리):

> 이렇게 대화하듯이 되어야 해. 너가 지금 해놓은 문맥은 혼자서 대답을 다해버리고, 강제로 내용을 주고 받는 대화 하나 없이
> 그냥 정보를 한번에 전달하는 형태야. 그건 잘못된 대화 방법이야.

지금 대부분의 편은 의뢰인이 **한 덩어리 대사**로 사정 · 할 일 · 이유를 한 번에 쏟고, 주인공은 고를 말 라벨로만 답한다.
이것을 **사람끼리 실제로 주고받는 대화**로 바꾼다 — 주인공이 묻고, 되묻고, 반응하고, 상대가 그에 답하며 정보가 조금씩 나온다.

**기준 = 286차 시범 「해녀의 딸」** — 반드시 먼저 읽는다:

- 그것을 옮긴 코드: `packages/core/src/db-schema/StoryTalkN01.ts` (1~210줄 받는 자리 · 끝까지 = 목표 대화 · 끝내는 자리)
- 집필 도구: `packages/core/src/db-schema/StoryTalkKit.ts` · 몸짓 표 `packages/core/src/rules/TalkActs.ts`
- 타입: `packages/core/src/types/Story.ts` 의 `TalkBeat` · `TalkNodeDef` · `TalkChoiceDef` · `TalkEndDef`(290 `offer` 칸) · `StoryTalkDef`

## 1. 무엇을 쓰나

맡은 묶음의 **의뢰인이 있는 편마다** 대본 둘:

| 자리 | `at` | `id` 꼴 | 대화 상대(`npcId`) | 끝 |
|---|---|---|---|---|
| 받는 자리 | `'offer'` | `m1_02_offer` (편 id 소문자 · `-` → `_`) | 그 편 의뢰인(`q.giver`) | 받기 · (곁가지만) 미루기 · 거절 |
| 끝내는 자리 | `'complete'` | `m1_02_done` | 그 편 의뢰인 | 보상 답(`complete`) · 결말(`ending`) |

- 의뢰인이 없는 편(혼잣말 — M1-01 · M7-08)은 쓰지 않는다.
- **이미 대화가 있는 편**(문맥 파일 「이미 있는 대화」)은 그 파일의 대화를 **대본 장면으로 고쳐 쓴다** — 받는 · 끝내는 자리만이 아니라
  그 파일의 목표(`objective`) · 행동(`action`) 대화도 전부. 이때 **단계 id · 고를 말 id · 표시(flags) · 우호도 · 조건(requires) · 끝(end) · 결말(ending)은 그대로** 둔다
  (뒤 편 · 결말 · 세이브가 그 id를 읽는다). 바꾸는 것은 대사 꼴뿐이다:
  `say(lineKo, lineEn, [고를 말…], speaker?)` → `scene([line(...), line(P, ...), ...], { choices: [같은 고를 말…], note })`.
  고를 말에는 `say`(실제로 하는 말) · `note`(일지 한 문장)를 더한다. 이미 있는 대화에 없는 받는 · 끝내는 자리는 새로 쓴다.
- N01-5(시범)는 손대지 않는다 — 단 **호칭만** 고친다(§4: 주인공의 「아저씨」 → 「바람 씨」).

파일: 묶음 이름마다 하나 — `packages/core/src/db-schema/StoryTalk<묶음>.ts`, 내보내는 이름 `TALKS_<묶음>` (`StoryTalkM1.ts` → `export const TALKS_M1: StoryTalkDef[]`).
파일 머리는 한국어 JSDoc(무엇 · 인물 말투 요약 · 남기는 표시). 다른 파일(등록 `StoryTalks.ts` 포함)은 고치지 않는다 — 등록은 묶음이 다 모인 뒤 한 번에 한다.

## 2. 대화를 쓰는 규칙

### 2-1. 주고받기

- **의뢰인 한 줄 = 한두 문장(140자 이하).** 사정 → 할 일 → 이유를 한 번에 붙이지 않는다. 덩어리 사이에 주인공이 끼어든다.
- 주인공은 사람이 실제로 할 법한 말로 끌어낸다 — 「무슨 일인데요?」 · 「그래서 어떻게 됐어요?」 · 「제가 뭘 하면 될까요?」 · 「왜 하필 저예요?」 ·
  맞장구 · 놀람 · 머뭇거림(「…」) · 속말(`(괄호 — 주인공 속으로)`).
- 받는 자리 첫 장면(`start`) = 박자 **6~14개**(주인공 줄 2개 이상) → 고를 말 2~3개. 갈래 장면은 2~6박자. 갈래는 한두 번 더 이어져도 된다.
- 끝내는 자리 = 주인공이 한 일을 짧게 알리거나 물건을 내밀고 → 의뢰인이 반응하고 몇 마디 주고받은 뒤 → 보상 답마다 고를 말(`say` = 실제 말)
  → `end: endTalk({ complete: '<보상 답 id>', lineKo, lineEn })` — `lineKo`는 의뢰인의 마지막 말(옛 응답을 바탕으로 · 대화창이 따옴표를 붙인다).
- 할 일 · 장소 · 만날 사람 · 가져올 것은 대본 안에서 **반드시 한 번은** 말로 나온다(목표 줄과 맞게). 옛 받는 말이 알려 주던 사실을 빠뜨리지 않는다.
- 일지 한 문장(`note`): 장면마다(`scene(..., { note })`)와 뜻 있는 고를 말마다 — **주인공 1인칭 과거 · 1~2문장** · 무엇을 들었고 어떻게 느꼈나.
  일지에는 `{player}`를 쓰지 않는다. 인물은 이름으로(「정옥선 씨는 …」).
- 진행 중 물음(287 — 문맥 파일)과 같은 말을 반복하지 않는다.
- 몸짓은 드물게(장면당 0~3): 말이 멈추는 것(`cig_light` · `cig_puff` · `cig_out` · `give` · `sigh` · `laugh` · `silence`)은 따로 `act(누가, 몸짓)` 박자로,
  말과 함께 하는 것(`nod` · `shake_head` · `look_away` · `look_sea` · `look_up` · `peer` · `receive`)은 `line(누가, 한, 영, { act })`.
  **담배는 바람만** 피운다(설정). 다른 인물에게 담배를 지어 붙이지 않는다. `give` 몸짓은 옛 답의 결과가 실제로 물건을 줄 때만(새 물건을 만들지 않는다).
- `give(...)` 박자(장면 속 받기)는 쓰지 않는다 — 결과는 옛 답에 묶는다(§3).

### 2-2. 옛 답을 잃지 않는다 (가장 중요 — 검사가 본다)

- **받는 자리의 받는 끝**은 옛 받는 답에 묶는다: `end: endTalk({ accept: true, offer: '<옛 답 id>' })`.
  옛 답의 결과(우호도 · 표시 · 평판 · 돈 · 물건)와 기록이 그대로 붙는다. 뜻이 가장 가까운 옛 답을 고른다.
  옛 답이 여럿이면 갈래를 나눠 **옛 답마다 하나씩** 닿게 쓰는 것이 기본이다(특히 표시가 있는 답 — 검사가 「표시를 대본이 남기지 않는다」로 잡는다).
- 옛 미루는 답(`decline: true` 결과)은 `end: endTalk({ decline: true, offer: '<그 id>' })`.
- **끝내는 자리의 보상 답은 전부** 어딘가의 끝에 묶는다(품삯 · 가르침 · 사양 · 청탁 … — 검사가 빠진 답을 잡는다).
- 조건 있는 옛 답(문맥 파일 「조건」 — 우호도 · 레벨 · 면허 · 표시)은 그냥 묶으면 된다 — 조건이 맞지 않으면 게임이 그 말을 숨긴다.
  단, 한 단계에 **조건 없는 말이 하나는** 있어야 한다(조건 있는 답에 묶인 말은 조건 있는 말로 친다).
- 고를 말 자체의 우호도(`aff`)는 ±0.15 안 · 대개 0.02~0.08 · 무례 · 경솔한 말은 음수. 묶인 옛 답에 이미 우호도가 있으면 고를 말에는 더 붙이지 않는다(겹친다).
- 새 표시(`choice.…`)는 뒤에서 읽을 것이 아니면 만들지 않는다. 옛 표시를 옮길 때 이름을 바꾸지 않는다.
- 메인 편은 미루기 · 거절이 없다(받는 길만). 곁가지:
  - 받는 정책 `once` · `event` 는 미루기 · 거절 끝이 **반드시** 있다(옛 미루는 답이 있으면 그 id로).
  - `standard` 곁가지는 자연스러운 곳에서만 물러서는 길을 둔다 — 「다음에요」 = `decline`(다시 온다) · 끝까지 다 듣고 「못 하겠습니다」 = `fail`(그 편은 실패로 닫힌다 · 사용자 「곁가지는 개시를 선택적으로 안 할 수도 있다 → 거절 = 실패」).
    `fail`은 묶음에서 드물게(4편에 1편 이하). `fail` 끝에는 `offer`를 묶지 않는다.
- 결말을 정하는 편(문맥 「이 편이 정하는 결말」)은 끝마다 `ending: '<결말 id>'`를 둔다(결말이 하나면 생략 가능). 이미 있는 대화의 결말 배치는 그대로.

### 2-3. 말투 · 글

- 인물 말투는 문맥 파일의 옛 받는 말 · 끝내는 말 · 진행 중 물음 조언을 읽고 맞춘다(반말 · 존댓말 · 사투리 · 버릇).
- 주인공은 늘 존댓말(해요체 · 합니다체 섞어도 된다). 22살 · 아버지를 잃고 속초로 온 낚시꾼 — 말수는 적당하고 솔직하다.
- 큰따옴표 금지(대화창이 붙인다) · 이모지 금지 · 내부 id(`M1-02` 꼴) 금지 · 개발 용어 금지(퀘스트 · 우호도 · 경험치 · 숙련도 · 플래그 · 아크 …).
- 영어 줄에 한글 금지 · 한 · 영 단락 수 같게(단락은 빈 줄 `\n\n` — 대본 줄은 대개 한 단락).
- 영업시간 단서(문맥 「영업시간 단서」)는 대화창이 따로 빨간 글로 찍는다 — 대본에 다시 쓰지 않는다.
- 스포일러 금지 — 그 편보다 뒤에 밝혀질 사실(다음 편 내용 · 인물의 숨은 정체)을 앞당기지 않는다.
- 특정 시각을 조건처럼 말하지 않는다(「밤에」 · 「물이 빠질 때」 · 계절은 된다 · R12).
- 고를 말 라벨(`labelKo`) 4~45자 — 고르는 줄에 보이는 짧은 뜻. 실제로 하는 말은 `say`(길어도 된다).

## 3. 형식 — 이렇게 쓴다

```ts
/**
 * @file StoryTalkM1.ts
 * @description 290차 — 제1부 M1 받는 자리 · 끝내는 자리 대본(주고받는 장면). 규칙 = `StoryTalks.ts` 머리 · `.agents/inputs/290_talk_brief.md`.
 * 인물: 정옥선(71 · 좌판 · 무뚝뚝한 반말 · 「~거라」) · …
 */
import type { StoryTalkDef } from '../types/Story.js';
import { opt, endTalk, line, act, scene } from './StoryTalkKit.js';

const O = 'okseon';
const P = 'player';

export const TALKS_M1: StoryTalkDef[] = [
  {
    id: 'm1_02_offer', questId: 'M1-02', at: 'offer', npcId: O, start: 'start',
    nodes: {
      start: scene([
        line(O, '…', '...', { act: 'look_up' }),
        line(P, '…', '...'),
        // …
      ], {
        choices: [
          opt('carry', '상자부터 옮길게요', "I'll move the box first", {
            say: ['…', '...'], next: 'carry' }),
          opt('ask', '그 전에 하나만 여쭤봐도 될까요?', 'Can I ask one thing first?', {
            say: ['…', '...'], next: 'ask' }),
        ],
        note: ['…(1인칭 과거 한두 문장)', '...'],
      }),
      carry: scene([ line(O, '…', '...') ], {
        end: endTalk({ accept: true, offer: 'tone_honest' }),
        note: ['…', '...'],
      }),
      // …
    },
  },
  {
    id: 'm1_02_done', questId: 'M1-02', at: 'complete', npcId: O, start: 'start',
    nodes: {
      start: scene([ line(P, '…', '...'), line(O, '…', '...') ], {
        choices: [
          opt('pay', '품삯이면 충분해요', 'The pay is enough', { say: ['…', '...'],
            end: endTalk({ complete: 'pay', lineKo: '…', lineEn: '...' }), note: ['…', '...'] }),
          // 보상 답마다 하나씩
        ],
      }),
    },
  },
];
```

- import는 `../types/Story.js`(type) · `./StoryTalkKit.js`만 — 검사기가 이 둘만 풀어 읽는다(다른 모듈을 import하면 검사가 돌지 않는다).
- 대사를 쓰는 사람(`line`의 첫 인자) = 인물 id · `P`(`'player'`) · `''`(지문 — 드물게). 그 자리에 실제로 있는 사람만.
- 고를 말 id는 그 단계 안에서 유일 · 소문자 영어(`/^[a-z][a-z0-9_]*$/`). 단계 id도 소문자 영어.

## 4. 호칭 — 「OOO 씨」로 통일 (이번 차수의 사용자 결정)

| 누가 → 누구 | 한국어 | 영어 |
|---|---|---|
| 주인공 → 인물(부를 때 · 그 사람을 가리킬 때) | **이름 + 씨** — 「정옥선 씨」 · 「도현수 씨」 · 「바람 씨」 · 「짐 강 씨」 | 이름(given name) — Okseon · Hyeonsu · Baram · Jim (Mr. · Ms. · Grandma 없이) |
| 인물 → 주인공 | 이름으로 부를 때 `{player} 씨`(그리는 순간 주인공 이름이 들어간다) · 아니면 성별 없는 2인칭(자네 · 너 · 당신 · 그쪽) | `{player}` · you |
| 인물 ↔ 인물 | 그 사람들끼리의 사이 그대로(바람이 해녀를 「누님」) | 그대로 |

- 주인공 입에 **나이 · 성별 · 직함 부름말을 올리지 않는다**: 할머니 · 할아버지 · 아저씨 · 아주머니 · 어르신 · 형 · 형님 · 누나 · 누님 · 언니 · 오빠 · 삼촌 · 이모 ·
  사장님 · 선장님 · 선생님 · 계장님 · 조합장님 … (「할머니께서는 괜찮으세요?」처럼 상대의 집안사람을 가리킬 때도 이름이나 「그분」으로).
  주인공 자기 집안(「우리 아버지」 · 「제 할머니」)은 된다.
- 인물이 주인공을 **총각 · 아가씨 · 학생 · 젊은이 · 청년 · 아가 · 형 · 언니**로 부르지 않는다. 남녀 · 나이를 가르는 말을 피하면 `f:`(여자 주인공) 줄이 필요 없다.
- 자리 표시는 한국어에서 **늘 `{player} 씨`** 꼴(뒤에 조사를 붙이지 않는다 — 「{player} 씨가」는 된다 · 「{player}가」는 안 된다). 영어는 `{player}`. 한 장면에 한 번 정도만.
- 단체 의뢰인(`coop` = 동명항 어촌계)은 사무실 사람이 말한다 — 주인공은 이름을 부르지 않는다(부를 말이 없으면 부르지 않는다).

## 5. 검사 — 끝내기 전에 반드시

```bash
node tools/check_talks.mjs --part <묶음> --strict     # 맡은 묶음마다. 오류(✗) 0이 될 때까지
```

- 검사기는 소스를 바로 읽는다(빌드 불필요). **`pnpm build` · core dist를 다시 빌드하지 않는다**(여럿이 함께 쓰는 빌드본이다).
- 오류 = 참조 · 끝 규칙 · 막다른 길 · 글 규칙 · **덮개**(편마다 받는 · 끝내는 자리 대본 · 옛 답 표시 · 보상 답 전부 · 미루기) · **호칭**(`--strict`면 가리키는 말도).
- 경고(△) = 한 줄 140자 넘음 등 — 읽고 판단한다.
- 맡은 파일 밖은 고치지 않는다. 다른 묶음 파일 · 등록 파일 · 나레이션 · 옛 답 데이터도 고치지 않는다.
