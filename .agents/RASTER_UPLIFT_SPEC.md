### 0-1. 해상도 정합 (반드시 인지)

`TILE_M = 5.0`이므로 Sentinel-2 10m 픽셀 1개 = 게임 타일 **2×2**다. 1:1이 아니다.

- 면(面) 클래스(모래·식생·포장·갯벌)는 내부는 정확하고 경계만 2타일 계단으로 나온다.
  이 계단은 §5 경계 지터가 처리한다 — **업샘플로 해상도를 위조하지 말 것**.
- 분류는 반드시 **10m 원해상도에서 수행**하고, 결과 라벨만 5m 격자로 NEAREST 업샘플한다.
  영상을 먼저 5m로 리샘플한 뒤 분류하면 없는 정밀도를 지어내게 되고 경계가 뭉갠다.
- 20m 밴드(B11 SWIR 등)는 10m 격자로 NEAREST 업샘플 후 지수 계산.

```

[반복, 오프라인] py tools/classify_raster.py <region>
                → pixelazed/<region>/landcover.png   1px=1타일, 분류 라벨 (검수용 컬러맵)
                → pixelazed/<region>/slope.png       1px=1타일, 경사도 3단계 양자화

```

- DEM 원본 도엽(.img, ERDAS Imagine)은 rasterio가 GDAL HFA 드라이버로 그대로 읽는다.
  변환 불필요. 여러 도엽은 `classify_raster.py`가 병합하며, **원본 도엽은 삭제하지 않는다**
  (도엽 추가 시 재다운로드 방지).

  `landcover.png`·`slope.png`는 1px=1타일이라 수십 KB이므로 **커밋 대상**이다.

### 1-1. 좌표 정합 (최대 함정)

Sentinel-2는 UTM 투영(속초 = EPSG:32652, UTM 52N), 게임 격자는 bbox 기준 국지 등장방형
(OSM_TILEMAP_SPEC §3-1)이다. 두 격자는 자동으로 맞지 않는다.

```python
# pyproj로 게임 타일 중심 좌표 → UTM → 래스터 픽셀 인덱스 역변환
# (영상을 게임 격자로 warp 하지 말고, 게임 격자에서 영상을 샘플링한다)
lon = W + (tx + 0.5) * TILE_M / M_LON
lat = N - (ty + 0.5) * TILE_M / M_LAT
```

샘플링 방향을 반대로 잡으면(영상을 warp) 보간이 끼어들어 라벨이 오염된다. **반드시 역방향 샘플링**.

### 3-2. 검출 원리 — NDWI 실측 검증 완료 (2026-09-02)

Copernicus Browser의 NDWI 프리셋으로 기준 장면을 확인한 결과, 아래 대상이 바다 배경에서
흰 선으로 완전히 분리되는 것을 육안 확인했다. 알고리즘의 전제는 검증되었다.

- 속초항 북방파제(등대까지 끊김 없음) · 남방파제 · 중앙 부두
- 청호동 도류제(청초호 출구 양안)
- 속초해수욕장 남측 호안의 테트라포드 열(점선 패턴 — §11 L3 프롭 배치에 재사용 가능)
- 조도(바다에 갇힌 폐합 성분 → detached 판정 대상)
- 청초호는 True color에서 탁수로 어둡게 보이나 NDWI에서는 바다와 동일하게 물로 분류됨
  → 당초 우려한 MNDWI 우선 적용은 불필요

방파제는 위성이 가장 잘 잡는 대상이다. 물은 NIR(B08)에서 거의 0에 수렴하고 콘크리트는 밝다.

```python
NDWI  = (B03 - B08) / (B03 + B08)        # 물 > 0 — 속초 실측상 이것만으로 충분
MNDWI = (B03 - B11) / (B03 + B11)        # SWIR 기반 — 탁수 심한 타 지역용 폴백
water = (NDWI > tau_water)               # tau_water 기본 0.15
bright_struct = (B08 > tau_nir) & ~water # tau_nir 기본 0.18 (반사율 스케일)
```

1. water 마스크에서 육지 본체를 flood로 제거 → 해수면만 남김
2. bright_struct 중 해수면에 4방향 이상 둘러싸인 연결성분만 후보
3. 성분별 선형성 판정: 길이/폭 ≥ 3.0 (skeletonize 후 주축 길이 / 면적÷길이) →
   선형이면 b(방파제·부두), 아니면 r(간척지·매립 구조물) 또는 미분류
4. 육지 접속 확인: 후보 성분이 육지와 연결되지 않으면 이안제(離岸堤) — b로 두되
   `raster_meta.json`에 `detached: true` 기록(도보 도달 불가 → §7 검증에서 별도 취급)
5. 5m 격자로 NEAREST 업샘플 후 폭 최소 2타일 보장(morphological closing)

속초·동명항 방파제는 실폭 20~40m = Sentinel 2~4px = 게임 4~8타일 폭으로 나온다.

## 4. Phase 2 — 피복 분류 보강

OSM이 태그하지 않는 것들을 메운다. **OSM에 태그가 있으면 무조건 OSM이 이긴다**(§6).

| 대상 | 판정식 | 타일 |
|---|---|---|
| 식생 | NDVI > 0.35 | `,` |
| 모래사장 | NDVI < 0.2 & B04 높음 & 해수면 인접 8타일 이내 | `s` |
| 포장·나지 | NDVI < 0.15 & 밝기 중간 & 해수면 비인접 | `r` |
| 내수면 | NDWI > tau_water & 해수면 flood 미연결 | `~` |
| 갯벌 | 저조위 장면에서 육지 & 고조위 장면에서 물 | `m` 예약 — **본 발주 미구현** |

```python
NDVI = (B08 - B04) / (B08 + B04)
```

갯벌(m)은 스키마 자리만 예약하고 구현하지 않는다. 타일 문자 유니언에 추가하면 core 타입·
walkable·fishableFrom·오토타일 16마스크·팔레트가 전부 연동 변경되어 범위가 폭발한다.
태안·인천 지역 착수 시점에 별도 발주한다(OSM_TILEMAP_SPEC §13-5 미결 항목과 연결).

## 5. Phase 3 — DEM 활용 (경사도)

정점 변형(displacement)·셰이더는 쓰지 않는다. 2D 픽셀 퍼펙트 렌더에 맞지 않는다.
고도는 세 가지 용도로만 쓴다.

1. **해안 타일 변형 선택**: 해수면 인접 타일의 경사도로 완경사 → s(모래) / 급경사 → 갯바위 변형 /
   수직 → 인공 호안 을 오토타일 변형 인덱스로 전달. 영금정 같은 지형이 실제로 절벽처럼 보이게
   되는 유일한 저비용 수단.
2. **통행성 자동화**: slope > 35° 타일을 walkable = false 후보로 표시. **자동 반영 금지** —
   slope.png 검수 후 patch.json에 수동 반영. 등산로가 끊길 수 있다.
3. **음영 베이크**: 경사·향(aspect)을 3단계로 양자화해 청크 베이크 시 팔레트 내 틴트로 적용.
   팔레트 밖 색 생성 금지, 알파 블렌딩 금지 — **팔레트 인덱스 시프트로만** 처리.
   RegionFieldScene 청크 베이크에 1패스 추가되며 런타임 비용은 베이크 시점 1회뿐이다.

### 5-1. DEM 도엽 선별 규칙 (확장 규약의 예외)

국토정보플랫폼은 API가 없어 사람이 로그인해 클릭으로 받는 수밖에 없다. 따라서
OSM_TILEMAP_SPEC §10의 "지역 추가 = bbox 한 줄" 원칙이 DEM에는 적용되지 않는다.
Phase 1~2(Sentinel-2)만 자동 확장되고, **Phase 3는 지역별 수동 작업**이다.

선별 기준: 육지 면적이 아니라 **b·s 타일이 될 물가 접선이 지나가는가**.
바다가 90%인 도엽이라도 그 안에 방파제 끝단·갯바위·해변이 있으면 받는다. 반대로 내륙 도엽은
육지가 100%여도 플레이어가 갈 일이 없으면 받지 않는다. 해안선을 따라가는 띠만 확보하면 되므로,
대형 지역도 전체 도엽의 1/3 이하로 줄어든다.

속초 확정 도엽 4장 (1:5,000, 각 391KB):

| 도엽 | 포함 대상 |
|---|---|
| 38815014 | 동명항·속초항·영랑호·금호동 — 방파제 본체 |
| 38815015 | 등대해수욕장·방파제 끝단 — 바다 비중 높으나 낚시 지점 |
| 38815024 | 청초호 남안·조양동·엑스포 |
| 38815025 | 조도·속초해수욕장·외옹치 |

**Phase 3 적용 지역 한정**: 경사 데이터의 가치는 지역차가 크다. 절벽·갯바위 해안인
울릉·독도·제주 서귀포·속초(영금정)·거제 해금강에 우선 적용하고, 평탄한 항만·해변 지역
(인천 연안부두·태안 만리포·부산 민락 등)은 경사도가 0에 수렴하므로 생략한다.
DEM 파일 부재 시 Phase 3는 자동 스킵되므로 코드 분기는 필요 없다.

**속초에서 효과를 먼저 검증하고 타 지역 도엽을 받을 것.** 경사 기반 갯바위/호안 변형이
화면에서 체감되지 않으면 대형 지역 도엽 수십 장을 받는 수고가 통째로 낭비된다.

## 6. 병합 우선순위 (build_osm_tilemap.py 병합 패스)

뒤가 앞을 덮는다:

```
래스터 추론  <  OSM 벡터  <  patch.json(사용자 손수정)
```

- OSM에 태그가 있는 셀은 래스터가 절대 덮지 않는다. 래스터는 미분류·불확실 셀만 채운다.
- 단 예외 1건: b 타일은 래스터 검출이 OSM 부재를 메우는 것이므로, OSM이 `.`(육지 기본값)으로만
  채운 셀에 한해 래스터 b가 우선한다. OSM이 명시적으로 `#`·`,`·`r`로 태그한 셀은 덮지 않는다.
- **⚠ 개정(§0.5 노트 3)**: "래스터 b vs **103차 추론 b**"가 어긋나는 셀의 처리는
  [개정안 §2의 4케이스 표](RASTER_UPLIFT_AMENDMENT.md)를 따른다 — 추론 단독 b는 자동 삭제 금지.
- patch.json(현재 321타일, 실효 118타일)은 항상 최후에 적용한다. 재빌드가 손수정을 덮어쓸
  위험은 여기서 차단된다.
- 병합 패스는 `--no-raster` 플래그로 끌 수 있어야 한다(A/B 비교 및 회귀 시).
