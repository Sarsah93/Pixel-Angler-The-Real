## 0. 사용자 지시 요지 (원문 요약)

1. **탑다운 설치물 상호작용** — 화구는 아이템 하나를 단순 설치하는 게 아니라 **가스스토브 + 가스 캐니스터 +
   조리도구(팬·냄비)** 를 조합해 세우고, `[F]`로 UI 패널을 연다. 조리를 걸어 놓고 떠나 있는 동안
   **탑다운에서 상태가 보이고**, 상호작용하면 조리·상태 패널이 **실시간**으로 열린다.
2. **레시피 = 필수 요소 고정 + 부가 재료로 고급화** — 창작 요리는 배제(경우의 수·지향점 아님).
   특정 요리명을 표방하면 조리 과정의 **필수 요소는 반드시** 반영하고, **기타 재료·조리법 추가는
   NORMAL 기준 고급화**로 판정. 택1 채소를 둘 다 넣거나 재료가 한도를 넘으면 **완성도 하락**.
   소금·설탕은 **양 조절**(싱겁다·짜다·달다). 투입 순서는 레시피마다 다르므로 **보편적인 쪽으로 정합**.
   완성 요리의 **상세정보** 설계. **맛 별 5개** = 간(★1)·온도(★2)·식감(★3)·신선도(★4)·완성도(★5).
   온도·식감·신선도는 **완성 직후부터 시간이 지날수록** 떨어지고 완성도·맛도 따라 떨어진다.
   자료가 방대해지므로 **인게임에서 구현할 요리 후보를 먼저 선정**.
3. **걸어두고 나가기** — 인게임 밸런스를 고려해 반영.

## 1. 결정 (⚖)

- ⚖ **트레이스 미니게임이 아니다.** 손질·회썰기는 칼(공간 정밀도), 불요리는 **온도와 시간**이다.
  조작은 ① 불 세기 ② 재료 투입 순서/양 ③ 뒤집기·젓기 셋뿐 — 대신 읽어야 할 신호(온도 바·끓음·색)가 많다.
- ⚖ **무대 둘** — 집 주방(가스레인지 2구·수도 무한·무풍) / 현장(휴대 버너 설치물 — 연료 소모·바람).
  둘 다 **같은 `CookingPanel`** 을 연다. 화면을 둘로 만들지 않는다.
- ⚖ **화구·용기·연료는 데이터**(`CookwareDatabase`) — 조리 가능 여부는 `recipe.cookware ∩ 용기 종류`로
  결정한다. 하드코딩 `if (recipe.id === …)` 금지.
- ⚖ **화구 설치 = 조합** — 스토브(필수) + 연료(필수 · 캐니스터 1개 = 분 단위 연료) + 용기(설치 후에도 교체).
  `[F]` = 조리 패널 · `[Shift+F]` = 회수(조리 중·완성 요리 얹힘 상태에서는 거부).
- ⚖ **시뮬은 wall-clock**(통발과 같은 규칙) — 패널을 닫아도, 맵을 떠나도 익는다. 오프라인(게임 종료)은 정지
  (신선도·통발과 같은 오프라인 규칙 — `lastTickMs`를 갭만큼 민다).
- ⚖ **시간 배율 `timeScale` 6** — 시뮬 1분 = 실시간 10초. 매운탕 25분 = 실시간 약 4분.
- ⚖ **탄 요리는 소실이 아니라 등급 하락** — `탄 매운탕`(별 0~1 · 판매 불가 · 섭취 가능·회복 반감).
- ⚖ **재료 '보통' 등급은 조리 가능**(21차 규칙 — 회는 불가). '나쁨'·'부패'는 투입 거부(식중독).
  → 불요리 = **신선도 구제 경로**, 회 = 신선도 프리미엄.
- ⚖ **채집물(조례상 판매 금지)의 sink** — 조개탕·전복죽이 바지락·홍합·전복을 소비한다.
  손질 부산물(머리·척추·갈빗대 = `byproductKind head|spine|rib`)은 매운탕·지리의 **서더리**다.
- ⚖ **별점은 이름에 글자로**(`매운탕 (별 4개)`) · UI는 픽셀 별 아이콘. 이모지·★ 글리프 금지(§8-8).
- ⚖ **레거시 `CookScene`은 건드리지 않는다**(FieldScene 전용 사문). 심리스 경로는 이 스펙만 쓴다.

## 3. 재료 (핵심 필드)

`CookIngredientDef { id, kind, unit, saltGPerUnit, sugarGPerUnit, cookMinC, cookSec, burnC, massG }`

- `kind`: `main`(생선·해산물) · `base`(무·대파 등 국물 채소) · `veg` · `season` · `liquid` · `oil` · `grain` · `finish`(마지막 넣는 향채).
- `unit`: `g`(주재료 — 아이템 실중량) · `ea`(채소 1개/한 줌) · `spoon`(양념 1큰술 = 정량 1) · `cup`(물 200ml).
- **간 계산**: 소금 1큰술 = 15g · 국간장 1큰술 = 2.4g 염분 · 액젓 = 3g · 고추장 = 1.2g · 된장 = 1.8g.
  염도 = Σ염분 ÷ (물 + 고형 중량). **적정 염도 0.8~1.2%**(사용자 기준). 구이는 100g당 소금 0.9g 기준.
- **당분**: 설탕 1큰술 = 12g. 탕은 목표 0(넣으면 달다), 조림 2, 볶음 1.5, 장어 양념 1.5.
- **아이템 → 재료 매핑**(`ingredientOfItem`): `subCategory 어획물` → `fish`(중량 g) · `byproductKind head|spine|rib` →
  `seodeori` · `forageCatch` + speciesId(바지락·홍합·굴·전복) → 해당 · `inv_ceph_*` 몸통살/통마리 → `squid` ·
  `inv_dressed_*`/`inv_fillet*` → `fish_dressed` · 식자재 아이템은 `cookIngredient` 필드로 직접 지정.

## 5. 조리 시뮬 (core `CookingSim.ts` — 순수 스텝)

- 상태: 온도 `tempC` · 물 `waterMl` · 내용물별 `doneness`/`burnt` · 단계 `stageNow` · 화력 관리 누적(적정대 안/밖 초).
- 열: `dT = (W·heatFrac − k·(T−주변)) · dt ÷ (m·c + 열관성)`. 물이 있으면 **100°C 캡** — 초과 에너지는 증발(2,260 J/g).
  물이 0이 되고 불이 켜져 있으면 **졸아붙음** → `burnt` 누적. 팬은 250°C 캡.
- 익음: `T ≥ cookMinC`일 때 `doneness += ((T − cookMinC)/(100 − cookMinC))^1 ÷ cookSec × dt`.
  `1.0` 익음 · `>1.15` 과조리 · `>1.6` 퍼짐. 팬은 `T > burnC`면 `burnt` 누적.
- **뒤집기**(구이) / **젓기**(볶음): `flipEverySec`마다 필요. 놓치면 아래면이 탄다(`burnt` 가속).
- 단계(`stages`)는 트리거로 전이 — `start` → `boil`(끓음) → `mainCooked`(주재료 익음) → `final`(마무리 1~2분).
  레시피의 각 재료는 **이상적 단계**를 가진다. 실제 투입 단계와의 차이가 완성도의 「순서」 점수.
- 적정대: 계열별 목표 온도 밴드(탕 92~100 · 조림 88~100 · 구이 160~200 · 볶음 170~220 · 죽 85~98).
  밴드 안 시간 비율 = 「화력 관리」.

## 6. 맛 별 5개 (`evaluateDish`)

각 요소 0~1 점수 → **0.72 이상이면 별 획득**. 완성도 별은 **나머지 넷을 모두 얻어야** 열린다(사용자 원문 "여기서 비로소 만점").

| 별 | 요소 | 산식 |
|---|---|---|
| ★1 | 간 | `0.75·gauss(염도, 1.0, σ0.3) + 0.25·gauss(당분차, 0, σ1.2)` · 라벨 싱겁다/적당/짜다·달다 |
| ★2 | 온도 | 완성 시 `T`가 계열별 서빙 온도(탕 70 · 구이 60 · 죽 65) 이상이면 1 · 시간 감쇠 `T(t)=주변+(T0−주변)·e^(−t/τ)`(τ 탕 25분 · 구이 12분) |
| ★3 | 식감 | 내용물별 `doneness` — 0.95~1.15 = 1 · 미달 `d/0.95`(0.8 미만 0.3) · 과조리 `1−(d−1.15)/0.6` · `burnt` 페널티. 역할 가중 main .6 / veg .3 / finish .1. 시간 감쇠 계열별 |
| ★4 | 신선도 | 주재료 최소 `freshness01`(활어 1 · 신선 .92 · 냉장 .9 · 보통 .65 · 해동 .55) × 요리 아이템 신선도 그래프(완성 = 신선 3h → 보통 → 나쁨) |
| ★5 | 완성도 | `0.4·구성 + 0.3·순서 + 0.3·화력관리`, 구성 = `1 − 0.25·필수누락 − 0.15·택1위반 − 0.10·초과종 + 0.06·부가(≤0.30)` · `life_cook` +5%/랭크 · 넷 중 하나라도 0.6 미만이면 0.55 캡 |

- **총점 0~100** = 가중 평균(간 .25 · 온도 .15 · 식감 .25 · 신선 .15 · 완성 .20) — 판매가·XP·회복치 배율.
- **시간 감쇠는 조회 시점에 계산**(`dishStarsAt(dish, now)`) — 저장은 완성 시 기준값만(신선도 lazy refresh와 같은 원리).

## 7. 완성 요리 아이템 · 상세정보

- `InvItem.dish: DishData { recipeId, cookedAtMs, tempAtDoneC, base: {season,temp,texture,fresh,finish}, saltLabel, sugarLabel, contents[], stoveKind, cookwareId, burnt, servings, skillRank }`.
- 이름 `매운탕 (별 4개)` · 탄 것은 `탄 매운탕` · 카테고리 food · 소분류 `요리` · 신선도 `fresh`부터.
- **상세정보 행**: 요리 · 맛 별점(현재/완성 시) · 간(싱겁다/적당/짜다) · 온도(뜨거움/따뜻함/식음 + 분) ·
  식감(라벨) · 신선도 · 완성도 · 재료 구성(필수/부가 목록) · 조리한 곳(집 주방/현장 버너) · 조리 시각 ·
  섭취 효과(현재 별점 반영) · 판매가.
- **회복치** = 레시피 기본 × `0.45 + 0.75·(총점/100)` — 별 5 = 1.2배, 탄 것 = 0.4배.
- **판매가** = `baseValueKrw × (0.3 + 0.9·총점/100)` × 상태 배율. 탄 것 0.

## 8. 걸어두기 밸런스 (⚖)

- **약불 걸어두기는 안전하다** — 약불 92~96°C 유지, 물 증발 느림(코펠 1.8L 기준 졸아붙음까지 시뮬 ≈ 55분 = 실시간 9분).
- **강불 방치는 위험하다** — 끓고 8~10분(실시간 1.5분) 뒤 과조리, 20분(실시간 3.3분) 뒤 졸아붙어 탄다.
- **완성 뒤 불을 안 끄면** 과조리 → 식감 하락 → 탐. 완성 뒤 불을 껐으면 온도만 식는다(안전).
- **연료 소진** = 불 꺼짐(안전·식음). 현장은 캐니스터가 상한이다(55분 강불 = 매운탕 2번).
- **탑다운 표시**: 화구 위 냄비/팬 + 불꽃(세기별 높이) + 김/연기 + **진행 배지**(`끓는 중 62%` / `완성` / `탐!`).
  완성 상태에서 3분 이상 방치 시 배지 색이 주황 → 빨강. 미니맵에는 표시하지 않는다(가까이서만).
- **회수 규칙**: 조리 중·완성 얹힘 상태에서는 `[Shift+F]` 거부("먼저 요리를 내리세요").
