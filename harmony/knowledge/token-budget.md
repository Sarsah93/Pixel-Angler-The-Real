# 토큰 예산 — 절감책 사다리와 채택 기록

> 2026-10-12 사용자 지시로 만들었다. 절차는 `PROTOCOL.md` §2.9 · §5, 기록 도구는 `tools/tokens.py`,
> 원자료는 `metrics/tokens.jsonl`. 이 파일은 **조율자가 스스로 고친다**(채택 · 해제 · 효과 기록).

## 1. 목표

- 실행 1회 사용량 = **세션 예산의 1% 이하**(예산 15,000,000이면 150k).
- 실행 차수가 늘수록 원장 · 학습 노트 · 검토 기록이 커져 읽는 양이 자연히 는다. 그 증가를 절감책으로 상쇄한다.
- 품질 하한: 절감 때문에 아래를 빼지 않는다 — PR 상태 반영 · 검증 명령 · 비밀값 검사 · 보고서 · 상태 저장.

## 2. 절감책 사다리 (위에서부터 하나씩 채택)

| 번호 | 절감책 | 기대 효과 | 되돌릴 신호 |
|---|---|---|---|
| T1 | JSON · 긴 파일은 통째로 출력하지 않는다 — 파이썬으로 필요한 필드만 뽑고, 출력은 `head`/`cut`으로 자른다 | 원장 · 지표 읽기 30~50% 감소 | 없음(상시 유지) |
| T2 | 바뀐 파일만 읽는다 — `audited_commit` 이후 변경이 없으면 학습 노트 · 지침은 「다음 실행 중점」 절만 읽는다 | 노트 읽기 대부분 생략 | 노트와 실제가 어긋난 발견이 나오면 해제 |
| T3 | 기본 브랜치에 새 커밋이 없고 어제 검증이 성공이면 설치 · 빌드 · 테스트를 건너뛴다(§2.3 그대로) · 돌릴 때도 출력은 `tail` 몇 줄만 | 빌드 로그 수천 토큰 | 없음 |
| T4 | 원장 대조는 스크립트로 — 열린 발견 목록을 제목 · 근거 경로로 한 번에 뽑고, 근거 파일은 그 줄 주변만 읽는다(`sed -n`) | 발견 재확인 비용 절반 | 같은 문제를 새 번호로 만든 일이 생기면 해제 |
| T5 | 하위 에이전트는 심화 도메인 1개에만 쓰고, 지시문에 「읽을 파일 목록 · 돌려줄 형식 · 2,000단어 이내」를 박는다 | 하위 에이전트 합 감소 | 심화 결과가 얕아지면(발견 0 · 배운 것 1줄) 해제 |
| T6 | 심화 한도를 줄인다 — `limits.deep_dive_max_files` 40 → 25, `deep_dive_max_lines` 15000 → 9000 | 심화 비용 약 40% 감소 | 숙련이 2주 연속 오르지 않으면 원래 값으로 |
| T7 | 학습 노트 압축 — 파일당 400줄 한도를 250줄로, 오래된 사실은 한 줄 요약으로 접는다 | 노트 읽기 감소 | 접은 내용을 다시 찾느라 비용이 늘면 해제 |
| T8 | 원장 보관 — `해소` · `병합` · `닫힘` 항목 중 30일 지난 것을 `ledger/archive-<연월>.json`으로 옮긴다(번호 유지) | 원장 크기 감소 | 없음 |
| T9 | 보고서 다이어트 — 변화 없는 도메인은 표 한 줄로 묶고 「도메인별」 절에서 뺀다 | 쓰기 비용 감소 | 사용자가 더 자세히 달라고 하면 해제 |

- 사다리에 없는 절감책을 찾으면 **T10부터 이어 붙인다**(이름 · 기대 효과 · 되돌릴 신호를 같이 쓴다).
- 절대 규칙 · `PROTOCOL.md` · `tools/score.py`의 점수 공식을 바꾸는 절감책은 채택하지 않고 보고서 「절차 변경 제안」에 적는다.
- 한도(`limits`)는 **줄이는 쪽만** 스스로 바꿀 수 있다(T6). 늘리는 것은 사용자만 한다.

## 3. 채택 규칙

1. 매 실행 끝에 `tokens.py record`가 판정을 낸다.
2. 판정이 「절감책 1단계 채택 필요」면 사다리에서 **아직 채택하지 않은 가장 위의 것 하나**를 채택한다.
   - 다음 실행부터 적용하고, 아래 4절 기록에 날짜 · 사유 · 채택 전 3회 평균을 적는다.
   - 한 번에 하나만 채택한다(어느 절감책이 효과였는지 가리기 위해).
3. 판정이 「유지」로 **5회 연속**이면 새로 채택하지 않는다. 채택된 것은 그대로 둔다.
4. 채택 후 3회가 지나면 효과를 적는다(채택 전 평균 → 후 평균). 효과가 5% 미만이면 「효과 없음」으로 적고 해제해도 된다.
5. 「되돌릴 신호」가 보이면 해제하고 이유를 적는다. 해제한 것을 다시 채택할 때는 사유가 바뀌었음을 적는다.
6. 사다리를 다 썼는데도 목표를 넘으면, 보고서 「사용자 결정이 필요한 것」에 올린다(예: 심화 격일 · 도메인 통합).
