# 하모니 — 일일 점검 상태 브랜치

이 브랜치(`harmony-state`)는 **Pixel Angler The Real**의 일일 자동 점검이 남기는 기록이다.
게임 코드는 들어 있지 않고, 기본 브랜치(`main`)와 합쳐지지 않는다.

## 무엇을 하나 (v2 — 2026-10-27 개편 · 10-28 새벽 실행부터)

매일 새벽 예약 작업이 저장소를 받아 **플레이어가 겪을 문제**를 찾고, 재현되는 작은 결함은 고쳐서 PR로 올린다.
요일마다 한 갈래를 깊게 본다.

| 요일 | 갈래 | 예 |
|---|---|---|
| 월 | ① 아이템·재화 배선 | 열지 않은 미끼 갑이 채비 미끼 칸에 들어감 · 가방이 차면 물건이 사라짐 |
| 화 | ② 그림·데이터·문구 정합 | 한 켤레 아이템 그림에 세 켤레 · 상세 창 숫자가 실제와 다름 |
| 수 | ③ 플레이 흐름·예외 처리 | 놀이 중 ESC → 오류 · 멈춤 · 탭 복귀 검은 화면 |
| 목 | ④ 기획 현실성·밸런스 | 현실과 다른 값 · 사서 되팔기 차익 · 막다른 길 (제안만) |
| 금 | ⑤ 보안·계정·서비스 | 서버가 클라이언트 값을 그대로 믿음 · 키 노출 |
| 토 | ⑥ 접근성·사용성 | 색만으로 구별 · 글자 넘침 · 한글 입력 · 처음 하는 사람이 막히는 곳 |
| 일 | 문서·지침 정합 | 시스템 페이지 · 스킬 · 백로그가 코드와 같은가 |

빌드 · 타입 · 시험 · 규칙 정규식은 매일 짧게 돈다(기본 점검).

결과는 세 곳에 남는다.

- **보고서** — `harmony/reports/<날짜>.md` (찾은 버그 · 재현 · 수정 PR · 밸런스 제안)
- **수정안** — `harmony/<날짜>-…` 브랜치의 풀 리퀘스트. 병합할지는 사용자가 정한다.
- **점수** — `harmony/scores/latest.json` · `history.jsonl` (보조 지표)

## 어디를 보면 되나

| 궁금한 것 | 파일 |
|---|---|
| 오늘 무엇을 찾았나 | `harmony/reports/` 최신 파일 |
| 열려 있는 문제 | `harmony/ledger/findings.json` (`status`가 `열림` · `lane`이 갈래) |
| 올라온 수정안의 결과 | `harmony/ledger/proposals.json` |
| 되풀이되는 버그 모양 | `harmony/knowledge/bug-patterns.md` |
| 갈래별 시나리오와 마지막으로 돌린 날 | `harmony/knowledge/scenarios.json` |
| 에이전트가 따르는 지침 | `harmony/PROTOCOL.md` · `harmony/agents/` |
| 범위 · 요일 · 한도 · 점수 가중치 | `harmony/config.json` |
| v1(2026-10-08 ~ 10-27) 지침 · 학습 노트 | `harmony/agents/v1/` · `harmony/knowledge/v1/` |

## 점수의 뜻 (v2)

| 항목 | 계산 |
|---|---|
| 상태 | 100 − 열린 발견 감점 합(심각 15 · 보통 6 · 경미 2) |
| 시나리오 | 그 갈래 시나리오 중 최근 14일 안에 실제로 돌린 비율 |
| 실행 | 최근 30일 동안 결정된 수정 PR 중 병합된 비율(결정 3건 미만이면 표시하지 않음) |
| 종합 | 상태 0.5 · 시나리오 0.3 · 실행 0.2 가중 평균 |
| 하모니 지수 | 제품 갈래 ①~⑥ 종합의 평균(기본 점검 · 문서는 지수에 넣지 않는다) |
| 오늘 찾음 · 고침 | 오늘 새로 연 발견 수 · 오늘 해소한 발견 수 |

v1은 「범위 안 파일을 몇 개 읽었나(숙련)」를 셌다. 그래서 점검이 문서 정리로 쏠렸다 — v2는 이것을 빼고 「돌려 본 시나리오」를 센다.

## 사용자가 조절하는 법

- **수정안을 받아들인다 / 거절한다** — PR을 병합하거나 닫는다. 닫을 때 이유를 댓글로 남기면 다음부터 반영한다.
- **「이건 의도된 것」** — `ledger/findings.json`에서 그 항목의 `status`를 `보류`로 바꾸거나, PR 댓글로 알린다.
- **시나리오 추가** — `knowledge/scenarios.json`의 갈래에 한 줄 더한다(예: 「통발을 놓은 채 출조 지역을 바꿔 본다」).
- **요일 · 범위 · 한도 · 가중치** — `config.json`을 고친다(이 브랜치에 직접 커밋).
- **절차** — `PROTOCOL.md`를 고친다. 에이전트는 이 문서를 스스로 바꾸지 않는다.
- **멈춤** — 예약 작업을 끄면 된다. 이 브랜치와 `harmony/` 브랜치들을 지워도 `main`에는 영향이 없다.

## 지키는 선

- 쓰는 곳은 `harmony-state`와 `harmony/`로 시작하는 브랜치뿐이다. `main`과 `gh-pages`에는 쓰지 않는다.
- 병합 · 배포 · 태그는 하지 않는다.
- 비밀값은 기록하지 않는다. 환경 변수는 이름만 다룬다. 보안 결함의 재현 방법은 공개 기록에 쓰지 않는다.
- 밸런스 값 · 설계 변경은 제안만 한다. 재현되고 검증된 작은 결함 수정만 PR로 올린다.

## 도구

```bash
# 지표 수집 (표준 라이브러리만 사용)
python3 harmony/tools/collect_metrics.py --repo <main 체크아웃> --config harmony/config.json --out harmony/metrics/<날짜>.json

# 점수 계산
python3 harmony/tools/score.py --repo <main 체크아웃> --state harmony --date <날짜>

# 게임을 띄우는 하네스 시작 본 (dev 서버가 떠 있어야 한다 — 사용법은 파일 머리 주석)
node <시나리오 스크립트>   # 안에서 require('harmony/tools/harness_start.cjs').boot()
```
