# 5 파이프라인

## 목적

원본 → 도구 → 산출물 → 빌드 → 배포로 이어지는 배선이 끊기지 않고 다시 돌릴 수 있게 한다.

## 공통 점검

- 배선도: 각 도구의 입력 · 출력 · 실행 순서 · 호출하는 곳(문서 · 스크립트 · 스킬).
- 끊긴 배선: 없는 경로를 읽는 도구, 아무도 쓰지 않는 산출물, 생성기 없이 손으로 고친 생성물.
- 신선도: 입력이 산출물보다 새로워진 곳(다시 구워야 하는 것).
- 재현성: 하드코딩된 개인 경로 · 운영체제 의존 · 버전 고정 누락.
- 작업 러너(빌드 · 테스트 · 린트) 정의와 실제 패키지 스크립트의 어긋남.
- 자동 검사(CI)의 유무와, 지금 손으로 하는 검증 중 자동화할 수 있는 것.

## 이 프로젝트 전용

- 지도 파이프라인 정본은 루트 `tools/`(`fetch_region_osm` → `build_osm_tilemap` · `build_region_maps`) — 스킬 `add-region`.
- 에셋 생성기 `tools/gen_*` · `pixelize*`와 산출물(`public/**` · `src/data/*`)의 짝.
- `turbo.json`에 `lint` · `test`가 정의돼 있는데 패키지에 스크립트가 없는 곳.
- `.github/` 워크플로가 없다 — 빌드 · 타입 검사 · 테스트 자동 실행은 제안 사항.
- 배포는 gh-pages 수동 절차(스킬 `deploy-ghpages`) — 하모니는 배포하지 않는다.
- `tools/__pycache__/`처럼 커밋된 생성물.
- 래스터 보강(위성 · DEM)은 빌드 시점 전용, 위성 영상은 번들에 넣지 않는다.

## 고칠 수 있는 것

- 도구 안의 깨진 경로 · 안내 문구
- 누락된 패키지 스크립트 중 동작이 자명한 것(예: typecheck)

## 제안만 하는 것

- CI 워크플로 추가
- 도구 실행 순서 · 산출물 위치 변경
- 생성물 재생성(결과 파일이 대량으로 바뀌는 작업)
