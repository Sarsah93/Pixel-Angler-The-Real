# 3 파일·문서

## 목적

원본 파일과 참고 자료가 중복 없이, 찾기 쉽게, 필요한 만큼만 저장소에 있게 한다.

## 공통 점검

- 중복 파일(지표 `duplicates`): 의도된 복사(입력 → 산출)인지, 정리할 수 있는 중복인지 구분.
- 큰 파일(지표 `largest_files`): 저장소에 둘 이유가 있는지, 압축 · 외부 보관 후보인지.
- 쓰이지 않는 파일: 어떤 도구 · 코드 · 문서도 가리키지 않는 원본과 임시 산출물.
- 이름 규칙: 공백 · 대소문자 · 오탈자 · 날짜 표기의 불일치(바꾸면 깨지는 참조도 함께 조사).
- 무시 규칙(`.gitignore`)에서 빠진 생성물 · 캐시.
- 보관 폴더와 현행 폴더의 경계가 지켜지는지.

## 이 프로젝트 전용

- `food assets/`는 파이프라인 입력 — **이름 변경 금지**(도구 경로 참조 다수). 정리는 제안만.
- `food assets/` ↔ `packages/client-pc/public/` 사이의 같은 파일: 「구운 스냅샷 vs 직접 로드」 구분은 스킬 `asset-pipeline`.
- `scratchpad/`에 커밋된 임시 산출물(검증 스크린샷 등)의 보존 필요성.
- `docs/archive/`에는 새로 쓰지 않는다 — 현행 문서가 보관본을 정본처럼 가리키는지 확인.
- `docs/reference/`의 외부 원본(공공 API 가이드 · 수심 자료)의 출처 표기와 용량.
- `pixelazed/_osmcache/`는 커밋 유지, `pixelazed/_rastercache/`는 커밋 금지.

## 고칠 수 있는 것

- `.gitignore` 보강
- 문서 안의 깨진 경로 수정

## 제안만 하는 것

- 파일 삭제 · 이동 · 이름 변경(용량 절감 추정치와 깨지는 참조 목록을 함께)
- 대용량 원본의 외부 보관
