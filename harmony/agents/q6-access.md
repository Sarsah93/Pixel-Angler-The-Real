# ⑥ 접근성·사용성

## 목적

색 · 글자 · 조작 · 안내가 **처음 하는 사람 · 색약 · 키보드 사용자 · 영어 사용자**에게도 통하게 한다.

## 보는 것 (질문)

1. 색만으로 구별하는 표시가 있는가? 색약 보정 모드(251차)에서도 구별되는가?
2. 글자가 창 밖으로 넘치거나 겹치는가? (한국어 · 영어 · 가장 긴 이름)
3. 마우스 없이 주요 흐름을 할 수 있는가?
4. 모든 입력 칸에서 한글(IME)이 되는가?
5. 인게임 표현 규칙 R1~R14(AGENTS §4)를 어기는 화면이 있는가? — 내부 id · 스포일러 · 조작 안내 문구 · 바탕 상자 글자 · 이모지
6. 처음 하는 사람이 **안내 없이 멈추는 곳**, 가이드가 다른 창을 가리는 곳이 있는가?

## 방법

- 하네스(`tools/harness_start.cjs`) + 스크린샷을 **직접 본다**(그림으로 된 판은 감사 도구가 못 본다).
- 넘침 · 겹침: `tools/ui_overlap_audit.js` · dev 콘솔 `[TextOverflow]` 경고 수(스킬 ui-panel).
- 색약: 스크린샷을 시뮬레이션 행렬(제1 · 2 · 3색약)로 바꿔 대비를 잰다(Pillow · numpy).
- 규칙 정규식: `no-ui-emoji` · `no-keydown-text-input` · `no-screen-edge-anchor`.

## 이 프로젝트 전용

- 접근성 설정: `ui/SettingsPanel` 「접근성」 탭 · 색 팔레트 모듈(251차) · 포인터(250 · 251차).
- 가이드: `ui/GuideTour.ts` · `ui/PrologueCoach.ts` · 도움말 `data/HelpContent.ts`(F1).
- 사용자 지시 규칙: 창에 조작 안내 문구 금지(R11) · 필드 글자 흰 테(R14) · ESC는 실내를 나가지 않는다(절대 규칙 16).

## 고칠 수 있는 것 (재현 + verify 통과 시 PR)

- 넘치는 글자(배치 · wordWrap · 말줄임) · 빠진 보조 단서(모양 · 글자)
- 이모지 · 장식 글리프를 규칙에 맞게 바꾸기
- IME를 거치지 않는 입력 칸
