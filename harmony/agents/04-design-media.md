# 4 디자인·미디어

## 목적

화면에 나오는 그림과 UI가 한 세계관으로 읽히고, 규칙을 지키며, 쓰이는 것만 실린다.

## 공통 점검

- 소비 에셋 목록: 개수 · 용량 · 크기 분포(지표 `images`).
- 참조되지 않는 소비 에셋 후보(지표 `possibly_unreferenced`) — 키를 조립해 쓰는 것은 오탐이므로 코드로 확인.
- 크기 · 배율 · 팔레트 · 이름의 일관성. 같은 종류인데 규격이 다른 것.
- UI 문구: 길이 넘침 위험, 용어 불일치, 번역 누락.
- 빠진 그림: 코드가 자리표시(임시 도형 · 폴백)로 버티는 곳의 목록과 필요한 규격.
- 새 그림이 필요한 곳에는 만들 수 있는 것(절차 생성 픽셀 아이콘 · SVG 목업)의 초안을 제안한다.

## 이 프로젝트 전용

- 지표 규칙: `no-ui-emoji`(이모지 · 장식 특수문자), `no-screen-edge-anchor`(화면 끝 상수 배치).
- 인게임 표현 규칙 R1~R12(AGENTS §4): 내부 용어 · id 노출, 스포일러, 조작 안내 문구, 텍스트 약어 배지.
- 아이콘은 16x16 손그림 픽셀 아이콘 경로(`tools/gen_pixel_icons.py` → `PixelIconArt` → `ui/PixelIcon.ts`).
- 레거시 `icon` 이모지 폴백(`InventoryStore` 시드 · `ShopCatalog`)의 남은 개수 추적.
- 비정수 배율 · 캐릭터(세로 52px) 대비 크기 규칙(R8).
- 백로그의 「에셋 대기」 항목과 실제 파일 유무 대조(사용자 작업 예정분은 건드리지 않는다).
- 실렌더 확인이 필요한 판단은 스킬 `verify-render` — 예약 실행에서는 확인하지 못한 것으로 적는다.

## 고칠 수 있는 것

- UI 문자열의 이모지를 색 칩 · 말머리로 교체(동작 불변일 때)
- 문구 오탈자

## 제안만 하는 것

- 그림 추가 · 교체 · 삭제
- 레이아웃 변경
- 아이콘 초안(파일로 넣지 말고 보고서에 규격과 초안만)
