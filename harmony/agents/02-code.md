# 2 코드

## 목적

필요한 기능만 남기고, 한 객체가 한 역할을 하도록 정리하며, 오류가 조용히 묻히지 않게 한다.

## 공통 점검

- 죽은 코드: 어디서도 불리지 않는 함수 · 파일 · export, 도달할 수 없는 분기.
- 중복: 같은 로직이 두 곳 이상에 복사된 것(공통 함수로 뽑을 후보).
- 역할 분리: 한 파일 · 한 클래스가 여러 책임을 지는 곳, 관련 기능이 흩어진 곳(묶을 후보).
- 오류 처리: 빈 catch, 무시되는 Promise, 경계값(0 · 음수 · 빈 배열 · NaN) 누락, 널 가능 값의 강제 단언.
- 타입: `any`, 강제 캐스팅, 타입 억제 주석의 증감.
- 매직 넘버 · 하드코딩 문자열(튜닝 표나 상수로 올릴 후보).
- 지나치게 긴 파일(`limits.long_file_lines` 초과)의 분할 계획 — 한 번에 쪼개지 말고 경계부터 제안.

## 이 프로젝트 전용

- 지표 규칙 위반 건수: `no-lowercase-gamestate` · `no-scene-start-field` · `no-bare-fadeout-wait` · `no-any` · `no-keydown-text-input`.
- 게임 로직이 `client-pc`에 직접 구현된 곳(core로 옮길 후보).
- 씬 전환: `pause + launch` / `stop + resume` 패턴, 재진입 가드 리셋(스킬 `scene-transition`).
- 세이브 하위호환: 새 필드에 시드 백필과 폴백이 있는지(스킬 `save-migration`).
- 매직 넘버는 `TUNING`으로(스킬 `add-tuning`).
- 1,500줄 초과 파일이 많다(`RegionFieldScene.ts` 등) — 분할은 제안만, 죽은 코드 제거 · 헬퍼 추출 같은 작은 단계부터.
- 파일 상단 JSDoc과 핵심 주석은 한국어.

## 고칠 수 있는 것

- 미사용 심볼 · 죽은 코드 제거
- 동작이 같은 작은 헬퍼 추출
- 빠진 경계값 방어 · 빈 catch 보강
- `any` 제거(타입이 명확할 때)

## 제안만 하는 것

- 대형 파일 분할
- 「완료된 시스템(수정 금지)」 목록 파일의 동작 변경
- 공개 인터페이스 이름 변경
- 밸런스에 영향을 주는 상수 변경
