# 8 노트·메모리

## 목적

다음 세션이 문서만 읽고 이어받을 수 있게, 기록이 사실과 맞고 짧고 한 곳에만 있게 한다.

## 공통 점검

- 사실 대조: 문서가 말하는 상태(완료 · 진행 · 파일 경로 · 명령)가 코드와 맞는지.
- 깨진 링크와 없는 파일을 가리키는 경로.
- 중복 기록: 같은 내용이 여러 문서에 길게 있는 곳.
- 패치 노트: 이전 점검 이후 커밋을 사용자용 변경 요약으로 정리한 초안(보고서에 싣는다).
- 버전 · 패키징: 패키지 버전, 배포 번호, 변경 기록의 일치.
- 에이전트 지침 문서의 길이와 최신성(세션 컨텍스트를 먹는 문서가 불어나지 않는지).

## 이 프로젝트 전용

- `CLAUDE.md` 「현재 진행 상황」 · `AGENTS.md` §9 = 최근 3개 차수만. 넘치면 발견 사항.
- 워크로그(`docs/wiki/03-WORKLOG/`) 색인(§3.1)과 파일의 일치, 8절 양식.
- 시스템 페이지(`02-SYSTEMS/`)는 누적이 아니라 갱신 — 차수 나열이 복사돼 있지 않은지.
- 가독성 규칙(스킬 `doc-readability`): 200자 넘는 줄(지표 `md_files_with_long_lines`), 5줄 이상 블록인용.
- `AGENTS.md` §5 「완료된 시스템」 표의 파일 경로가 실제로 있는지.
- 패키지 버전이 `0.1.0`에 머물러 있다 — 배포 번호(`gh-pages` n차)와의 대응은 제안 사항.
- 하모니는 차수 번호를 따지 않는다. 최근 차수 목록은 읽기만 한다.

## 고칠 수 있는 것

- 깨진 링크 · 경로
- 가독성 규칙 위반(내용 불변)
- 색인 누락 보충

## 제안만 하는 것

- 규칙 문서(§1~§8) 변경
- 문서 구조 개편
- 버전 정책
- 보관 문서 수정
