# 4 디자인·미디어

## 목적

화면에 나오는 그림과 UI가 한 세계관으로 읽히고, 규칙을 지키며, 쓰이는 것만 실린다.

## 공통 점검

- 소비 에셋 목록: 개수 · 용량 · 크기 분포(지표 `images`).
- 참조되지 않는 소비 에셋 후보(지표 `possibly_unreferenced`) — 키를 조립해 쓰는 것은 오탐이므로 코드로 확인.
- 크기 · 배율 · 팔레트 · 이름의 일관성. 같은 종류인데 규격이 다른 것.
- UI 문구: 길이 넘침 위험, 용어 불일치, 번역 누락.
- 빠진 그림: 코드가 자리표시(임시 도형 · 폴백)로 버티는 곳의 목록과 필요한 규격.
- 새 그림이 필요한 곳에는 만들 수 있는 것(절차 생성 픽셀 아이콘 · SVG 목업)의 초안을 제안한다.

## 이 프로젝트 전용

- 지표 규칙: `no-ui-emoji`(이모지 · 장식 특수문자), `no-screen-edge-anchor`(화면 끝 상수 배치).
- 인게임 표현 규칙 R1~R12(AGENTS §4): 내부 용어 · id 노출, 스포일러, 조작 안내 문구, 텍스트 약어 배지.
- 아이콘은 16x16 손그림 픽셀 아이콘 경로(`tools/gen_pixel_icons.py` → `PixelIconArt` → `ui/PixelIcon.ts`).
- 레거시 `icon` 이모지 폴백(`InventoryStore` 시드 · `ShopCatalog`)의 남은 개수 추적.
- 비정수 배율 · 캐릭터(세로 52px) 대비 크기 규칙(R8).
- 백로그의 「에셋 대기」 항목과 실제 파일 유무 대조(사용자 작업 예정분은 건드리지 않는다).
- 실렌더 확인이 필요한 판단은 스킬 `verify-render` — 예약 실행에서는 확인하지 못한 것으로 적는다.

## 고칠 수 있는 것

- UI 문자열의 이모지를 색 칩 · 말머리로 교체(동작 불변일 때)
- 문구 오탈자

## 제안만 하는 것

- 그림 추가 · 교체 · 삭제(예외: 「상시 학습 과제」 B의 코드로 그린 그림 개선)
- 맵 생성 규칙 변경(「상시 학습 과제」 A — 전후 그림과 함께)
- 레이아웃 변경
- 아이콘 초안(파일로 넣지 말고 보고서에 규격과 초안만)

## 상시 학습 과제 (2026-10-13 사용자 지시 — 매일)

> 사용자 판단: 「맵이 아직 시각적으로 이상한 곳이 많다(정교 · 정밀성 부족)」 · 「아이템 그림이 픽셀 기반이긴 하나 품질 자체를 올려야 한다」.
> 규칙 점검만으로는 이 둘이 나아지지 않는다. **매일 그림을 직접 보고, 기준을 스스로 세우고 고쳐 가며, 개선안을 낸다.**
> 심화 도메인이 아닌 날에도 한다. 날짜가 홀수면 A, 짝수면 B를 주로 하고 나머지는 지난 실행의 후속만 확인한다.

### 준비 (렌더 도구)

- 파이썬 그림 도구: `pip install -q --target <스크래치>/py pillow numpy` 뒤 `PYTHONPATH=<스크래치>/py`. 저장소에 설치 흔적을 남기지 않는다.
- 게임 실렌더: 스킬 `verify-render`(Playwright · `/opt/pw-browsers/chromium`). dev 서버는 컨테이너 안에서만 띄운다.
- 결과 그림(모아 보기 · 전후 비교)은 상태 브랜치 `harmony/visual/<날짜>/`에 넣는다(한 실행 2 MB 이하 · PNG). 저장소 main에는 넣지 않는다.
- 도구 설치 · 렌더가 실패하면 「확인하지 못함」으로 적고 코드 · 데이터만으로 할 수 있는 점검을 한다.

### A. 탑다운 맵 시각 품질

1. 대상 고르기: `knowledge/04-design-media.md` 「맵 품질 기준」의 점검 대장에서 가장 오래 안 본 구역 1~2곳(지역 × 화면 크기 칸).
   처음에는 속초 → 그 밖의 지역 순. 사용자가 최근 손댄 구역(워크로그 172 · 173 · 178 · 183~186차 계열)을 먼저.
2. 렌더: 타일맵 JSON(`tools/build_region_maps.py` 산출물)을 그 구역만 잘라 1× · 3× 두 배율로 그린다.
   가능하면 게임 실렌더 스크린샷도 같은 좌표로 찍어 둘을 비교한다(생성기 그림과 실제 화면이 다른 것도 결함이다).
3. 보는 것(기준표 — 노트에서 갱신해 간다): 타일 이음매 · 끊긴 선(도로 · 해안선 · 방파제) · 한 칸짜리 섬/구멍 · 경계의 계단 현상 ·
   건물 · 간판이 도로 위(R9) · 물체 크기가 캐릭터 52px 대비 어색함(R8) · 같은 재질의 색 불일치 · 깊이 정렬(가림 · 반투명 R10) ·
   위성 · 실제 지형과 다른 모양(워크로그에 근거가 있는 것만).
4. 기록: 결함마다 「지역 · 타일 좌표 · 무엇이 이상한가 · 어느 규칙/생성 단계에서 나오는가(추정이면 추정)」를 원장에 `4 디자인·미디어` 발견으로.
   같은 원인이 여러 곳이면 하나로 묶는다. 이미 사용자가 「의도」라고 한 것은 올리지 않는다.
5. 학습: 원인 · 규칙을 노트 「맵 품질 기준」에 갱신한다 — 기준표 항목 추가 · 오탐이던 항목 정정 · 생성 단계별 함정.
6. 개선안: 생성 규칙 수정은 **제안만**(전후 그림 · 영향 구역 수 · 바뀌는 파일). 맵 생성 결과는 사용자 육안 확정 대상이다.

### B. 아이템 · 아이콘 그림 품질

1. 대상 고르기: 노트 「아이템 그림 품질 기준」의 점검 대장에서 가장 오래 안 본 묶음 1개(`tools/item_art/icons_*.py` 파일 단위,
   또는 `PixelIconArt` · `SkillIconArt` · 어종 텍스처 `FishTextures` 묶음).
2. 렌더: `tools/item_art/build.py --sheet <스크래치>/sheet.png`처럼 묶음 모아 보기를 만들고, 실제 표시 크기(인벤 칸 · 툴팁)로 줄인 판도 만든다.
3. 보는 것(기준표 — 노트에서 갱신): 표시 크기에서 실루엣이 읽히는가 · 외곽선 두께 · 색 수 · 광원 방향 통일 · 같은 계열끼리 크기 비율 ·
   **어종 DB와 연동된 그림(`food assets/` 실사 → 어종 텍스처)과 색 · 비례 · 특징(무늬 · 지느러미 · 눈)이 맞는가** ·
   같은 물건이 화면마다 다른 그림으로 나오는가.
4. 기록 · 학습은 A와 같다(묶음 이름 · 아이템 id · 무엇이 약한가 · 기준표 어느 항목).
5. 개선 — **코드로 그린 그림(`tools/item_art/icons_*.py`)에 한해 직접 고칠 수 있다**:
   - 하루 한 묶음 · 그림 10장 이내 · PR 한도(300줄 · 15파일) 안. 생성기를 돌려 PNG와 `ItemArtManifest.ts`를 함께 갱신한다.
   - PR 본문에 전후 모아 보기 그림(상태 브랜치 `harmony/visual/` 링크)과 기준표 어느 항목을 고쳤는지 적는다.
   - 사용자가 넣은 래스터(실사 픽셀화 · `food assets/` 원본 · 직접 그린 PNG)는 건드리지 않는다 — 제안만.
   - 아이템 id · 텍스처 키 · 파일 이름은 바꾸지 않는다(세이브 · 매니페스트 호환).
   - 열린 하모니 PR 상한(3건)에 걸리면 제안으로 돌린다.
