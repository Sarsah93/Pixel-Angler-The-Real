# 6 티켓·경제

## 목적

남은 일의 목록이 실제 상태와 맞고, 게임 안에서 값이 들어오고 나가는 길에 새는 곳이 없게 한다.

## 공통 점검

- 티켓: 백로그 · 계획서 · 이슈의 항목을 코드 상태와 대조 — 이미 끝난 것, 선행 조건이 풀린 것, 오래 묵은 것.
- 코드의 TODO · FIXME 중 티켓에 없는 것.
- (게임) 자원 흐름표: 돈 · 아이템 · 경험치가 **생기는 곳**과 **사라지는 곳**을 전부 나열한다.
- (게임) 누수: 복제(같은 물건 · 돈이 두 번 생김), 무한 수급(비용 없이 반복 가능한 이득), 음수 · 넘침, 저장 · 불러오기로 되돌리는 이득.
- (게임) 운영 흐름: 구매 · 판매 · 제작 · 보상 · 벌칙 · 파산의 처리 순서와 중간에 끊겼을 때의 상태.
- (게임) 멀티플레이: 클라이언트가 보낸 값을 서버가 그대로 믿는 곳, 거래 양쪽의 원자성.

## 이 프로젝트 전용

- 티켓 원본: `docs/wiki/04-BACKLOG.md`(A 잔여 · B 위험 · C 최적화 · D 미해결 질문), `.agents/IMPLEMENTATION_PLAN.md`.
- 판매가 공식: `evaluateFishSellPrice` × 상태 배율 × 0.6 — 시세 캐시와 `getMarketPriceFactor`의 이중 적용 여부.
- 시세 하락 장부(`MarketSaturation` · `MarketStore`), 위판 맡기기(`Consign*`), 하루 결산(`DayLedger` · `LedgerStore`).
- 거래 적용 순서 = 인벤토리 → 저장 → 서버 「적용함」(232차). 거래품 꼬리표(`traded`)와 `ownOnly` 퀘스트(233차).
- 파산 = 슬롯 삭제 + 저장 잠금(231차) — 잠금을 우회하는 저장 경로가 없는지.
- 채집 고갈 키(`f:맵|스팟`) · 공유 소비 채널 — 주인만 고쳐 쓰는지.
- 231차 멀티 전수조사 잔여(백로그 BI)의 진행 상태.
- 밸런스 수치는 사용자 실플레이로 정한다 — 수치 자체는 제안만, 흐름의 결함만 발견 사항으로.

## 고칠 수 있는 것

- 백로그에서 이미 해소된 항목의 상태 표기(근거 커밋 · 파일을 함께)
- 명백한 복제 · 음수 방어 누락(검증 가능할 때)

## 제안만 하는 것

- 가격 · 보상 · 확률 · 재생 시간 변경
- 거래 · 저장 순서 변경
- 서버 판정 추가
- 사용자 답이 필요한 티켓의 결정
