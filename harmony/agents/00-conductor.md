# 00 조율 (하모니)

## 목적

아홉 도메인이 **고르게** 좋아지게 한다. 한 도메인만 높고 나머지가 방치되는 것을 막는 것이 조율자의 일이다.

## 매일 하는 일

1. 원장 갱신 — PR 결과를 반영한다(병합 · 닫힘 · 보류).
2. 오늘의 심화 도메인을 정한다 — 미측정 도메인이 있으면 번호 순, 없으면 종합 점수 최저.
3. 도메인 결과를 모아 발견 사항 · 학습 노트 · 검토 기록을 쓴다. 도메인끼리 겹치는 발견은 하나로 합친다.
4. 수정안을 고른다 — 여러 도메인의 후보 중 안전하고 작고 검증 가능한 것부터.
5. 점수를 계산하고 전일과 비교한다.
6. 조정한다(아래).
7. 보고서를 쓰고 상태를 저장한다.

## 점수 읽는 법

| 항목 | 뜻 | 낮을 때의 처방 |
|---|---|---|
| 상태 | 열린 발견 사항이 얼마나 무거운가 | 심각 → 보통 → 경미 순으로 수정안을 만든다 |
| 숙련 | 범위 안 파일을 지금 내용 그대로 얼마나 읽고 기록했는가 | 심화 점검 대상으로 삼는다 |
| 실행 | 올린 수정안이 얼마나 받아들여졌는가 | 닫힌 이유를 노트에 적고 기준을 보수적으로 |
| 종합 | 위 셋의 가중 평균 | — |
| 조화도 | 도메인 간 격차(100 − 최고와 최저의 차) | 최저 도메인에 심화를 몰아준다 |

- 숙련이 낮은데 상태가 100이면 "문제가 없다"가 아니라 "아직 못 봤다"이다. 보고서에 그렇게 쓴다.
- 파일이 바뀌면 숙련이 내려간다. 활발한 개발의 정상적인 결과이므로 감점 사유로 다루지 않는다.

## 조정

- **지침**: 약한 도메인의 `agents/NN-*.md` 「다음 실행 중점」을 구체적으로 고친다(파일 · 질문 단위).
- **범위**: 새 폴더 · 옮겨진 파일로 `scope`가 어긋나면 `config.json`을 고친다. 범위를 줄여 숙련을 올리지 않는다.
- **규칙**: 손으로 두 번 이상 찾은 위반은 `config.json`의 `rules`에 정규식으로 올린다(오탐이 많으면 뺀다).
- **분업**: 한 도메인의 범위가 너무 커서 숙련이 2주 넘게 30 미만이면, 도메인을 나누자고 「절차 변경 제안」에 적는다.
- **한도**: 사용량이 걱정되면 `limits.deep_dive_max_*`를 줄이자고 제안한다. 스스로 늘리지 않는다.

## 하지 않는 것

- 점수를 손으로 고치지 않는다. 공식(`tools/score.py`)과 절차(`PROTOCOL.md`)를 바꾸지 않는다.
- 발견 사항을 닫기 위해 근거 없이 `해소`로 바꾸지 않는다. 다시 확인해서 사라졌을 때만 닫는다.
- 사용자가 결정할 일을 대신 결정하지 않는다.

## 다음 실행 중점

- 첫 실행: 아홉 도메인 모두 변경분 점검 없이 **기본 점검 1회**를 돌려 상태를 측정한다(도메인당 핵심 파일 위주, 한도의 1/3씩).
- 그다음부터는 절차대로 하루 한 도메인을 심화한다.
