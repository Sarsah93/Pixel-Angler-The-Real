# 00 조율 (하모니 v2)

## 목적

매일 **플레이어가 겪을 문제를 하나라도 더 찾아 고치게** 한다.
점수를 올리는 것이 목적이 아니다 — 점수는 「어디를 오래 안 봤나」를 알려 주는 보조 지표다.

## 매일 하는 일

1. 원장 갱신 — PR 결과(병합 · 닫힘 · 보류).
2. 오늘 갈래 확인(요일 → `config.json` `schedule`). 새 커밋이 있으면 변경분 영향 점검을 먼저.
3. 시나리오를 고르고 **돌린다**(하네스 · 정적 표 · 그림 보기 · 웹 자료).
4. 버그마다 같은 모양 훑기 → 패턴 목록 갱신.
5. 재현 + 검증된 작은 결함 수정은 PR, 밸런스 · 설계는 제안.
6. 점수 · 보고서 · 상태 저장 · 토큰 기록.

## 우선순위 (시간 · 예산이 모자랄 때)

1. 기본 점검이 깨졌으면 그 원인.
2. 새 커밋의 회귀(변경분 영향 점검에서 재현된 것).
3. 오늘 갈래의 **심각** 후보 재현.
4. 오늘 갈래 시나리오(한 번도 안 돌린 것 먼저).
5. 열린 발견 재확인 · 문서.

## 점수 읽는 법 (v2)

| 항목 | 뜻 | 낮을 때의 처방 |
|---|---|---|
| 상태 | 열린 발견이 얼마나 무거운가 | 심각 → 보통 순으로 재현 · 수정 PR |
| 시나리오 | 최근 14일 안에 돌린 시나리오 비율 | 그 갈래 요일에 안 돌린 시나리오부터 |
| 실행 | 올린 수정 PR이 얼마나 병합됐는가 | 닫힌 이유를 지침에 적고 기준을 보수적으로 |
| 하모니 지수 | 제품 갈래 ①~⑥ 종합의 평균 | 지수보다 「오늘 찾음 · 고침」을 먼저 본다 |

- 상태가 100인데 시나리오가 낮으면 「문제가 없다」가 아니라 「아직 안 돌려 봤다」이다. 보고서에 그렇게 쓴다.

## 하지 않는 것

- 점수를 손으로 고치지 않는다. 공식(`tools/score.py`)과 절차(`PROTOCOL.md`)를 바꾸지 않는다.
- 근거 없이 `해소`로 바꾸지 않는다. 다시 돌려서 사라졌을 때만 닫는다.
- 사용자가 결정할 일(밸런스 값 · 설계 · 「사용자 판단」 백로그)을 대신 결정하지 않는다.
- 문서 정리로 하루를 쓰지 않는다 — 문서는 일요일 갈래다.
