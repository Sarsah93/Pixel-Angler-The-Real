## 1. 배경

사용자 원문:

> 3D를 요구하는 건 아니나, 실제 위성지도(OSM 같은) 기반으로 타일을 따와서 배치할 때,
> 현재 적용된 버전의 타일보다 좀 더 자연스럽고 정교하게 배치할 수 없을까?
> 지금 적용된 건 정말 '도로-모래-바다'의 경계 또는 돌바닥-테트라포트 타일 경계는 명확히 보이지만,
> 각 경계 간 사이의 중간 타일이라던지, 높낮이 타일이 없다던지, 방파제 쪽에서는 돌바닥-테트라포트
> 사이에 자연스러운 타일이 없다던지 등 부족한 부분이 많아.

레퍼런스(다른 게임 캡처 2·3번)의 공통점은 셋이다.

- 경계가 **격자와 무관한 선**(곡선·45°)으로 흐른다.
- 두 재료 사이에 **중간 띠**(젖은 모래 → 포말 → 얕은 물 / 돌 부스러기)가 있다.
- 높이가 다르면 **옆면(턱)과 그림자**가 보인다.

## 2. 원인 — 무엇이 계단을 만들었나

실렌더 6지점(해변 3 · 방파제 3)을 같은 좌표에서 찍어 비교했다.

| 증상 | 기전 |
|---|---|
| 해변-바다 경계가 계단 | 105~106차 **직선 접경 셀을 방위별로 회전해** 물 타일에 붙였다. 셀 하나는 예쁘지만 대각선 해안에서 셀이 1타일 계단으로 이어진다. |
| 안벽·호안 대각선이 계단 + 검은 윤곽 | 물 타일 가장자리 포말(`noRim`)과 뭍 타일 경계선이 **타일 변을 따라** 그어졌다. 대각 스무딩(101차 `tri`)은 **뭍↔뭍 전용**이었다. |
| 포장 광장(`p`) ↔ 맨땅(`.`) 계단 | `terrainGroup('p') = '.'`이라 101차 삼각 규칙이 **같은 군**으로 보고 건너뛰었다. 그런데 렌더는 `p`에 자기 베이스(`pave`)를 깔아 색이 다르다. |
| 방파제 단면 띠가 타일 상자 | 114차 `computeBreakwaters`가 **물까지 거리**로 상판/사석/피복을 타일 단위로 배정한다 — 대각선 방파제에서 띠가 상자 계단이 된다. |
| 높이가 평면 | 상판·사석·피복·물이 같은 평면에 붙어 있어 "돌바닥 ↔ 테트라포드"가 색 경계로만 읽혔다. |

⚠ 첫 시도의 오류(실렌더로 잡음):

- 사석 쪽에도 콘크리트 알갱이 띠를 깔았더니 사석 셀 둘레가 **회색 액자**처럼 보였다 → 피복 쪽에만.
- 45° 호안 삼각형이 **베이지**로 나왔다 — `groundTex.get(terrainGroup('p'))`가 맨땅 텍스처를 돌려줬다.
- 방파제 45°가 몇 곳에서만 붙었다 — 띠가 1타일 두께라 **대각 이웃이 한 단계 더 바다 쪽**인 경우가 대부분이었다.

## 3. 변경

| 구분 | 위치 | 내용 |
|---|---|---|
| 신설 | `packages/core/src/rules/TerrainTransition.ts` | `reliefHeight(ch, bwClass)` — 의사 높이(물 0 · 피복 1 · 사석 2 · 상판·안벽·포장 3 · 모래·갯벌 1) · `castsReliefShadow` · `BreakwaterClass` |
| 신설 | `SeamlessChunks.drawShoreBlend` | **곡선 해안선** — 모래 쪽·물 쪽 타일이 같은 함수 `v = s − o`(부호 거리 − 전역 노이즈)를 평가 → 젖은 모래 → 포말 → 부서진 거품 → 얕은 물(모래가 비침) + 두 번째 물결선. 경계 모양은 **타일 중심 쌍선형 보간장**(마칭 스퀘어)이라 1타일 계단이 45° 선으로 펴진다. |
| 신설 | `SeamlessChunks.waterChamferAt` · `drawChamferRim` | **45° 호안** — 물 타일의 안쪽 모서리(직교 두 변 + 대각이 단단한 뭍)에 그 뭍 재질의 삼각형을 얹고, 빗변을 따라 턱 그림자 + 포말. 광장(`r`)·포장(`p`)은 자기 재질 삼각형. |
| 신설 | `SeamlessChunks.bwChamferAt` · `triOf` · `drawChamferRelief` | **방파제 45°** — 상판 → 사석 → 피복 띠의 바깥 모서리를 더 바다 쪽 재료의 삼각형으로 덮고, 빗변에 옆면(남향)·하이라이트(북서)·그림자(남동)를 그린다. 삼각형 텍스처는 필요할 때 굽는다. |
| 신설 | `SeamlessChunks.drawBreakwaterSeam` | 피복 ↔ 사석: 사석 덩어리(3~5px + 그늘 + 윗면 빛)가 블록 틈으로 흘러들고, 사석 쪽에는 파편이 드문드문. |
| 신설 | `SeamlessChunks.drawReliefShadow` | 단차 — 높은 이웃이 북·서면 폭 `4 × 높이차` 그림자(2px 디더), 상판 남쪽 옆면(턱)·동쪽 어두운 면·북서 하이라이트. 이웃·자신의 45° 모서리가 덮은 변은 건너뛴다. |
| 수정 | `SeamlessChunks` 지면 패스 | 포장(`p`) 타일 모서리에 맨땅 삼각형(칠하기 순서: 낮은 쪽이 덮는다) · 이웃 삼각형이 덮은 변은 옛 계단 윤곽선을 긋지 않는다. |
| 수정 | `SeamlessChunks` 물 패스 | `SHORE_BLEND` 켜짐이면 직선 접경 셀(TTP 시트)을 깔지 않는다. 45° 호안 타일은 직선 포말 대신 빗변 포말. |
| 수정 | `ensurePlazaTextures` | 광장 텍스처의 삼각형 변형 4종. |

## 4. 구조상 위치

`월드 필드 → 타일 렌더(심리스 청크) → 경계 전이`. **렌더 층만** 건드렸다.

- 충돌·통행·지형 데이터·세이브는 불변. 45° 삼각형은 **그림**이다 — 물 타일 위 뭍 삼각형은 여전히 물(막힘),
  상판 모서리의 사석 삼각형은 여전히 걸을 수 있다.
- 높이 표(`reliefHeight`)는 core가 정한다(172차 원칙 — "core가 규칙, 렌더는 그리기").

## 6. 잔여

- **테트라포드 ↔ 물 경계의 45°** — 피복 시트 셀은 가장자리까지 블록이 차 있어 삼각형으로 자르면 블록이 반쪽이 된다.
  블록 단위 배치(편집기 겹침 허용)와 함께 다룰 것.
- **2타일 이상 폭의 계단**(경사 2:1)은 45° 삼각형 하나로 다 펴지지 않는다 — 한 칸씩 노치가 남는다.
  필요하면 26.6° 삼각형 쌍을 추가한다.
- **모래 ↔ 포장**은 172차 알갱이 띠 그대로다(선은 곧다). 레퍼런스 3번처럼 연석 그림자를 줄지는 사용자 확인 후.
- 청크 경계를 넘는 45° 모서리의 윤곽선 생략은 청크 안에서만 판정된다(이웃 청크의 삼각형은 모름) — 육안상 차이는 미미.

## 7. 위험·부작용

- **청크 굽기 +3.6ms(중앙값)** — 해안·방파제 청크에서 2px 단위 루프가 늘었다. 한 프레임 한 청크라 60fps 예산 안이지만,
  저사양에서는 해안 이동 중 프레임이 튈 수 있다.
- 45° 삼각형은 충돌과 어긋난다 — 물 위 뭍 삼각형 끝(최대 반 타일)은 **보이지만 못 딛는다**,
  상판 모서리의 사석 삼각형은 **딛을 수 있다**. 둘 다 원래도 딛을 수 있던/없던 타일이라 통행은 불변.
- `SHORE_BLEND = false`로 105~106차 경로 복귀 가능.
