## 1. 배경

로드맵 다음 단계(사용자 확정)는 **가방 2~4단계**였다.

착수 조사에서 라벨과 실제가 어긋난 것을 다시 만났다 — **가방 아이템은 이미 다 있었다.**
141차가 `bagSlots` 3·5·8·10·12 다섯 개를 실물로 발행했고(`QuestRewardItems.ts`),
`InventoryStore.gridCapacity()`가 그 값을 소비하고 있었다.

문제는 그 다음 줄이었다.

```ts
export const GRID_CAPACITY_MAX = 30;   // 135차
gridCapacity() { return Math.min(GRID_CAPACITY_MAX, GRID_CAPACITY + (bag?.bagSlots ?? 0)); }
```

25 + 8 · 25 + 10 · 25 + 12 가 **전부 30으로 클램프**된다. 즉 Ch3 원정 가방(8)·Ch5 가이드 가방(10)·
Ch6 항해 가방(12)이 **서로 똑같은 효과**였다. 미구현이 아니라 **죽은 보상**이다
(144차 `'run'`·147차 `AuctionEngine`에 이은 세 번째 같은 패턴).

그리고 30이라는 숫자는 밸런스가 아니라 **렌더 한계**였다 — 135차 주석이 그렇게 적어 두었다:
"인벤 패널 세로 여백의 실측 한계다(7행이면 하단 상태줄을 침범한다 — **더 늘리려면 패널 재설계가 먼저**)."

그래서 148차의 실제 작업은 가방이 아니라 **`InventoryPanel` 재설계**이고, 방식은
사용자가 고른 **윈도우드 스크롤**이다.

## 2. 원인 (확정)

| 증상 | 기전 | 근거 |
|---|---|---|
| 8·10·12 가방이 같은 효과 | `GRID_CAPACITY_MAX = 30` 클램프 | 실측 — 상한 해제 전 셋 다 `gridCapacity() = 30` |
| 상한을 못 올림 | 그리드가 **용량 전부를 한 화면에** 그린다(스크롤 없음) | `renderGrid`가 `for (idx = 0; idx < cap; idx++)` |
| 시드 4건이 유저에게 안 보임 | `tackle` 29개 > 25칸 — slot 25~28은 루프 밖 | 135차 dev 경고 + 이번 실렌더 재현 |

### 3-1. 가방 사다리 (실측)

| 가방 | 퀘스트 | `bagSlots` | 용량 |
|---|---|---|---|
| (없음) | — | — | **25** |
| 옛 계원의 채비 주머니 | M1-08 | 3 | **28** |
| 촬영 스태프 필드백 | Ch2 | 5 | **30** |
| 어촌계 원정 가방 | Ch3 | 8 | **33** |
| 가이드 가방 | Ch5 | 10 | **35** |
| 원거리 항해 가방 | Ch6 | 12 | **37** |

### 3-2. 윈도우드 스크롤 지오메트리

```
뷰포트 = gridY0(88) ~ GRID_VP_BOTTOM(504)  = 416px
행 간격 = 가방 없음 7px → 5행 가시 / 가방 착용 4px → 6행 가시
전체 행 = ceil(totalSlots / 5)          (37칸 = 8행)
표기·안내 = 뷰포트 아래 13px 띠 (좌 = 잠긴 칸 안내 / 우 = n–m / N행)
```

⚠ **마스크를 쓰지 않았다.** Phaser는 마스크로 **입력을 클립하지 않아** 스크롤아웃된 셀의
히트가 그대로 남는다(54차 ShopPanel 전례 — `ui-panel` 스킬 규칙). 인터랙티브 그리드는
"보이는 행만 생성"이 유일한 안전한 방식이다.

### 3-3. 잠긴 칸 (용량 밖)

용량을 넘는 칸에 아이템이 남아 있으면 **그 칸까지 그린다** — 어두운 바탕 + 주황 테두리.

- **꺼내기는 된다**(드래그·우클릭 메뉴 전부 정상) · **넣기는 거부**(`moveItem` + 패널 안내).
- 좌하단 `잠긴 칸 N행 — 가방을 착용하면 열립니다`.
- 이로써 135차 dev 경고가 가리키던 **시드 tackle 4건이 처음으로 화면에 나온다**.

### 3-4. 칸 축소 가드 일반화

135차의 `bagUnequipBlocked`는 "벗기"만 봤다. 사다리가 5단계로 분화되면서
**12칸 → 3칸 교체**가 가능해졌고, 그러면 확장 칸이 잠긴다.
`bagShrinkBlocked(bag, targetBagSlots)` 하나로 벗기(target 0)와 교체를 함께 막는다.
(S5 §5가 "가방 2단계 이상을 도입하면 교체 경로에도 가드가 필요하다"고 적어 둔 그 항목이다.)

## 4. 구조상 위치

`시스템 S5 인벤토리 → 세부과제 「가방 사다리」·「그리드 렌더」 → 이 작업`.

- **용량 계약**(`gridCapacity`)은 스토어 한 곳 — 상한 상수만 바뀌었다.
- **렌더/입력**은 패널 한 곳 — 스토어 계약은 그대로다.
- 세이브 스키마 무변경(`slot` 숫자 그대로) → **구세이브 회귀 없음**.

## 6. 잔여

- **시드 tackle 29개**는 그대로다 — 이제 '잠긴 칸'으로 보이고 꺼낼 수 있으므로 사라지지 않지만,
  기본 25칸에서 4칸이 잠긴 채 시작하는 것은 변함없다. 시드를 줄일지 가방을 전제할지는 데이터 결정.
- **탭별 용량 차등**(`BACKPACK_SPECS.slotsPerTabRatio` — 134차 core 모델)은 여전히 미배선이다.
  현재 실경로는 `bagSlots` 단일 축이고, core 모델은 `resolveSlotsPerTab`/`canUnequipBag` 모두
  소비처가 없다. 두 모델을 합칠지 core 쪽을 걷어낼지는 별도 결정(백로그).
- 드래그 자동 스크롤 간격(`AUTOSCROLL_MS` 220ms)은 실플레이 체감 조율 여지.

## 7. 위험·부작용

- **회귀 지점**: `slotAtPointer`가 이제 스크롤 오프셋을 더한다 — 드래그 이동·우클릭 메뉴가 전부 이 경로다.
  실렌더에서 스크롤 0·2행 양쪽을 확인했다.
- `gridCapacity()`가 30 → 최대 37로 커지므로 **`freeSlotCount`·`findFreeSlot`·쿨러 이송량**이 함께 늘어난다.
  의도된 변화(가방 보상의 실체)이고, 가방이 없으면 25 그대로라 구세이브는 불변.
- 잠긴 칸은 **드래그로 꺼낼 수 있다** — 넣기만 막는다. 아이템 유실 경로는 없다.
- ⚠ 성능: 렌더 셀 수가 늘지 않는다(보이는 행만 생성) — 오히려 37칸을 전부 그리는 것보다 가볍다.
