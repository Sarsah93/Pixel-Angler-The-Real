# 175차 — 표준명 문치가자미 + 대구 흰 배경 제거 + 갈치 픽셀아트 교체

- 일자: 2026-09-23
- 대상 시스템: S20 발견·위키(어종 실사 에셋) · 어종 DB 표시명
- 상태: ✅ 완결

## 1. 배경

사용자 지시 3건(원문):

> 표준명 문치가자미로 하자.
> 그리고 두 가지. 대구 생선 배경이 투명이 아니라 흰색인 것 같아. 수정이 필요해 보이네.
> 또한, 갈치 사진이 아직도 구형이야. 왜 교체를 못하고 있지? (캡처 사진이 새로운 갈치 픽셀아트야)

174차에서 매핑한 7종 중 3번(`flounder`)의 표시명이 「참도다리(문치가자미)」였고,
174차 워크로그 §6에 "표시명 확인 대기"로 남겨 둔 항목이다. 나머지 둘은 174차와 무관한 기존 에셋 결함이다.

## 2. 원인

**① 표시명** — 설계 시점에 별칭을 괄호로 병기한 것이고 버그는 아니다. 사용자가 표준명으로 확정했다.

**② 대구 흰 배경** — `pacific_cod.png`는 **RGBA인데 투명 화소가 0.0%** 였다(실측).
네 모서리 전부 `(255,255,255,255)`. 알파 채널만 있고 배경이 **불투명 흰색으로 구워져** 있었다.
174차 체커보드 건과 같은 계열이지만 **패턴이 아니라 단색 매트**라 격자 모델이 아니라 테두리 BFS로 충분하다.

**③ 갈치 — 교체가 빗나간 실제 기전.**
`public/fish/`에 **`hairtail.png`는 존재하지 않는다**. `fish_hairtail` 텍스처가 읽는 파일은
**`Cutlassfish.png`(대문자 C)** 였다. 폴더의 나머지 50개가 전부 소문자인데 이것 하나만 대문자라,
어종 id(`hairtail`)나 소문자 통칭으로 파일을 쓰면 **게임이 한 번도 읽지 않는 새 파일이 생기고
구 이미지는 그대로 남는다**. 사용자가 "왜 교체를 못하고 있지?"라고 물은 상태가 정확히 이것이다.

## 4. 구조상 위치

`S20 발견·위키 → 어종 실사 에셋 → 이번 작업`.
층은 **데이터·에셋**이다. 표시명은 core DB 2곳(도감·오라클)이 소유하고,
그림은 `public/fish/*.png` → `BootScene` 로드 → `FISH_TEXTURE` → 어획 팝업·인벤·상세·위키가 공유한다.
판정·렌더 코드는 한 줄도 건드리지 않았다.

## 5. 검증

| 대상 | 방법 | 결과 |
|---|---|---|
| 표시명 | `dist`에서 `FISH_DATABASE` 조회 | `flounder` = **문치가자미** · 참도다리 잔존 **0** |
| 도다리류 분화 | 4종 동시 조회 | 문치가자미 / 도다리 / 강도다리 / 광어(넙치) — 중복 없음 |
| 대구 배경 | PIL 화소 집계 | 투명 **0.0% → 45.5%** · 잔여 흰 화소 **1**(샘플 기준) |
| 대구 육안 | 패널색(0x1a1c22) 합성 | 지느러미 해칭 보존 · 흰 테두리 없음 |
| 인게임 텍스처 | 실렌더(`__PIXEL_ANGLER_GAME`) | `fish_hairtail` **1024×203**(신규) · `fish_pacific_cod` **1545×546** · `fish_flounder` 1728×910 — 3/3 로드 |
| 위키 카드 | 실클릭 + 라벨→카드 역추적 | 갈치·대구·문치가자미·도다리·강도다리·광어·병어·덕대 **8/8 정확** |
| 위키 이미지 | 60장 로드 검사 | 깨짐 **0** · 404 **0** · pageerror **0** |
| 빌드 | `pnpm run build` / typecheck | **3/3** · **0 오류** |

아티팩트 **Version 15** 재발행(같은 URL) — 바뀐 썸네일 2장(`fish_hairtail`·`fish_pacific_cod`)만 갱신.

⚠ 검증 하네스 함정: 로컬 `python3 -m http.server`는 charset을 안 보내 한글이 깨진다(발행본은 래퍼가 붙인다).
로컬 점검용 사본에 `<meta charset>`을 주입해서 봐야 한다.

## 6. 잔여

- **병어·덕대 해상도**(174차 이월) — 473×318 / 484×288로 다른 어종(1,400~2,000px)보다 낮아
  어획 팝업 대형 렌더에서 거칠다. 고해상 원본이 오면 교체.
- 그림이 없는 수산생물 **20종**(174차 기준) — 사용자 에셋 대기.

## 7. 위험·부작용

- **표시명 변경은 세이브에 무해하다** — 세이브는 `speciesId`를 저장하고 `nameKo`는 조회값이다.
  구세이브의 어획물도 재로드 시 「문치가자미」로 표기된다.
- **대구 이미지가 작아졌다**(1592×656 → 1545×546). 렌더는 종횡비 유지 축소라 레이아웃 영향은 없다.
- ⚠ **파일명 대소문자 함정** — gh-pages는 대소문자를 구분한다. 이번에 소문자로 통일했으므로
  앞으로 `public/fish/`에 대문자 파일명을 다시 만들지 않는다(같은 교체 실패가 재현된다).
