## 1. 배경 — 왜 했나

위성·DEM으로 OSM 결손을 메우는 **래스터 보강 스펙 v2**가 Antigravity 발주 직전 상태.
발주 전 검토에서 확인된 선행 정정(§0-2)과 부대 요구를 이쪽(Claude Code)에서 먼저 처리했다.
사용자 추가 지시: *"credits 관련해서, 리소스 사용 관련 메인화면에서 남겨야 함."*

## 2. 원인 — 무엇이 문제였나

- **스펙 자기모순**: `OSM_TILEMAP_SPEC` §0.5-1이 "타일 픽셀 = 20px·청크 64타일"로 남아 있었다.
  실제는 101차 후속 2에서 **TR 32·청크 32타일**로 전환([RegionFieldScene.ts:294](../../../packages/client-pc/src/scenes/RegionFieldScene.ts#L294)).
  §0.5는 본문보다 우선하는 규칙이라 이대로면 발주 에이전트가 20px 기준으로 산식을 다시 짤 위험.
  §0.5-11의 "지면 타일셋 비정수비로 미적용"도 같은 시절 표기(실제는 Kenney ×2 적용됨).
- **파이프라인 이원화**: `packages/map-builder`(8차 GIS 잔재 — TS 191줄 + 파이썬 418줄)가
  워크스페이스 빌드에 참여 중이지만 **import 사용처 0**(실측). 정본은 루트 `tools/`.
- **캐시 정책 부재**: `_rastercache`(지역당 수백 MB)가 `.gitignore`에 없었다.
  `_osmcache`는 반대로 이미 커밋되어 있음(sokcho_v2 1.8MB) — 재fetch 없이 재빌드 재현용으로 유지.

## 5-b. 후속(같은 날) — §8-7 낚시 판정 교체 실기 검증 (코드 변경 0 — 분석 전용)

발주측 요청 3항을 정적 전수 분석(seamless.json) + 인게임 프로브로 판정했다.

| 질문 | 결과 |
|---|---|
| ① 방파제 끝단 캐스팅 되는가 | **O** — 속초항 외항 방파제 끝단 가장자리 (613,204) `b`에서 현행·신규 규칙 모두 캐스팅 가능(스크린샷·캐스팅 프롬프트 표시). ⚠ 폭 8~10타일 방파제의 **내부 타일은 발판이 아님**(인접 8방에 바다 없음 — 가장자리만) = 정상 |
| ② 추론 b 오검출 | **0건** — b 2,583타일·118성분 전수에서 **바다와 안 닿는 성분 0**. 백사장 한복판·도로변 b 없음 |
| ③ 방파제 끊김 | **주요 방파제 전 성분 스폰에서 도보 도달 O**. 도달 불가 = 12성분 101타일 전부 조도 주변 갯바위·이안제(장사항 (60,35)·외옹치 (351,539) 등) = 스펙 §3-2-4 detached 케이스로 **의도된 불가**(조도 도보 불가 체크 통과) |

**교체 시 손익 (결정 근거)**:

- 현행 규칙(걷기 타일 + 인접 8방 바다) 발판 = **7,593타일**
  (`.` 4,544 · b 1,267 · w 894 · s 317 · r 301 · `,` 270).
- §8-7 규칙(b|s + 인접 바다) 발판 = **1,584타일** — **79% 상실**.
- **b/s ⊂ 걷기 타일이므로 교체가 새로 여는 발판은 0개다** — 방파제 낚시는 현행 규칙으로 이미 된다.
- 상실분의 실체 = 속초항 내항 부두 안벽(실기 (542,351): 현행 O → 신규 X) ·
  **청초호 내안 전체**((448,458): 현행 O → 신규 X — 실제로 감성돔·숭어 낚시터라 고증에도 역행).

**권고**: §8-7은 "교체"가 아니라 **"현행 유지 + b/s 발판 보너스"**(`isFishableStandTerrain`을
스폰/입질 가중에 소비 — §0.5-2가 예약해 둔 의도 그대로)로 개정. Phase 1은 블로커가 아니므로
"추론 b의 위성 정밀화(폭·끝단 형상·이안제·테트라포드 열)"로 격하하고 우선순위는 Phase 2/오토타일 뒤로.

## 6. 잔여 — 이번에 안 한 것

- **래스터 스펙 본 작업**(fetch/classify/병합/§8-7) — Antigravity 발주분. 검토에서 지적한
  **Phase 1 전제 재정의**(b는 이미 2,583 — 103차 추론. "5→400" 폐기, 위성↔추론 diff 검증으로)와
  **§6 병합에 "래스터 b vs 추론 b" 규칙 추가**는 스펙 개정에 반영 필요.
- Sentinel-2·국토지리정보원 `DataAttributions` 엔트리 — **실사용 시점**(발주 step 9)에 추가.
  추가 시 메인화면 푸터 문구도 함께 갱신(코드 주석으로 안내해 둠).

## 7. 위험·부작용

- **빌드 기준 4/4 → 3/3** — 과거 문서·워크로그의 "4/4" 표기는 당시 기준(소급 수정 안 함).
