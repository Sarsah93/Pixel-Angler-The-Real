## 1. 배경 — 왜 했나

사용자 지시 4건(원문 요지):

1. **대화창** — "NPC 대화창 팝업에서 왼쪽에 캐릭터 외형과 우호도가 보이는 게 있는데, 안에 내용이
   위로 쏠린 느낌이야. 아래 여유 공간이 있어보이니 살짝 내려주면 좋을 것 같네. 그리고, 팝업 창 자체의
   디자인을 기존과 통일시켜야 할 것 같아. HUD 및 팝업창 내 텍스트 품질도 올리는 것을 고려해보자."
2. **AI 메모 제거** — "캐릭터 만들기 씬에서, 외형 창 우측 상단 배너에 '바닐라 = 나체 + 언더웨어
   옷은 장착 아이템'은 필요 없는 것 같아. 이렇듯, 인게임 내, 유저가 볼 필요 없거나 해석할 필요가
   없는 AI가 메모를 달아 놓은 것과 같은 표시나 설명들은 배제하는 게 좋을 것 같아."
3. **싱글/멀티** — "멀티플레이 이름은 세션 잡고 들어가는 과정 먼저 구현하고, 그 이후 슬롯 3개
   보여주고, 슬롯 선택하여 캐릭터 새로 생성하도록 전개." + 이름 중복 검사 문구 4종 지정 +
   "멀티플레이로 진행했을 때, 현재 구현된 모든 요소에서 걸리는 부분들이 있다면 알려줘."
4. **필드 라벨** — "인게임 내 지도에서, 뜬금없이 바닥에 동그라미(점) 표시와 '속초항 국제여객터미널'
   이라는 글씨가 출력되고 있어 … 캐릭터, NPC 및 상호작용 가능한 건물을 제외하고는 우선 숨김 처리 …
   건물 같은 경우는 … 미니맵에서 pin의 형태로 … 퀘스트 상태 표시(?, !)등을 미니맵에 보여주게."

후속: "'당신은 어떤 사람으로 속초에 도착합니까' 보다는 '당신은 어떤 사람인가요?'가 맞을 것 같네.
이렇듯 UI적으로 표시 및 출력되는 텍스트들의 어감 및 표현이 너무 AI 같으니, 전체적으로 좀 다듬을 필요가 있어."

## 2. 원인 — 무엇이 문제였나

**대화창 초상 열이 위로 쏠린 것**은 레이아웃 버그가 아니라 **기준점 선택**이었다.
`renderPortrait`가 초상·게이지·라벨을 전부 박스 **상단(y=4)** 에 매달아 놓았다 — 실측:
그림자 y≈150 · 스프라이트 하단 y≈148 · 눈금 바 y=170 · 라벨 y=184, 박스 높이는 260.
아래 **약 70px가 늘 비어 있었다**.

**팝업 프레임이 HUD와 달랐던 것**은 `DraggablePanel`이 자체 `fillRoundedRect(0x0a1628)` +
헤더 `0x0d2a40`를 그렸기 때문이다. 139차에 "게임의 모든 창은 `paintHudPanel` 문법"으로 정했는데
팝업 베이스만 그 밖에 있었다 — 팝업 전부가 이 베이스를 상속하므로 한 곳만 고치면 전부 따라온다.

**바닥 이름표**는 `loadChunkPois`가 `notable`(거래 가능하거나 POI 종류 라벨이 있으면)인 지점마다
점과 이름표를 그린 것이다. 속초 실측 **거래 가능 187곳 · 이름만 있는 곳 121곳** — 지형 타일을
글자가 덮는 게 당연한 양이었다.

### 3.1 멀티플레이 흐름 (사용자 지정 순서 그대로)

```
메인 메뉴 → 게임 시작 → [혼자 하기 | 여럿이 하기]
                              │
                              └→ 로비: 서버 주소 → 방 열기(코드 발급) 또는 코드로 참가
                                     │
                                     └→ 슬롯 3칸 → 슬롯 선택 → 캐릭터 만들기
                                            │
                                            └→ [이대로 생성하기]
                                                 중복 여부 확인중
                                                 → 중복 여부 통과 → 생성 중 로딩 → 접속중 → 필드
                                                 → (중복) 빨간 글씨:
                                                    "캐릭터 이름이 중복되어 생성할 수 없습니다! 이름을 변경하세요."
```

전송은 **REST + 1초 폴링**이다. 로비는 전부 묻고-답하기라 요청/응답이면 충분하고,
이름표를 띄우는 데는 1초 갱신이 모자라지 않는다. Socket.IO 경로(이미 있는 `PlayerSync`)로 올릴 때
이 계약(`types/Multiplayer.ts`)을 그대로 쓴다.

## 6. 잔여

- **다른 플레이어에게 충돌 바디가 없다** — 서로를 통과한다. 밀림·막힘은 서버 권위가 생긴 뒤에.
- **세션은 저장되지 않는다**(프로세스 메모리). 서버를 내리면 코드가 사라진다.
- **이어하기로 멀티에 들어가는 경로가 없다** — 멀티는 늘 새 캐릭터(사용자 지정 흐름). 기존 세이브를
  세션에 들여보내려면 그 시점에 이름 중복 검사를 다시 해야 한다.
- 텍스트 품질은 **프레임버퍼 1280x720이 상한**이다. 창이 그보다 크면 캔버스 전체가 CSS로 확대된다
  (31차 `image-rendering: auto`). 더 올리려면 내부 해상도를 키우는 별도 작업이 필요하다.
- 문구 다듬기는 **UI·표준 선택지까지**. 퀘스트 186편의 개별 나레이션은 손대지 않았다.

## 7. 위험·부작용

- **모든 팝업의 프레임이 바뀐다**(DraggablePanel 상속). 기능 회귀는 없지만 전 팝업의 외형이 달라진다.
- **Text 내부 래스터가 2배**가 되어 텍스트 텍스처 메모리가 약 4배다. 바닥 이름표를 기본으로 끈 것이
  같은 차수에 들어가 실사용 텍스트 수는 오히려 줄었다.
- `characterNameKey`는 **공백·대소문자만** 접는다. 비슷하게 생긴 글자(`ㅣ`/`l`)는 다른 이름으로 본다.
- 미니맵 마커 우선순위를 바꿨다 — 150px에서는 **의뢰·인물만**, 250px부터 물품 상점, 350px에서 전부.

## 8. 멀티플레이에서 걸리는 것들 (사용자 질문에 대한 답)

지금 구조는 **"같은 지도 위에 서로가 보이는" 단계**다. 아래는 그 위에서 어긋나는 지점이다.
밸런스는 제외하고, **구조상 어긋나는 것만** 적는다.

### 8-1. 세계가 사실은 공유되지 않는다 (가장 큰 것)

`GameState`는 각자의 브라우저에 사는 싱글턴이고 저장도 각자의 슬롯이다. 공유되는 것은
**지도·시간·서로의 위치와 이름**뿐이다. 그래서:

| 요소 | 지금 | 어긋나는 모습 |
|---|---|---|
| 퀘스트 진행 | 각자 로컬 | 같은 NPC가 A에게는 `!`, B에게는 `?`로 보인다 |
| 우호도 | 각자 로컬 | 같은 NPC와의 사이가 사람마다 다르다 |
| 인벤토리·재화 | 각자 로컬 | 물건을 건넬 방법이 없다 |
| 설치물(통발·텃밭·울타리·수조) | `SaveData.worldObjects` 로컬 | 내가 놓은 통발이 남에게 안 보인다 |
| 어획 | 각자 로컬 롤 | 같은 자리에서 서로 다른 고기를 낚는다 |
| 상점 재고·해금 | 로컬 플래그 | 상점 목록이 사람마다 다르다 |

### 8-2. 무작위가 각자 돌아가는 곳

- `FieldEventManager` — 보일링/스쿨링 발생·위치가 `Math.random`. **A 화면에만 갈매기가 뜬다.**
- `NuisanceField.spawn(seed = Date.now())` — 해파리·불가사리 배치가 클라이언트마다 다르다.
- `TrafficSystem` 차량, 홈타운 날씨(`rerollHometownWeather`) — 같은 자리에 다른 차가 서 있다.
- 반대로 **채집 스팟은 `forageSeed(mapKey, Date.now())` 결정적**이라 같은 자리에 같은 스팟이 뜬다.
  다만 **수확은 각자** 하므로 한 스팟을 두 사람이 동시에 걷어간다.

### 8-3. 시간 축

KST 실시간 기준(`KstTime`)이라 시계·조석·주야는 저절로 맞는다. 다만 **침대 수면**이 각자의
상태만 바꾸므로 한쪽만 자고 나올 수 있다. 하루 상한이 걸린 품삯(`DayJobs`)도 각자 센다.

### 8-4. 흐름(씬) 문제

- 1인칭 낚시·상점·손질은 `pause + launch`라 필드 씬 `update`가 멈춘다 →
  **그 사람은 마지막 서 있던 자리에 가만히 서 있는 것으로 보인다**(사라지지는 않는다).
- 지역 이동(출조)은 `regionId`가 바뀌므로 자동으로 서로의 시야에서 빠진다 — 의도대로 동작한다.
- 대화창·손질창은 전부 모달이라 남을 막지 않는다(각자 화면).

### 8-5. 이름·식별

- 유일성은 **세션 안에서만** 보장된다. 세션이 다르면 같은 이름이 있을 수 있다.
- 다른 사람의 외형은 서버가 보내지 않고 `characterOf('mp_' + playerId)`로 뽑는다 —
  모두의 화면에서 같은 얼굴로 보이지만 **본인이 만든 얼굴과는 다르다**. 외형 동기화는 후속.

### 8-6. 먼저 손대야 할 순서 (제안)

1. 설치물(통발·텃밭) 공유 — 세계에 물건이 놓이는 첫 공유 상태.
2. 무작위 이벤트의 **공용 시드**(보일링·과증식·차량) — `seed = f(mapKey, 시간블록)`으로 바꾸면 서버 없이도 맞는다.
3. 외형 동기화(`CharConfig` 전송) → 다른 사람이 만든 얼굴 그대로 보이기.
4. 채팅(지역 채널은 현재 목업) → 세션 브로드캐스트.
5. 그 다음이 어획·퀘스트 같은 **권위가 필요한 것들** — 서버 판정으로 옮겨야 한다.
