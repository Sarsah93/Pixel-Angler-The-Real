## 1. 배경 — 왜 했나

329(3)차 결과를 본 사용자가 piskel에서 남자 캐릭터의 눈을 직접 고친 그림을 붙여 보냈다. 원문:

- 「1) 눈을 6칸으로 표현하고 가운데 두 칸을 눈동자로 쓰고 있는데, 눈동자가 한 줄(2칸) 인 경우, 캡처 화면
  (내가 piskel에서 도트 찍어서 수정한 남자 캐릭터)처럼 눈동자가 두 줄(4칸, 코 쪽으로 4칸. 귀 쪽 방향의 두 칸은 흰자위)로도 할 수 있게 해줘.」
- 「4칸 적용 시에는 한 줄 눈동자와 같은 색으로 할 지 말지는 너가 선택해봐.
  (내 생각엔 유사 색조합으로 눈처럼 보이게 하려면 같은 색으로 두 줄 적용하면 안될 것 같음)」
- 「+캐릭터 만들기에서 눈동자 크기 '작게'와 '크게' 수정할 수 있도록 해주고. (정면만 건드리면 될 것 같아. 측면은 그대로 두면 될 듯?)」
- 「2) 캐릭터 만들기 화면에서 바뀐 캐릭터가 서있는 위치 발 부분이 이름없는 꾼과 겹쳐지고 있음. anchor 배치를 조금 더 위로 올려야 할 듯.」

첨부 그림의 남자 캐릭터 눈 = 윗줄 [흰 · 검 · 검] / 아랫줄 [흰 · 갈 · 갈](오른눈은 좌우 대칭).

## 2. 원인 — 무엇이 문제였나

**눈동자 크기** — 문제가 아니라 새 요구다. 329(3)의 눈은 [흰 · 검은자 · 흰] 한 가지였다.

**발 겹침** — 확정. `CharacterCreateScene.drawPreviewStage`가 미리보기 그림을 `420 + (32 - 1 - 28) × 10`에 놓았다.
28은 329(2) 전의 발바닥 행이다. 329(2)에 `CHAR_FOOT_Y`가 30이 됐는데 이 숫자는 화면 쪽에 따로 적혀 있어 따라오지 않았다.

| | 발바닥 y | 이름 줄 y |
|---|---|---|
| 329(2) 전(발 28행) | 420 | 438 ~ 456 |
| 329(2) 뒤(발 30행 · 숫자는 28 그대로) | **440** — 그림 아래 끝 450 | 438 ~ 456 — 겹침 |

329(2)에서 손 · 입 행은 core 상수로 옮겼는데(`CHAR_HAND_Y` · `CHAR_MOUTH_Y`) 이 화면의 발 행은 놓쳤다.

### 3.1 큰 눈동자의 색 — 고른 것과 버린 것

실제 캐릭터 위에 후보 아홉을 덮어 견주었다(눈 색 여섯 · 피부 넷 · 10배와 2배).

| 후보(왼눈 — 귀 쪽 → 코 쪽) | 판정 |
|---|---|
| [흰 · 검 · 검] / [흰 · 색 · 색] — 사용자 수정본과 같은 칠 | 검은 띠 아래 색 띠 — 눈보다 네모 덩어리로 읽힌다(사용자도 같은 색 두 열은 아닐 것 같다고 했다) |
| 아랫칸만 한쪽 밝게(흰색 섞기) | 갈색 눈에서 밝은 칸이 잿빛이 된다 |
| 아랫칸만 한쪽 밝게(채도 유지 · 1.7배) | 파란 · 초록 눈이 형광으로 뜨고 붉은 갈색은 살색과 헷갈린다 |
| 귀 쪽 열을 눈동자색 · 코 쪽 열을 검은자 | 검은 칸이 코 쪽으로 옮겨 가 모인 눈이 된다 |
| **[흰 · 검 · 짙은 눈동자색] / [흰 · 눈동자색 · 밝은 눈동자색]** | **채택** |

채택한 판의 둘째 열(코 쪽):

- 윗칸 `irisDeep` = 눈 색과 검정의 중간(`mix(eyeC, 검정, 0.5)`) — 갈색 눈에서는 거의 검정이라 사용자 수정본과 비슷하고, 색 있는 눈에서는 눈 색이 돈다.
- 아랫칸 `irisLit` = 눈 색 1.45배에 흰색 10%(`mix(brighten(eyeC, 1.45), 흰, 0.1)`) — 검은자 열 아랫칸보다 한 단 밝다.
- 검정 칸은 「작게」와 같은 자리(눈 가운데 열)에 남는다 — 크기를 바꿔도 시선은 그대로 앞을 본다(329(3) 규칙 유지).

### 3.2 미리보기 배율을 10 → 9로 내린 까닭

발을 바닥 줄(y 420)에 세우면 10배에서는 칸 윗끝이 y 110이 된다. 상투는 칸 맨 윗줄부터 그리므로 무대 홈(y 126 ~ 462)을 16px 넘고 패널 머리띠(~ 114)까지 4px 들어간다.
칸(32줄)이 꽉 찬 뒤로는 10배(320px) + 이름 줄(약 20px)이 홈 높이 336px에 들어가지 않는다.
9배면 칸 288px — 윗끝 y 141 · 발 420 · 그림 아래 끝 429 · 이름 줄 438. 화면 키는 252px로, 몸을 키우기 전(260px)과 비슷하다.

## 4. 구조상 위치 — 어느 계층의 무엇인가

- 눈동자 크기: `캐릭터 그림(core art) → 외형 계약(CharAppearance) → 얼굴 → 눈`. **계약 층**(선택 필드 하나)과 **렌더 층**.
  세이브에는 외형 객체가 통째로 실리므로 필드가 그대로 저장된다. 서버는 외형을 글자 수(2,000자)로만 거른다 — 그대로 지나간다(실측 424자).
- 서는 자리: `캐릭터 만들기 화면 → 미리보기 무대`. **렌더 층**(화면 배치).

## 6. 잔여

- 사용자 육안 — 큰 눈동자의 색 조합(둘째 열 명도 차이)이 마음에 드는지. 참고 줄(같은 색 두 열)로 바꾸려면 `irisDeep` · `irisLit` 두 줄만 고치면 된다.
- 이야기 인물 45명 · 마을 사람은 모두 「작게」다 — 인물마다 섞을지는 사용자 결정(해시로 고르면 기존 인물의 다른 특징은 그대로 둘 수 있다).
- 그림 얼굴 초상(268 ~ 271)과 절차 초상은 눈동자 크기를 반영하지 않는다(다른 그림).
- 329(2) · 329(3)에서 넘어온 것 그대로: 옆모습 서기의 다리 겹침 · 위로 걸을 때 고개 · 창 확대 단계 흐림(결정 대기).

## 7. 위험·부작용

- 캐시 키(`charCfgKey`)에 한 칸이 늘었다 — 텍스처 키가 모두 새로 만들어진다. 키는 실행 중 캐시일 뿐 저장되지 않는다(영향 없음).
- 미리보기가 10% 작아졌다(칸 한 변 320 → 288px). 배율은 정수(9)라 도트 굵기는 고르다.
- 옛 판 클라이언트로 접속한 사람에게는 내 큰 눈동자가 「작게」로 보인다(필드를 모른다 — 오류는 없다).
- 세이브 스키마: 선택 필드 하나 추가. 옛 세이브는 값이 없어 「작게」로 그려진다(지금 모습 그대로). 옮김 코드는 필요 없다.
