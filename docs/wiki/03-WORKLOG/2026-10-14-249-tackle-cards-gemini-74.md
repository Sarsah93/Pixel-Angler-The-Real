### 2.3 장비 그림 — 범위

- **카드 방식**: `public/item-icons/`의 사용자 장비 그림 41장(대 · 릴 · 찌 · 봉돌 · 루어 · 미끼 갑 등 1,254px 안팎) → 원본은 `food assets/tackle/`.
- **「대체 중」** = 248차 보고의 「코드로 그린 임시 그림」(`tools/item_art/` — 512px)을 쓰던 낚시 장비 59종 +
  다른 종류 그림을 빌려 쓰던 것 15종(원투대 · 쇼어지깅대 · 죽간 등이 스피닝대 그림 · 레버브레이크 · 원투 · 쇼어지깅 · 소형 릴이 스피닝릴 그림 ·
  합사 · 카본 목줄이 나일론 스풀 그림 · 섀드 웜이 그럽 웜 그림 · 잠길찌가 수중찌 그림).
- **「없는 것」**: 낚시 장비 중 그림이 아예 없는 것(이모지 · 16px 손그림만)은 0이었다.
- 장비 = 가방 「장비」 · 「낚시용품」 탭 + 낚시 도구 · 밑밥 · 해루질 도구 · 통발 · 장비 관리 소모품(릴 오일 · 케어 세트 · 낡은 릴 부품 · 로드 공구 · 방청 스프레이).
  요리 · 농사 · 약 · 음식 · 가구의 코드 그림 93장과 씨앗 · 농사 도구 16px 손그림은 **장비가 아니라 이번 범위 밖**이다(§6).

### 2.4 카드 방식 — 어종 · 갯것과 같은 생각, 장비에 맞춘 것

- 카드 = 상세 창이 그리는 칸 **228×90 안**(작물 카드와 같은 칸 — 장비는 크기 배율이 없다) · 아이콘 = 긴 변 64px(72px 이하 칸은 `fitFishTexture`).
- 줄이기 = 면적 평균 + **불투명도 보존**(칸 안 알파 최댓값 ≥ 128이면 그 9할) — 대 · 바늘 · 도래처럼 몇 px 굵기 선이 30px 칸에서 끊기지 않는다(비교 시트로 확인).
- **사용자 그림은 캔버스(여백)를 그대로** 줄인다 — 쿠션고무(채움 0.30) · 좁쌀봉돌(0.45)처럼 작은 부속을 작게 그려 둔 비율을 지킨다.
- 키: 사용자 그림 · 새 종류 그림은 `item_*` 등, 코드 그림을 바꾼 것은 **`art_*` 키를 그대로**(세이브 · 카탈로그 · `art_${trap}` 같은 동적 키를 고치지 않는다).
  `tools/item_art/build.py`가 `TackleTextures.ts` 표에 오른 키를 「바깥 그림」으로 보고 drawn PNG를 지우되 아이템 id · 접두사 · 16px 키 연결은 남긴다.
- 종류별 그림 키 = `rodArtKey`(core `rodSpecFor().use` 8갈래 + 죽간) · `reelArtKey`(베이트 · 레버 · 번수) · `lineArtKey`(목줄 · 합사 · 나일론).
  상점 · 시작 아이템 · 퀘스트 보상이 쓰고, **옛 세이브는 불러올 때 빌려 쓰던 키일 때만** 바꾼다(`refreshTackleArtKey` — 196차 카드 채비 선례).
  갯바위 찌낚시대는 사용자 스피닝대 그림, 선상 베이트대 · 베이트릴 · 범용 스피닝릴은 사용자 그림 그대로다. 시작 릴(다이오 2500L)은 레버브레이크 그림.

### 2.5 Gemini 74장

- `tools/gemini_tackle_art.cjs` — 생김새 설명(`LOOKS` 74줄) + 사용자 장비 그림 3장 화풍 참고(대 · 릴 · 루어 · 타이라바 · 줄 · 찌 · 포장 · 가방 · 금속 묶음).
  시범 4장(원투대 · 레버 릴 · 가이드 가방 · 게 통발) 뒤 70장 · **실패 0 · 다시 뽑기 0** · 약 2.5달러.
- 설치(`--install`): 흰 배경 벗기기(**떨어진 조각도 남긴다** — 장갑 한 켤레 · 경단 세 알) → 윤곽선에 갇힌 순백 배경 빼기(손잡이 고리 · 가이드 고리) →
  번짐 벗기기 → 타이트 크롭 → 격자 정규화(긴 변 192칸 · 셀 6px).
  그물 장비 5종(뜰채 · 게 통발 2 · 새우 통발 · 그물 통발)은 `mesh` — 그물코가 가늘어 둘레 기준을 넓히고 2px 그물코까지 뺀다(뜰채 흰 점 306곳 → 954곳 빼고 깨끗).

### 2.6 위키 — 파일 상한 정리(그 전까지 코드 그림 141장이 빠져 있었다)

- 아티팩트 한 판에는 파일이 511개까지다. 위키가 쓰는 그림은 512장이라 이미 넘쳤고, 실제로 `art_*` 141장이 한 번도 올라가지 않아 깨져 보이고 있었다.

  (HTML 1.7MB → 2.9MB · 상한 16MB). 템플릿 `img()`가 data URI를 그대로 쓴다.

## 6. 잔여 — 이번에 안 한 것

- **장비 밖의 코드 그림 93장**(요리 · 식기 · 농사 · 약 · 음식 · 가구 · 재료 · 도면)과 **16px 손그림만 있는 것**(씨앗 110 · 농사 도구 33 · 심부름 2) —
  사용자 지시가 「낚시 장비」라 범위 밖. 같은 도구(`LOOKS`에 줄만 더하면 된다)로 이어 할 수 있다 — 사용자 결정 대기.
- **부팅 텍스처 남은 큰 것**: 손질 부산물 그림 `trim_*` 31장(1,000px 넘음) · 코드 그림 93장(512px · 93.7MB) — 같은 카드 방식 후보(백로그 C).
- **하모니 원장 F-0088** — 수치는 정정됐지만 원장 항목은 `harmony-state`에서 닫아야 한다(일반 세션은 쓰지 않는다 — 사용자 또는 다음 심화 점검).
- **마우스 포인터** — 사용자 선택 대기.
- **gh-pages 배포 · main 반영** — 이번 지시에 없었다(요청하면 「테스트 배포」).

## 7. 위험·부작용

- 장비 원본을 `public/`에서 뺐다 — 옛 경로(`item-icons/it_*.png`)를 읽는 곳은 남아 있지 않다(BootScene · 위키 생성기 · 도구 3개를 고침).
- 대 그림이 core `rodSpecFor().use`에 매여 있다 — 새 낚싯대를 넣을 때 `use`가 맞으면 그림도 따라온다. 새 `RodUse`를 더하면 `ROD_ART_BY_USE`에 한 줄.
- Gemini 그림 몇 장(포대 · 모자 · 조끼)은 사용자 그림보다 매끈한 화풍이다 — 격자 정규화(셀 6px)로 도트 결은 맞췄다.
- `art_*` 키를 바꾸지 않았으므로 `tools/item_art/icons_*.py`에 그 그림 함수가 남아 있다(굽지는 않는다 — 표에서 빼면 다시 구워진다).
- 위키 HTML이 2.9MB가 됐다(작은 그림 219장 내장) — 그림 크기 상한 8KB(`INLINE_MAX`)로 조절한다.
