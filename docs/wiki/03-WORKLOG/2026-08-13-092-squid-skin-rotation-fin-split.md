## 1. 배경

91차의 껍질·날개 구간은 스테이지당 그림 1장 고정이라, 조작과 그림의 인과가 약했다:

1. **들추기**가 7점 곡선 긋기(lift_flap)였는데, 실제 동작은 "가장자리를 잡는" 순간 행동이다.
2. **뜯기 ①/②**는 시작부터 "뜯는 중" 그림이 떠 있어, 드래그해도 그림이 변하지 않았다.
3. **분리 완료**(4.2)는 왼쪽에 뜯긴 껍질 덩어리가 그대로 남아 "분리 완료"로 안 읽혔다.
4. **날개 2단**이 각각 1스테이지(2경로 자유)라 양쪽 날개를 뜯는 서사가 없었다.
5. **아가미 제거** 화면이 이미 아가미가 없는 완료 사진(6)이었다.

사용자가 F9 실측 좌표 3건(들추기 7점·뜯기 ① 스윕 7점·아가미 스윕 7점)과 함께
회전 뷰·진행 연출·2단 분할·합성 지시를 내렸다.

## 2. 판단 (좌표 해석 — 다음 실측 반영 시 참고)

- 들추기 실측 7점은 **F9 [복사] 출력 = 생선 로컬 좌표 그대로** 반영했다("회전뷰를 고려했을 때"는
  rotNorm이 처리한다는 뜻으로 해석). 회전 방향은 데이터 정합으로 확정:
  좌 90°(=`BoardRotation` **270**)에서 링이 화면 좌상에 오고, 뜯기 ① 잡기(0.234, 0.126)와
  **화면상 같은 부위**에서 이어진다("1단계에서 잡았던 부위로부터" 원문과 정합).
- 뜯기 ②의 "머리쪽(우측 끝)" 서술은 **우 90°(=90) 회전 시 4.1의 잔여 껍질(로컬 좌상)이
  화면 우상에 오는 것**과 정합 — 실렌더 스크린샷으로 확인(s16_04).
- 뜯기 ② 스윕은 90차 실측이 `squid_skin_pull` 프레임 기준이라 새 시작 프레임(4.1 회전)과
  어긋남 → **근사 재정의**(잔여 껍질 → 좌하 방향). F9 재실측 대상.

## 4. 구조상 위치

`S3 손질 → B2 두족류 → 무늬오징어 껍질·날개·아가미 구간`.

- A = 에셋 빌드 층(구운 스냅샷 — 재생성 필수).
- B = 데이터 층(트리·좌표·섹션) + **판정 층 1건**(advance 회전 스냅 — 두족류 한정).
- C = 렌더·입력 층. `renderedRotation`은 어류 회전 경로도 지나므로 회귀 검증 대상(§5).

## 7. 위험·부작용

- `renderedRotation`이 어류 렌더 경로에도 들어갔다 — 어류는 수동 회전이라 doRefresh 동기화로
  항상 `process.rotation`과 일치(광어 회귀 6/6으로 확인). 연출 중 표시가 어긋나는 건 두족류 자동
  스냅 구간뿐이며 그 동안 입력은 actionAnim 가드로 차단된다.
- 스테이지 수 14→16 — 스펙 §1.1 "사진 1:1" 예외 누적(제거 2 + 추가 2 + 분할 2). 전부 사용자
  공정 재정의가 근거임을 스테이지 파일 주석에 명기.
- 두족류 수동 회전(R) 차단은 어류 무영향(분기 최상단 cephalopod 가드).
- 파생 스프라이트는 결정적 재생산(해시 지터 — Math.random 없음). 구세이브 무영향(손질 진행은 세션 메모리).
