# 153차 — 대화 전용 70편 실목표 배선 + 아티팩트 장 접기 + '할 일' 용어 통일

- 날짜: 2026-09-18
- 시스템: S22 스토리·퀘스트 · S21 성장(제작) · UI 프레임워크(아티팩트)
- 상태: ✅ 완결 (빌드 3/3 · typecheck 0 · 아티팩트 pageerror 0)

---

## 1. 배경

사용자 지시 두 건.

**① 대화 전용 70편.** 152차가 난이도 표기를 붙이면서 드러낸 숫자다 —
186편 중 **70편(38%)이 「대화」 등급**, 즉 라벨이 무엇을 약속하든 실제로 요구되는 조작은
대화 [다음 단계] 한 번이었다. 152차는 그것을 **정직하게 표기하고 품삯을 0.25배로 낮췄을 뿐**
조업으로 바꾸지 않았다. 이번 지시가 그 빚이다 — 원문: *"대화 전용 임무 70편도 잘 바꿔줘."*

**② 아티팩트 좌측 색인.** 원문:

> 우측에 챕터1의 퀘스트 하나를 띄우는 중이라 하더라도, 왼쪽 패널에 챕터1 행을 접을 수 있도록 해줘야 해.
> … 내가 원하는 챕터를 눌러서 보기도 하고, 그렇지 않더라도 **평시에 챕터가 총 몇 개 있는 지를
> 눈으로 볼 수 있게** 하려는 거야. 이러한 부분이 유저 친화적 설계야.

사용자는 이어서 **"말한 대로만 딱 수정하고 더 추론하지 않을 것 같다"** 고 지적하며 4단계를 지정했다:
현상 → 구현 → 다시 폈을 때 선택 표시 → **이전 개발자 의도에서 놓친 부분 점검**
(예시로 *"'임무'라는 표현이 혼재되고 있음. '할 일' 같은 용어로 수정해야 함"*).

## 2. 원인 (확정)

### 2-1. 대화 전용 70편 — 설계가 그대로 드러난 것

`StoryStore.event()`가 `if (o.manual && ev.kind !== 'talk') return;` 이라
`manual` 목표는 **행위 이벤트를 전부 무시**하고 대화로만 닫힌다(134차 설계).
`questDifficulty()`는 manual을 점수에서 빼므로, 목표가 전부 manual인 퀘스트는 점수 0 = 「대화」다.

### 2-2. 색인이 접히지 않던 기전

`renderIndex()` 안에 있던 한 줄:

```js
if (!openCh.size && cur) openCh.add(cur.chapter);
```

마지막으로 열려 있던 장을 접으면 `openCh.size === 0`이 되고, **그 즉시 열람 중인 장이 다시 추가**된다.
그래서 보고 있는 퀘스트가 든 장은 **구조적으로 접힐 수 없었다**.

### 2-3. 실측으로 잡은 죽은 배선 2건 (지시에 없던 것)

- **제작(`craft`) 이벤트가 한 번도 발화하지 않았다.** `CraftingStore`가
  `GameState.grantXp(activityXp('craft', …))`를 **직접** 불러 `addActivityXp`를 비껴갔다.
  `addActivityXp`만이 `StoryStore.event({kind:'activity'})`와 **제작 숙련도**를 함께 올린다
  → 제작 목표는 영영 안 닫히고, **140차 제작 숙련도도 0에서 움직이지 않았다**(호출측 0건 실측).
- **면허 패널이 내부 id를 화면에 흘렸다**(§8-9 R1 위반). 요구사항 줄이
  `• 퀘스트 완료: ${req.questId}` · `• 특정 장소 방문: ${req.spotId}` ·
  `• 특정 어종 포획: ${req.fishId}` 로 **id를 그대로 출력**하고 있었다.

### 3-1. 70편에 무엇을 심었나 — 고른 기준

**추적기가 실제로 있는 종류만 쓴다.** 닫히지 않는 목표는 **진행 중 세이브를 막는다**(149차 규칙).
실측으로 확인한 발화 목록:

- ✅ `catch` · `release` · `butcher` · `sashimi` · `gather`(채집) · `craft`(3-1에서 되살림) ·
  `sell`(위판) · `trap` · `cull` · `license` · `reachLevel` · `earn` ·
  `custom`(`job:*` · `buy:*` · `bedSave` · `equip:bag`) · `visit`(`region:*` · `shop:any` · `poi:*`)
- ❌ `cook`(호출측 0 — 불요리 미구현) · `boatTrip` · `holdPosition` · `survive` ·
  `furnish` · `farm` · `mine` · `deliverFree` · `communityWork`(속초 `job:coop_work` 전용)
- ⚠ **`spotKind: 'boat'`는 어디서도 발화하지 않는다** — `standingSpotKind()`는 `breakwater|shore`만,
  1인칭은 `hole|shore`만 낸다. 그래서 **선상 조건을 단 목표는 하나도 만들지 않았다.**

추적 불가 종류의 `manual` 줄은 **지우지 않고 남겼다.** 그 줄이 이야기의 장면(승선·표결·가구 배치)을
가리키기 때문이고, 난이도는 어차피 manual을 세지 않는다. 바뀐 것은
**"대화만으로는 끝나지 않는다"** 는 사실 하나다.

대표 예:

| 퀘스트 | 구 목표(전부 대화) | 신설 자동 목표 |
|---|---|---|
| M2-04 남의 가게 | 횟집 납품 3회(`deliverFree`) | 통발 3회 + 손질 3마리 |
| M3-07 종묘방류 | 공동작업(속초 전용 — **포항에서 영원히 안 닫힘**) | **치어 방생 5회** (구 목표 폐기) |
| M6-05 병실 | 정옥선 방문 | **얼음 나르기 3회**(하루 2회 상한 → 이틀) |
| N22-3 돌을 고르다 | 채석(`mine`) | 갯가에서 봉돌 돌 줍기 3회(채집) |
| N23-6 남길 것 | 요리(`cook`) | 회 1접시(`sashimi`) |
| N12-1 다툰 날의 방파제 | 일몰까지 자리 지키기 | **채집 2회** — ⚖ *조과 0 완료*라는 이 퀘스트의 설계는 지켰다 |

### 3-2. 난이도 구간 재조정 (⚖)

70편이 점수를 갖게 되면서 분포가 통째로 올라갔다(구 0~10 → 신 **1~10**, 중앙값 3 → 5).
구 경계를 두면 「고난도」가 영영 비고 「보통」이 3분의 2를 먹는다.

| | 대화 | 수월 | 보통 | 까다로움 | 고난도 |
|---|---|---|---|---|---|
| 152차 | **70** | 33 | 79 | 4 | 0 |
| 153차 | **0** | 26 (14%) | 112 (60%) | 44 (24%) | 4 (2%) |

⚖ **「대화」 구간은 비어도 남긴다** — 표기는 계약이라, 앞으로 대화로 끝나는 임무가 생기면
그때도 정직하게 그렇게 적혀야 한다.

⚠ **품삯이 오른다.** 70편이 `DIFFICULTY_PAY_MULT` 0.25배 구간을 떠나 0.6~1.3배로 이동한다.
이것이 152차가 의도한 방향이다 — 이제 그 임무들은 실제로 손을 쓴다.

### 3-3. 아티팩트 색인

- **자동 재개방 삭제** — `openCh`는 부팅 때 한 번만 열람 중인 장으로 초기화한다.
  이동(`go`)은 그 장을 열지만(접기보다 우선), **접기는 예외 없이 접힌다.**
- **`모두 접기 / 모두 펼치기` + `7장 · 186편`** 을 색인 상단 고정 줄에 — 사용자가 말한
  *"평시에 챕터가 총 몇 개인지 눈으로 보는"* 상태가 기본으로 가능해졌다.
- **접어도 흔적은 남긴다** — 열람 중인 장은 좌측 금색 바(`.chtog.cur`) + **점(`.dot`)** +
  `title="열람 중 — 막차"`. 다시 펴면 그 행이 `aria-current`로 강조된다(요구 3번).
- ⚠ **`keepCurrentVisible()`의 `offsetTop` 계산이 틀렸다**(내가 쓴 코드) — 색인이 `sticky`이고
  행이 `section` 안에 있어 배치 조상이 어긋난다. 실측: 마지막 할 일로 이동하면 선택 행이
  **55px 밖**에 남았다(`selTop 884 > idxBot 878`). `getBoundingClientRect()` 기준으로 교체.

### 3-4. 용어 — 임무 → **할 일**

사용자가 든 예시 그대로 **'할 일'** 로 통일했다(인게임 + 아티팩트).
남긴 예외는 **152차에 사용자가 직접 이름 붙인 두 곳**뿐 —
문서 제호 `조행록 퀘스트 항로도`, 인포박스 머리 `퀘스트 정보 개요`.

적용: 일지 패널(제목·탭·토글·빈 화면) · 도움말 · 단축키 안내 · 피어 정보 ·
HUD 로그 `[퀘스트]` → **`[할 일]`** ×6 · 면허/스킬 요구사항 줄 ·
아티팩트 전문(리드·검색·색인·푸터·연관/선행·본문 서술).

⚠ **영문 규칙이 아예 없던 줄을 발견했다** — `[퀘스트] … 수락/완료/거절/미룸/달성/보상`
6종은 `en.ts`에 규칙이 없어 **영어 화면에 한국어로 남아 있었다**. 규칙 6건 신설 + 기존 1건 갱신.

## 6. 잔여

- **`cook` · `boatTrip` · `holdPosition` · `survive` · `furnish` · `farm` · `mine`** 은 여전히 추적기가 없다.
  해당 `manual` 줄은 이야기 표시로 남아 있다 — **각 시스템이 생기는 차수에 `auto`로 승격**한다
  (`cook`은 불요리, `farm`/`furnish`는 농장·집 단계).
- **`spotKind: 'boat'` 미발화** — 선상 낚시가 서면 `standingSpotKind()`에 편입하고,
  그때 M3-01·M4-02·M4-06·N08-1/3·N11-4에 선상 조건을 얹을 수 있다.
- 구 `QUEST_DATABASE`(레거시)는 면허 요구사항 참조용으로만 남아 있다.

## 7. 위험 · 부작용

- ⚠ **진행 중 세이브**: 70편의 목표가 늘었다. 이미 **완료한** 퀘스트는 `story.done`이라 영향 없고,
  **수락 상태**인 퀘스트는 새 목표가 미달로 잡혀 다시 조업해야 한다(설계 — 대화로 끝나던 것이 끝이다).
- ⚠ **품삯 상승**(3-2). 밸런스 의도는 맞지만 Ch2~Ch7 재화 곡선이 위로 이동한다.
- ⚠ **위판(`sell`) 목표 11편**은 법 §3에 따라 **통발·맨손 어획물만** 올릴 수 있다(낚싯대 어획 불가).
  전부 M1-11(계원·신고어업) 이후 구간이라 성립하지만, **통발 운용이 사실상 필수**가 된다.
- ⚠ **제작 숙련도가 이제 오른다.** 구세이브는 0에서 시작한다(140차 설계와 동일).
- 난이도 경계 변경은 **표기만** 바꾼다 — 목표·보상 데이터는 그대로다.
