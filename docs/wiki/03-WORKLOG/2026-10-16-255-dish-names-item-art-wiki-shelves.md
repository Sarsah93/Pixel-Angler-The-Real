## 2. 판단 — 무엇을 보고 어떻게 정했나

### 2.1 요리 그림 7장 — 매운탕 두 장과 같은 규격

- 매운탕 두 장 실측(`check_art_quality.cjs`): 셀 3px · 가로 168~188칸 · 505×407 · 565×425 · 투명 바탕(냄비 손잡이 고리 안도 투명).
- 새 일곱 장도 같은 셀 3px · 긴 변 192칸(582×393~432)으로 굽는다 — 한 상에 놓였을 때 도트 크기가 같다.
- 화풍 참고 = 통생선 매운탕 · 서더리 매운탕 · 모둠회 사진 3장. 국물 요리(지리 · 조개탕 · 전복죽)는 매운탕과 같은 **검은 양수 냄비**에 담았다.
- 원본은 `food assets/dishes/`(셀 6px · 192칸 정규화 — 생성본 그대로면 장당 1~1.6MB, 정규화 뒤 7장 508KB).
- 가방 · 상점 칸(≤ 72px)은 570px 사진을 GPU로 줄이던 것을 64px 판(`public/food/icon/` 10장 · 텍스처 `food_<이름>__icon`)으로 바꿨다.

### 2.2 요리 이름 규칙 — 매운탕은 「반쯤」 되어 있었다

- 156차에 매운탕 두 종류는 어종으로 갈라졌지만, 이름이 **도감 정식 이름 그대로** 붙어 「조피볼락(우럭) 서더리 매운탕」 · 「광어(넙치) 매운탕」으로 나왔다.
  상에 오를 때 부르는 이름(`DISH_SPECIES_NAME`)을 쓰게 고쳐 「우럭 서더리 매운탕」 · 「광어 매운탕」이 됐다(「감성돔 매운탕」은 원래 맞았다).
- 지리 · 생선구이 · 생선조림 · 오징어볶음 · 조개탕을 매운탕과 같은 방식으로 가른다. **장어구이도 가른다**(붕장어 · 갯장어 · 먹장어 — 주재료가 실제로 다르다).
  **전복죽만 「전복죽 (별 N개)」로 고정**이다(주재료가 전복 하나).

| 레시피 | 이름 틀(한 / 영) | 예 | 후보 |
|---|---|---|---|
| 지리 (맑은탕) | `OO 지리 (맑은탕)` / `OO Jiri (clear soup)` | 우럭 지리 (맑은탕) · 대구 지리 (맑은탕) | 어류 49 |
| 생선구이 | `OO구이` / `Grilled OO` | 고등어구이 · 참돔구이 | 어류 49 |
| 생선조림 | `OO조림` / `Braised OO` | 갈치조림 · 우럭조림 | 어류 49 |
| 오징어볶음 | `OO볶음` / `Stir-fried OO` | 한치볶음 · 갑오징어볶음 · 무늬오징어볶음 | 두족류 3 |
| 조개탕 | `OO탕` / `OO Soup` | 바지락탕 · 홍합탕 · **굴국**(통째 이름 예외 한 줄) | 채집 조개 3 |
| 장어구이 | `OO구이` / `Grilled OO` | 붕장어구이 · 갯장어구이 · 먹장어구이 | 장어류 3 |
| 서더리 매운탕 · 매운탕 | `OO 서더리 매운탕` · `OO 매운탕` | 우럭 서더리 매운탕 · 감성돔 매운탕 | 어류 49씩 |

- 수식어는 **하나만** 앞에 붙는다(탄 > 일품 > 싱싱한 > 기름진 — 156차 규칙 그대로). 예: 「일품 고등어구이」 · 「일품 바지락탕」.
- 상에 오르는 이름: 조피볼락 → 우럭 · 태평양 대구 → 대구 · 고등어 → Mackerel. 나머지는 도감 이름에서 괄호 별칭만 뗀다(`광어(넙치)` → `광어`).
  상세 창의 「주재료」 줄은 도감 정식 이름 그대로다.
- 요리 도감 후보는 변형 254(매운탕 2 × 49 + 지리 · 구이 · 조림 각 49 + 볶음 · 조개탕 · 장어구이 각 3) + 전복죽.
  도감 화면은 「외 N종」으로 자르던 목록을 쪽 넘김(「◀ 1 / 4 ▶」)으로 바꿨다.
- 밤에 낚은 참돔(`night_seabream`)도 요리에서는 참돔 하나로 센다(`cookingSpeciesId`) — 낮 참돔으로 만든 요리가 도감에 안 세지던 버그도 같이 고쳤다.

### 2.3 요리 효과 — 주재료 특성이 크기 · 지속을 움직인다

- 재료 점수 s(0~1) = 레시피마다 정한 재료 특성의 가중 평균. 크기 = 기본값 × (1 + 크기 폭 × (s − 0.5)) · 지속 = 기본값 × (1 + 지속 폭 × (s − 0.5)).
  두 배율은 0.5~1.5배로 묶었다. 계수는 `TUNING.cook.variantEffect`(F8 슬라이더 6개 · mockup 값).
- 레시피별로 보는 특성 · 비교(신선도 0.92 · 600g 기준):

| 레시피(효과 · 기본값) | 보는 특성 | 비교 |
|---|---|---|
| 지리 「맑은 속」 8% · 30분 | 비린 향 적음 .45 · 신선도 .35 · 국물 .2 | 우럭 10% · 38분 / 고등어 8% · 31분 |
| 생선구이 「고소한 한 끼」 8% · 30분 | 지방 .6 · 촉촉함 .4 | 고등어 9% · 35분 / 광어 7% · 28분 |
| 생선조림 「든든함」 10% · 40분 | 살 식감 .7 · 풍미 .3 | 우럭 11% · 47분 / 갈치 10% · 37분 |
| 오징어볶음 「활력」 8% · 25분 | 식감 .6 · 단맛 .4 | 갑오징어 10% · 30분 / 한치 8% · 26분 |
| 조개탕 「개운함」 10% · 30분 | 국물 .7 · 신선도 .3 | 홍합 14% · 41분 / 굴 12% · 36분 |
| 장어구이 「원기회복」 12% · 60분 | 지방 .7 · 풍미 .3 | 붕장어 14% · 70분 / 먹장어 13% · 66분 |
| 매운탕 두 종(156차 그대로) | 지방감 → 지속만(0.8~1.2배) | 감성돔 9% · 34분 / 광어 9% · 29분 |

- 1인분 요리는 무게 기준을 따로 둔다(구이 · 볶음 450g · 장어 500g · 조개탕 550g · 조림 650g) — 공통 800g이면 회복량 · 판매가가 지금보다 떨어진다.
- 조리 프로필 3종 → **58종**(어류 46 · 장어류 3 · 두족류 3 · 채집 조개 3 새로). 도감 후보 전부에 프로필이 있는지 시험이 본다.
- **실제로 듣는 것**: 허기 · 수분 회복(개체 값) · 포만감 계열(매운탕 둘 · 생선조림 — 생선조림은 이번에 처음 실제로 듣는다).
  지리 · 조개탕 · 장어구이의 기존 보양 효과(별 3개 이상)는 그대로 지켰다(변형으로 바뀌며 사라지지 않게 `CookingStore.dishTemplate`).
- **표시만 되는 것**: 맑은 속 · 고소한 한 끼 · 개운함 · 원기회복 · 활력 — 주재료별 수치는 상세에 나오지만 적용할 효과 장치가 아직 없다
  (스펙 §0.5 — Stage 9). 이번에 새 효과 장치는 만들지 않았다.
- 조개탕 상세는 「지방감」 대신 「국물」 줄(`brothLabel` — 옅음 · 보통 · 진함)을 보인다(조개를 지방감으로 말하지 않는다).

### 2.7 게임 쪽 그림 고르기 · 부팅 로드

- 그림 고르기(`ui/ItemIcon.ts` `createItemIcon` · 상세 창 같은 순서): 작물 초상(`px:crop_*` 또는 채소 별칭) → `itemImageKeyOf`
  (아이템 id → 16px 키 → 같은 음식 별칭 · 텍스처가 있을 때만) → 코드 그림 → `iconTexture` → 16px 손그림.
- 옛 코드 그림 키는 키를 그대로 두고 그림만 바뀐다 — `tools/item_art/build.py`가 새 그림 표에 오른 키를 「바깥 그림」으로 보고 drawn PNG를 지운다(86장 삭제).
- 카드 방식(249 장비와 같다): 원본은 `food assets/items/`(셀 6px · 192칸) · 게임은 카드(228×90 안) + 64px 아이콘만 싣는다(`item_cards.cjs`).
- 부팅 텍스처(아이템 그림): 코드 그림 93장 97.5MB → 남은 코드 그림 7장 7.3MB + 카드 6.9MB + 아이콘 2.8MB = **17.1MB**. 요리 사진 7장 +6.6MB.
- 배포 용량: 카드 · 아이콘 4.0MB 늘고 drawn PNG 0.6MB 줄었다(코드 그림은 단색이라 PNG가 작았다).

## 4. 구조상 위치 — 어느 계층의 무엇인가

- `S4 요리 → 요리 개체화 2단계(스펙 Stage 7 「나머지 레시피」) → 이름 · 효과 · 도감 후보` — **데이터 + 판정** 층.
  이미 만든 요리 개체는 값이 굳어 있어 바뀌지 않는다(156차 함정 8 · 9 그대로).
- `S25 실사 도트 → 장비 밖 아이템 그림` — **에셋 + 렌더 배선** 층. 키를 그대로 둔 교체라 아이템 정의 · 세이브 계약은 안 건드렸다.
  새 키(`item_*`)는 아이템 id · 16px 키로 잇는다(`ItemImages.ts`).
- `S20 위키 → 아이템 선반 탭 · 레시피 이름 규칙 절` — **생성기 + 템플릿** 층(게임 코드 밖).
- `S5 인벤토리 → 옛 세이브 요리 그림 키 보정` — **세이브 이전** 층(불러올 때 한 번 · 유저 상태는 안 건드림).

## 7. 위험·부작용

- **이름이 바뀐 매운탕** — 「조피볼락(우럭) 서더리 매운탕」으로 만든 옛 요리는 개체에 이름이 굳어 그대로다(영어 규칙은 더했다). 새로 만들면 「우럭 …」.
  도감 기록 id(`discovery_<레시피>_<어종>`)는 바뀌지 않았다.
- **생선조림 효과가 이제 실제로 듣는다** — 포만감 계열이라 허기 · 수분 · 피로 소모를 늦춘다(갈치조림 37분 −10%). 생존 밸런스에 아주 조금 유리해졌다.
- **세이브 이전** — `refreshDishPhoto`는 `iconTexture`가 `px:it_dish_`로 시작하고 `dish`가 있을 때만 바꾼다(유저 상태는 그대로).
- **부팅 로드** — 카드 223 + 아이콘 223 + 요리 17장을 더 싣는다(파일 수 ↑ · 텍스처는 97.5MB → 23.8MB로 ↓).
- **위키 선반 규칙** — 새 아이템이 규칙에 안 맞으면 「그 밖의 물건」으로 가고 생성기가 경고한다(조용히 사라지지 않는다).
