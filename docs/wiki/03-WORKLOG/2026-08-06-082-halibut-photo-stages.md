## 1. 배경
광어 포 뜨기 렌더가 파라메트릭 근사였다. 사용자가 실사 5장(`food assets/butchery/reference/halibut_ref_1~5`)의
투명본을 제공. **사용자 해부 설명**이 결정적이었다 — 5장은 서로 다른 장면이 아니라 **한 장의 필렛을 뜨는 연속 공정**이다:

> ref_5 지느러미↔껍질 경계에 오로시 길 → ref_4 길 따라 1회(지느러미 끝만 살짝 들림)
> → ref_2 뼈를 타고 한 번 더(살코기면 벌어짐) → ref_1 한 장 떠냄 / ref_3 = 같은 동작의 **내장 쪽 필렛**

## 2. 원인 *(해당 없음 — 신규 배선. 단 두 건의 잘못된 전제를 교정)*
| 잘못된 전제 | 실제 | 확정 근거 |
|---|---|---|
| 사진마다 배/등이 특정된다 | **구별 불가** — 들린 필렛이 껍질면을 가린다 | 사용자 확인 |
| 내장은 항상 위쪽(74차) | **면마다 반대** — 배면 위=위쪽 / 등면 위=아래쪽 | 사용자 확인. 장축으로 뒤집으면 위/아래 가장자리가 바뀐다 |

두 번째는 **기존 배면 배선(`gutsExposed = FLIP && up_lift`)이 맞았고, 등면 쪽만 누락**이었음을 확인.

**선택 규칙** (면 무관, 진행도 기반):
```
gutsExposed              → gut_lift        (내장 노출 · 긁기 전)
진행 중인 면 == 내장 쪽  → gut_lift
진행 중 p < 0.5          → lift_a          (1스트로크)
진행 중 p ≥ 0.5          → lift_b          (후반)
한쪽 완료·반대쪽 미완    → lift_done
칼길만(lift 0)           → fin_score
보간 연출 중             → (실사 없음 — 파라메트릭 플랩)
```
`strokesRequired: 3` → `flatLiftProgress`가 0 / 0.33 / 0.67 / 1 로 떨어져 사진 4장 눈금과 일치.

## 6-b. 후속 (같은 날) — 에셋을 더 받지 않고 **합성**으로 해결

사용자 지적: *"제공된 사진을 최대한 활용하되, 잘려서 안 보이는 부분도 전체 해부학적 구조를 이해했다면 활용 가능한 영역이 많은데, 그 부분만 다시 달라는 건 이해하지 못했다는 것"*. 타당하다. 세 건 모두 재요청 없이 해결:

| 최초 판단 | 실제 | 조치 |
|---|---|---|
| `lift_b`에 **나무 도마** 혼입 | **오판** — 갈색은 젖혀진 필렛 아래로 보이는 **등면 껍질** | 그대로 사용 |
| `fin_score` 대각 기울기 | 사용자가 세로 정렬본(`ref5_transparent`) 제공 — **칼까지 그려 칼길을 지정** | 재굽기 |
| `lift_a` 재촬영 필요 | **불필요** — `fin_score`(온전한 배면 전체 뷰)에서 파생 가능 | 합성 |

- **`ERASE_POLY`**(파이프라인 신설) — 사진 속 칼은 게임이 별도 연출로 그리므로 굽기 전에 제거.
  눈대중 대신 **행별 실루엣 실측**으로 경계를 잡았다: `y≥0.62`부터 생선(`~0.526`)과 칼(`0.541~`)이 **별도 런으로 분리**된다.
  bbox 검증: 193×128 = 생선만(칼 포함이면 221×128) — 이론값 197×128과 정합.
- **`deriveLiftA`**(파생 생성) — `fin_score`에서 지느러미↔살 경계를 열별로 검출해, 칼이 들어가 드러난
  **붉은 단면 띠**를 꼬리쪽으로 갈수록 두껍게(제곱 램프, 최대 6셀) 합성. `_up`/`_dn` 두 변형.
  74차의 "등면 스프라이트 → 배면 파생"과 같은 패턴 — **사진 1장 = 상태 1개가 아니다**.
  ⚠ 팔레트 최근접 재사용은 흰 뱃살에 묻혀 보이지 않았다(실측) → 전용 색 2개를 팔레트에 추가.

최종 6키: `fin_score`(193×128) · `lift_a_up`/`lift_a_dn`(193×128, 파생) · `lift_b`(128×81) · `lift_done`(191×128) · `gut_lift`(128×93).

## 7. 위험·부작용
- **구 키 3개 삭제** — 다른 곳에서 참조하면 폴백(파라메트릭)으로 조용히 떨어진다. 현재 참조는 `drawFlatFish` 한 곳뿐이라 안전(빌드로 확인).
- 실사가 **진행 중 상태**를 덮으므로, `opening` 플래그가 빠지면 80차 벌어짐 연출이 죽는다. 두 값이 한 쌍으로 움직여야 한다.
- 사진 스케일이 서로 달라(128×81 ~ 191×128) 도마 위 크기가 단계마다 튈 수 있다 — 실렌더에서 확인 필요.
- 파이프라인 회전은 **굽는 시점** 변환이다. 렌더 코드에서 또 돌리면 이중 회전(세로로 눕는다).
