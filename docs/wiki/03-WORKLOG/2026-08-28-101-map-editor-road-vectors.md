## 1. 배경 — 왜 했나

사용자 원문 요지:

1. "지도 자체를 dev 모드에서 즉각 수정할 수 있도록 타일 편집기 및 마인크래프트의 크리에이티브
   모드처럼 … 아이템을 마스터모드에서 바로 최대 수량 … 단축키+클릭 조합으로 순간이동" —
   "맵 전체에서 부분적으로 수정하기 힘들기 때문에, 수동검증을 통해 찾으려는 것".
2. "중앙선은 노란색 실선이고, 차선 변경이 가능한 선은 점선 흰색 … 도로가 대각선으로 표현될 때,
   타일이 대각선 형이 없어" (100차 타일 휴리스틱 점선은 가로/세로만).
3. "건물, 나무, 지형 등 좀 더 디테일한 다각적 요소들을 반영한 타일을 추가 … 편집 모드로 볼 수 있게".

## 2. 원인 — 대각선이 없던 이유

100차 마킹은 **타일 단위 휴리스틱**(`roadAxis` — 이웃 스팬으로 남북/동서 판정)이라 격자 축
2방향밖에 표현할 수 없었다. 도로는 OSM 벡터에서 래스터라이즈되므로 **벡터 자체가 정답**을 갖고
있다 → 래스터라이저가 차도 중심선 폴리라인을 `roads.json`으로 함께 내보내고, 클라이언트가
벡터를 임의 각도 선분으로 그린다(타일은 계단식이어도 마킹은 매끈).

- 교차부 마킹은 세그먼트 인셋으로만 완화 — 실제 교차로 박스(정지선·횡단보도)는 후속.

## 7. 위험·부작용

- `patch.json`은 **재빌드 시 build_region_maps가 굽는다** — terrain.png를 손수정해도 패치가 우선 덮는다.
- `invalidateTiles`는 전맵 BFS·라벨을 재계산(76만 타일 ≈ 수십 ms) — dev 전용이라 허용.
- vite 미들웨어는 dev 서버에만 존재 — 프로덕션에서 편집기 저장 호출 경로 자체가 없다(F7도 DEV 가드).

## 후속 5 — 도로 = 벡터 밴드 렌더 + 교차로 박스 + 교통 규칙 (사용자 리포트 6건)

**핵심 결정(5.3)**: "타일별 곡률 타일 생성기" 제안을 **실시간 벡터 밴드**로 채택 — 청크 베이킹 때 `r`/`w`
타일도 맨땅 베이스로 깔고, 그 위에 폴리라인을 굵은 선(보도 폭+2 → 연석 폭+0.14 → 아스팔트 폭)으로 그린다.
정점마다 원을 찍어 라운드 조인. 곡률·각도·진입 변 조합의 타일 아틀라스가 불필요하고 교차부는 밴드가
겹쳐 자연히 합쳐진다. 설명 페이지: 아티팩트 "Road Band Renderer".

1. **거꾸로 달리는 차** — 스프라이트 방향(전조등 위)·우측 법선·회전식은 실측 정상. 원인은 막다른 끝 **U턴 보간**
   0.9초 동안 뒤로 미끄러지던 것 → U턴 폐기, 끝에서 **0.6초 페이드아웃 후 다른 도로에 재등장**.
2. **차간 규칙** — 전방 원뿔(2.6타일·cos 0.75, 마주 오는 차 제외) 안 차량 있으면 정지 · 교차 정점 1.5타일 전에
   정점 반경 2.2타일 안에 먼저 든 차가 있으면 **양보 대기**(선진입 우선 — 회전교차로 진입 규칙의 단순화).
3. **중앙선 끊김·U턴** — 주행 가능 폭 3→**2타일**(주택가 2.8타일 도로가 막다른 길을 만들었다) + 중앙선도
   w ≥ 2에 그림.
4. **차선 관통** — `markingPieces`: 교차 정점(다른 도로가 지나는 정점)에서 조각으로 나누고 "다른 도로 반폭 +
   0.4"만큼 물러남 → 교차로 박스 안은 비고 마킹이 서로 관통하지 않는다.
5.1 **타일 위쪽 흰 선** — Kenney 행 22 셀의 13행 모르타르 줄(밝기 228) → 행별 밝기 프로파일이 4행 주기로
   완전히 반복되는 셀만(`GROUND_CELLS` tan/pave/pier 축소).
5.2 **깨진 소형 건물** — 높이 ≤ 2줄 또는 ≤ 3타일 컴포넌트는 벽·문 없이 지붕만(창고/헛간).
6. **NPC** — POI NPC 깊이 = max(자기 y, 소속 건물 하단 y)로 지붕 RT 뒤에 숨지 않음. 차도 위 NPC는 문 탐색
   도로 회피(후속 4)로 해소.

**검증**: 교차로(5도로 정점) 박스 비움·곡선 도로 밴드·소형 건물 지붕만 — 실렌더 3지점 · 교통 80틱: 후진 이동

## 후속 6 — 도로 벡터 편집 툴 · 횡단보도 벡터 · 아스팔트 톤 · 보행자 밴드 판정 (사용자 지시 4건)

## 후속 7 — 회전교차로·왕복 4차로 규범 + 차량↔캐릭터 (사용자 그림 3장 학습)

**그림 학습**: ① 수복탑 사거리 위성 = OSM `junction=roundabout` 링(반시계) + 5개 진입로 ② 회전교차로 규범도 =
중앙 교통섬(잔디+테) · 원형 차로 2차선 · 진입부 분리섬·양보선 · 링 위 차량 우선 ③ 사거리 = 팔마다 횡단보도 +
그 앞 정지선(진입 차로만) — 대각선 횡단보도는 신호 교차로 전용이라 보류.

- **파이프라인**: `build_osm_tilemap.py`가 `junction=roundabout|circular` → `roundabout+oneway`, `oneway=yes/-1`
  → `oneway`(−1은 pts 반전) 플래그를 roads.json에. 속초 = 회전교차로 3(수복탑 등)·일방통행 160. core `RegionRoad`
  타입 확장. ⚠ 재빌드는 terrain.png를 OSM에서 다시 굽는다 — 사용자 타일 편집은 patch.json이라 보존.
- **렌더**: 링 중심·평균 반경으로 **중앙 교통섬**(연석 → 흙 테 → 잔디) · 일방통행/링 = 중앙선 없이 전 폭 차로
  점선 · **왕복 4차로(lanes ≥ 2) = 이중 황색 실선**(±0.09타일) · 링 진입부 = **양보선(흰 점선) + 1타일 뒤로
  물린 횡단보도**, 반경+2.5 안 복합부는 양보선만 · 짧은 조각(<2.5)·짧은 도로(<5)엔 횡단보도 생략 ·
  **횡단보도 겹침 = 줄무늬 단위 생략**(앞서 그린 횡단보도 사각형 안에 드는 줄무늬만 건너뜀 — 사용자 규칙).
- **교통**: 일방통행/링은 pts 순방향만(끝점 역진입 금지) · 링 위 차량 우선 — 진입 차량은 링 차량이 노드 3타일
  안이면 대기(양보선) · 링 차량은 교차 양보 안 함 · 닫힌 링은 순환.
- **차량↔캐릭터**: 전방 1.6타일 원뿔 또는 1타일 안이면 **정지해 지나갈 때까지 대기** · 0.75타일 안 = 부딪힘 →
  씬이 **진행 방향 뒤로 넉백**(속도 0이면 차량 진행 반대) + `stamina −20`(HP −20%) + 카메라 흔들림, 차량은
  **180초 정지**(다른 차는 앞차 규칙으로 뒤에 선다). 1.5초 재충돌 무적.

**검증**: 회전교차로 링 프레임 69·역방향 0 · 차 앞 1.3타일에 서면 1.2초 이동 0 · 부딪힘 stamina 100→80·halt 180 ·
