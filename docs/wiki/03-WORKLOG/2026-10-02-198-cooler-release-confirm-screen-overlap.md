## 1. 배경 — 왜 했나

사용자 원문:

> "쿨러에서 놓아줄 때, 재확인 필요할 것 같아. 쿨러 슬롯들 중, 어종을 선택하고 놓아주기 직접 선택해서 빈공간을 만들고,
> 그 자리에 넣을 수 있도록 구현하는 게 중요하고, 그 다음으로 유저가 실수로 어획물을 잘못 선택한 채로 방생해버릴 수 있기 때문에,
> 하나 혹은 다수의 어획물 지정 및 방생하기 클릭 시, 재확인 문구와 버튼을 구현할 필요가 있어보임."

> "미니맵 우측 아래 보여질 '가구배치' 버튼이 왜 겹쳐지는 위치에 유저가 상호작용 해야하도록 설계되었지? (…)
> 잘 확인해보고 문제가 있으면 수정하고, 전수조사해서 비슷한 케이스는 없는 지 확인하고 수정할 것. (규칙 추가하기)"

## 2. 원인 — 무엇이 문제였나

**쿨러 정리 창(196차)**

- 카드를 누르면 곧바로 「놓아줌」 표시가 되고, [정리하고 넣기] 한 번에 놓아주기와 넣기가 함께 일어났다. 놓아주기 전에 묻는 단계가 없었다.
- 새 고기를 넣을 자리를 고를 수 없었다(`CoolerStore.add`가 첫 빈 칸에 넣는다).
- [들어가는 만큼만 넣기]는 남는 고기를 묻지 않고 놓아줬다. 결정 패널의 [방생하기]도 바로 놓아줬다.

**화면 겹침 — 확정 기전(실측)**

| 대상 | 원인 | 실측 |
|---|---|---|
| 집 [가구 배치] | `x = GAME_WIDTH - 16 - w`(화면 끝 상수) | (1114,110)~(1264,144) — 미니맵 판 아래쪽·「M 전체 지도」를 덮음 |
| 배치 모드 트레이 | `GAME_WIDTH - TRAY_W - 16`, 높이 = 방 높이 + 40 | 300×520 — 미니맵 아래쪽 + 「지금 할 일」 전체를 덮음 |
| 집 방 액자 | 화면 가운데 정렬 | 액자 왼쪽 328 < 상태 창 오른쪽 336 → 8×106px 겹침 |
| 집 안 알림(flash) | 방 밑변 + 26 | 퀵슬롯 띠 윗변을 덮음 |
| 월드맵 개발 도구 단추(개발 빌드) | 고정 y = `GAME_HEIGHT − 170` | 범례 제목·판 윗변을 덮음. 그리는 함수가 둘이라 한쪽만 고치면 배경만 남았다 |

- 집 안은 필드 위에 `pause+launch`된 씬이라 **필드 HUD가 그대로 그려진다**. 그런데 집 쪽은 HUD 위치를 모르고 상수로 놓았다.
- HUD 창은 끌어 옮기고 크기를 바꿀 수 있어 상수로는 빈자리를 알 수 없다.

## 4. 구조상 위치 — 어느 계층의 무엇인가

- `낚시 → 보관(쿨러) → 정리 창` — 판정·렌더 층(쿨러 스토어에 칸 지정 넣기 추가 · 세이브 계약 변경 없음).
- `UI 프레임워크 → 화면 배치` — 렌더 층. HUD가 자기 점유 영역을 알리는 **계약**(`occupiedRects`/`screenReserved`)이 새로 생겼다.

## 6. 잔여 — 이번에 안 한 것

- 1인칭 화면 위·아래 조작 안내 띠(「우클릭 챔질 · …」)는 R11 대상일 수 있으나 이번 지시(겹침·재확인) 범위 밖이다 — 백로그로 남긴다.
- Graphics만으로 된 판은 감사가 경계를 모른다 — 새 판은 컨테이너나 경계 사각형을 같이 둔다(감사가 볼 수 있게).
- 쿨러 패널(B · 3x3)의 다중 선택 방생은 하지 않았다(한 마리씩 확인 창은 원래 있다).

## 7. 위험·부작용

- 방이 12px 오른쪽으로 갔다 — 방 좌표(`OX`)에서 파생하는 가구·가이드·도움말 촬영 좌표는 함께 움직인다. 도움말 「집」 그림은 재촬영 전까지 12px 차이.
- 「지금 할 일」 창을 사용자가 끌어 방 위로 옮기면 겹친다 — 사용자가 고른 배치라 막지 않는다.
- 정리 창에서 놓아준 고기는 [돌아가기]해도 돌아오지 않는다(확인 창이 그렇게 말한다).
