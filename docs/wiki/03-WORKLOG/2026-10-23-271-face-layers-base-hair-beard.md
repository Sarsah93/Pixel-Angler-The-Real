## 1. 배경 — 왜 했나

270(2)를 마친 확대 캡처에 사용자가 동그라미 둘을 쳤다 — 흰 머리 · 밝은 피부의 귀 옆(구레나룻)과 잿빛 수염 아래 턱:

> 「눈썹 주변에 흰색 부분, 수염 아래 턱부분에 흰색 부분 이 보이네. 머리색을 따라갈꺼면 따라가게하고, 수염색을 따라갈꺼면 수염을 따라가야해.
> 잘보니까 그 영역 구분을 잘 못하고 있다는 생각이 들어(부자연스러워).
> 기본 얼굴형에 머리/수염/입을 변경하는 것으로 적용해야 지, 하나하나 케이스별로 다 뽑는 건 의미가 없지않을까?(계속해서 지금처럼 부분적으로 맞지 않는 것들이 생길거야)」

분류 지도로 본 두 곳은 원인이 달랐다(§2). 둘 다 「한 장에 납작하게 그린 판을 색 규칙으로 가르는」 방식의 한계라 규칙이 아니라 구조를 바꿨다 —
시범 2장(약 120원)으로 가능성을 재고 전량으로 갔다.

## 2. 원인 — 무엇이 문제였나

| # | 자리 | 기전(확정 근거) |
|---|---|---|
| ① | 흰 머리 · 밝은 피부 귀 옆 | 분류는 맞았다(원판의 갈색 구레나룻 · 귀 뒤 머리). 흰 머리(L≈230)와 밝은 피부(L≈216)는 밝기가 같아져 경계가 사라진다 — 원판은 색 대비로만 경계를 그렸고 윤곽선이 없다(픽셀 123개가 L<170 → ≥200) |
| ② | 잿빛 수염 아래 턱 | 수염이 피부로 옅어지는 가장자리의 전이 픽셀(원래 L 132~169 · 100개)이 수염으로 분류돼 잿빛 목표색의 「밝은 단계」로 올라가 흰 점이 됐다 — 원판에서 수염도 피부도 아닌 픽셀이라 주인이 없다 |

결론: 경계마다 추측이고 색 조합이 바뀌면 다른 경계에서 또 난다. 픽셀의 주인이 **그림(데이터)에** 박혀 있어야 한다.

## 3. 변경 — 어디를 어떻게

### 3-1. 층 원판(Gemini · 같은 인물 앵커)

| 구분 | 위치 | 내용 |
|---|---|---|
| 수정 | [`tools/gemini_face_art.cjs`](../../../tools/gemini_face_art.cjs) | `--set layers` — 기본 머리 `base_<m|f>_<oval|round|square>`(민머리 · 민낯) · 머리 모양 층 `hair_<m|f>_<모양>` · 수염 층 `beard_m_<얼굴형>`. 앞 판을 **같은 인물 앵커**(`anchorRefPart` — 같은 폴더 원판 576px 또는 설치본 3배)로 붙이고 「설명한 것 말고는 자리 · 크기까지 그대로」(`LAYER_ANCHOR_TEXT`). `--manifest`(판을 지운 뒤 목록만). `--set player` · `--shapes`는 271부터 안 쓴다 |
| 생성 | scratchpad `layers271/` | 기본 6(남 · 여 계란형은 `player_<sex>_short` 원판 앵커 · 둥근 · 각진은 계란형 기본판 앵커) + 머리 16(각 성별 민머리 앵커) = 22장 · 실패 0 · 약 1,300원(한 장 ≈ 60원). **수염 3장은 HTTP 402(크레딧 소진)** — 충전 뒤 `--only beard_m_oval,beard_m_round,beard_m_square`(약 200원) |

시범 실측(남 민머리 ↔ 짧은 머리): 정렬 이동 0 · 배율 1.000 · 눈~입 평균 채널 차 6.5/255 · 코~턱 차이 픽셀 0.29% → 앵커 재생성이 자리를 지킨다.
전량에서도 정렬은 이동 ≤ 1px · 배율 1.000이었다(눈~입 차 4.9~22.5 — 여 상투가 가장 컸지만 머리 밖 차이는 층에 안 들어온다).

### 3-2. 층 추출 · 설치(`tools/face_layers.cjs` 신설)

| 단계 | 규칙 |
|---|---|
| 정렬 | 배경 벗기기(테두리 BFS · 허용 30) → 번짐 벗기기 → 앵커 판 틀에 이동(±16 · 4px 단계 → ±3 · 1px) · 배율(0.98~1.02 → ±0.005) 탐색. 비용 = 눈~입 구역(상자 가로 0.28~0.72 · 세로 0.36~0.70) 평균 채널 차. 얼굴형 · 머리 판은 계란형 기본판에, 수염 판은 그 얼굴형 기본판에 |
| 틀 | 성별마다 정렬한 판 전부의 합집합 상자 → 정사각(아래 = 어깨선 · 가로 가운데 · 위 · 양옆 여백 2% — 여 상투가 틀에 닿았다) → 96칸(셀 2px). 같은 틀이라 안 바뀐 곳은 같은 칸 |
| 머리 · 수염 층 | 앵커 판과의 차이(알파 다름 또는 채널 차 > 40) → 열기 2px · 성분 ≥ 400px · 닫기 2px → 칸 덮임 ≥ 50%. 순백 칸(머리칼 사이 갇힌 배경)은 비운다. 기본판의 다른 칸에 맞닿은 테두리 칸은 × 0.8(RIM — 흰 머리 + 밝은 피부도 갈라진다) |
| 라벨 마스크 | 기본판(민머리 · 민낯)마다 `<키>_mask.png` — 흰자(밝고 무채 2~80px · 어두운 픽셀 2px 안) · 눈동자(흰자 창 ±3 · −1~+2줄의 어두운 덩어리 ≥ 4px) · 눈썹(흰자 위 납작 어두운 머리색 조각) · 입술(입술 선 성분 가로 8~30 둘레의 분홍 · 선) · 피부(남은 따뜻한 픽셀). 색 = 청록 · 주황 · 초록 · 분홍 · 흰 |
| 손 고정 | `tools/face_layer_fixes.json` — 키 → `{x, y, w, h, label}` 목록(192px 좌표). 자동 분류 뒤 덮어쓴다 — 한 번 고치면 다시 안 본다(이번에는 0건) |
| 설치 | `public/faces/layers/` 28장(기본 6 · 마스크 6 · 머리 16) + `src/data/FaceLayers.ts`(자동 목록 · 부팅 `facelayer_<키>`) |

## 4. 구조상 위치 — 어느 계층의 무엇인가

캐릭터 → 대화 초상(§4.6) → 그림 초상(267~271). **데이터 층**(층 PNG · 라벨 마스크 · 손 고정 JSON — 도구가 굽는다)과
**렌더 층**(`composePlayerFace` — 라벨 · 알파대로 칠하고 겹친다)으로 갈라졌다. 판정(추측 분류)은 없어졌다.
인물 42장 · 32×32 절차 초상 · 필드 스프라이트는 그대로다.

## 6. 잔여 — 이번에 안 한 것

- **수염 층 3장** — Gemini 크레딧이 비어(HTTP 402 · 269의 잔액 추정 6,200원은 틀렸다 — 22장 ≈ 1,300원 뒤 소진) 못 뽑았다. 충전 뒤
  `NODE_USE_ENV_PROXY=1 node tools/gemini_face_art.cjs --out <폴더> --set layers --only beard_m_oval,beard_m_round,beard_m_square` →
  `node tools/face_layers.cjs --src <폴더> --install`. 그때까지 수염을 고른 주인공은 대화창에서 민낯이다(필드 · 32px 초상은 수염 그대로).
- 사용자 육안 — 동그라미 둘 자리 · 48칸 × 색 · 얼굴형 셋(민머리 기본판 턱선).
- 손 고정 JSON은 비어 있다 — 마스크가 틀린 자리를 보면 사각형 한 줄.
- 83차 배포에는 들어 있지 않다 — 다음 배포 때 포함(사용자 요청 시).

## 7. 위험·부작용

- 층은 성별마다 한 틀이다 — 기본판을 다시 뽑으면 머리 층 전부를 같은 폴더에서 다시 굽는다(틀이 바뀐다). 머리 한 모양만 다시 뽑을 때는 같은 기본판 앵커로.
- 앵커 재생성이 자리를 지키는 것은 실측(이동 ≤ 1px)이지 보장이 아니다 — 정렬 탐색(±16px · 배율 ±2%)이 받아 주고, 눈~입 차가 20을 넘으면 시트를 본다.
- 층 가장자리 어둡기(RIM 0.8)는 상수다 — 밝은 머리에서 테가 두꺼워 보이면 0.85~0.9.
- 캐시 키에 얼굴형 · 머리 모양이 들어가 조합 수만큼 캔버스 텍스처가 생긴다(192×192 — 작다).
