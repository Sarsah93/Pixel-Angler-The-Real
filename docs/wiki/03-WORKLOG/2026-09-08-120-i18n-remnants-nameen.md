## 1. 배경 — 왜 했나

119차가 남긴 영어 잔여 3건 중 ①(OSM 상호명)은 "로마자화 여부 자체가 결정 사항"이라
사용자에게 물었고, 되돌아온 답이 **분류 기준**이었다(원문).

> 1) 인게임 내 HUD 등으로 표시될 지역 이름일 경우, 영어로 변환이 필요함.
> 2) 게임 내 랜더링되는 타일 혹은 이미지 등, 간판에 표시된 상호명의 경우, 오히려 한국어로 유지하는 방향이 좋아보임.
> 3) 지역 선택 화면에서 보이는 한반도 지도에서 표기되는 지역명 등은 변환이 필요함.

실측으로 답한 결과 **74개는 (2)가 아니었다** — 뒤의 §2에 근거를 적었다.
이후 사용자가 확정한 범위는 세 가지다.

1. 동적 조립 문자열 `EN_RULES` 보강 (손질·도감·아이템 상세 잔여 한글 해소)
2. 상호명 `nameEn` 배선 — **OSM `name:en` 혼용**, 없는 것만 사전
3. `nameEn` 필드 구조화 — `RegionDef`/`WorldMapNode`/`RegionMapNode`

튜토리얼 삽화 18장 영문판은 **이번 범위에서 제외**(사용자 선택).

## 2. 원인 — 무엇이 문제였나

### 2-1. "상호명 74개"의 정체 (분류 오해)

119차 잔여 노트는 이 이름들을 "실제 간판"으로 적었지만, 실제 렌더 경로는
[RegionFieldScene.ts:1188](../../../packages/client-pc/src/scenes/RegionFieldScene.ts#L1188) —
상점 문 위에 띄우는 **Phaser Text 라벨**이다. 타일·이미지에 구워진 그림이 아니다.

- 지역명(HUD 로그 · 한반도 지도 · 출조 구역 · 지역 맵 노드) = **119차에 이미 영문화 완료**
  (`i18n/places.ts`). 즉 사용자 분류 (1)·(3)은 이미 끝난 상태였다.
- 남은 것은 (2)가 아니라 **UI 텍스트**이며, 그중 상점류는 `[E]` 거래가 되는 **길찾기 기능 요소**다.

실측(속초 `pois.json` 310건):

| 구분 | 수 |
|---|---|
| 라벨로 렌더되는 POI (`notable` ∧ 이름 보유) | 175 |
| 그중 한글 이름 | 133 |
| 고유 이름 | 136 (한글 113 · 영문뿐 23) |

### 2-2. 비용이 거의 없었다 — OSM `name:en`

`pixelazed/_osmcache/sokcho_v2.part_0_0.json`에 **`name:en` 태그가 이미 573건** 있었다.
파이프라인이 `name:ko`/`name`만 뽑고 이 태그를 버리고 있었던 것이 진짜 원인이다.

- 렌더 라벨 한글 133건 중 **91건은 OSM 공식 영문명 보유** → 수작업 0
- **수작업이 필요한 고유 이름은 42건**(+ 라벨 밖 11건 = 53건)

### 2-3. 산문은 규칙으로 풀 수 없다

119차 잔여 ③은 "동적 조립 문자열"로 적혀 있었지만, 실측 결과 두 종류였다.

- **조립 문자열** — 수치·코드가 낀 것(`평균 정확도 82%`, `바늘 간격 0.3m`). 규칙으로 잡힌다.
- **산문** — 어종 습성 설명 57건, 손질 안내문 28건 등. 캡처할 변수가 없어 **1:1 사전만이 답**이다.

### 3-1. 사전 우선순위 (충돌 규칙)

```
EN_PLACES(지명) > EN_POIS(큐레이션) > OSM nameEn(registerNames) > 원문(한국어)
```

`registerNames`가 **이미 있는 키를 덮지 않기** 때문에 이 순서가 성립한다.
`동명항`처럼 지명과 POI 이름이 같은 글자일 때 지명 쪽이 이겨야 하고,
OSM 원본이 부정확한 5건은 큐레이션이 이겨야 한다.

### 3-2. 추가한 규칙 (순서 주의)

- 손질 상태 줄 `필렛 0 / 2   시메 O · 방혈 X · 세척 2회` — **통짜 규칙 우선**
- `평균 정확도 …` 3종 — **구체적인 것부터**
- `N. 본문` 번호 접두 · `바람 —` · `바늘 간격 0.3m` · `칼:` · `뷰:` · `방향 OK`

## 6. 잔여 — 이번에 안 한 것

- **튜토리얼 삽화 18장 영문판** — 사용자가 이번 범위에서 제외했다.
  착수 조건: `docs/mockups/game_guide_hub.html` 을 영어로 복제 렌더 → `guide_*_en.png` →
  BootScene 로케일 폴백 배선. 실캡처 기반 `guide_fight_6_en` 만 119차에 완료돼 있다.
- **dev 전용 문자열** — 순간이동 로그·맵 편집기·손질 dev 버튼 3종은 한국어로 둔다
  (`import.meta.env.DEV` 게이트 — 프로덕션 빌드에 없다).
- **타 지역 POI 백필** — 속초만 심리스로 열려 있다. OSM land 14개 확장 시
  `py tools/backfill_poi_nameen.py <region>` 를 등록 절차에 포함하면 된다(파이프라인은 자동).
- `places.ts` 는 아직 남는다 — 조석 권역 라벨(`동해`/`서해`) 등 데이터 필드가 없는 지명 전용.
  지역·노드 이름은 이제 데이터가 정본이다.

## 7. 위험·부작용

- **`SEP_PATTERNS` 에 `, ` 추가** — 마지막 수단 구분자다. 한국어 문장이 쉼표로 쪼개지면
  조각별 번역이 실패해 **원문 그대로 다시 이어붙는다**(손실 없음). 다만 절반만 번역된 문장이
  나올 여지는 생긴다. 실측 범위(패널 9종·도감·손질·필드)에서는 관찰되지 않았다.
- **`registerNames` 의 전역 사전 오염** — POI 상호명 159건이 전역 사전에 들어간다.
  같은 글자가 다른 맥락에서 쓰이면 상호명 번역이 뜬다. 지명·큐레이션이 먼저 들어가므로
  현재 충돌은 없지만, 신규 지역 추가 시 **일반 명사 상호명**(예: `바다`)이 있으면 확인할 것.
- **성능** — `registerNames`는 지역 로드 시 1회, 159건 Map 삽입 + 캐시 클리어. 무시 가능.
- **회귀 지점** — 한국어 로케일은 §5에서 실측 확인(상호명 원문 유지). 빌드 3/3 · typecheck 0.
