## 1. 배경 — 왜 했나

사용자 지시(요약 · 원문 표현 유지):

1. 「바늘 갯수만큼 미끼를 하나씩 끼울 수 있도록 하고, 각각 다른 미끼를 끼울 수 있도록」
2. 「최소한 하나의 미끼라도 끼워야 채비 저장 및 고정하기(낚시 성공 및 실패 시, 미끼만 끼우면 되도록 UI 구현)」
3. 「다중 미끼일 때 … 추가 시마다 +2%씩 가중. 바늘 3개라면 최대 +4% … 같은 미끼를 연속으로 끼웠을 때 시너지로 1% 추가해서 5%」
4. 「'한 바늘에 두 미끼' 스킬 … 같은 미끼가 2개 소모 … 입질 확률 +2% … 미끼를 끼운 후 바로 아래 작은 버튼 'x2'(켜고 끌 수 있음)」
5. 「카드채비(반짝이 깃)을 장착했을 경우, 미끼를 끼우지 않아도 채비 확정 … 입질 확률은 0이지만, 전갱이만 10% 특수적용」

## 2. 원인 — 192차 상태

- 미끼 칸은 바늘마다 이미 있었지만 **「미끼 1」만 필수**였고, 입질·소모는 평면 투영 `rig.bait`(첫 미끼) 하나만 봤다.
- 카드 채비는 아이템 없이 단수만 고르는 갈래였다(반짝이 개념 없음). 고정 중에는 미끼 칸도 잠겼다.

## 6. 잔여

- 1인칭 실캐스팅 입질 확률 실측은 하지 않았다(배율 배선은 코드 검토 + 하네스 요약값). 체감 확인은 사용자 실검증.
- 카드 채비 아이콘은 절차 생성 임시 도트 — 고퀄 그림이 오면 `it_card_rig_*.png` 교체.
- 묶음추 바늘은 여전히 **한 번에 한 마리**만 문다(다단 동시 히트는 카드 채비만).
- 착수 조건: 사용자 실검증 피드백.

## 7. 위험·부작용

- **스킬 포인트 +1**: 시작 보너스로 모든 세이브의 가용 포인트가 1 늘었다(예산 등식 유지용 — 130차 원칙: 비용을 깎지 않고 우변을 늘린다).
- 미끼 칸은 가방의 같은 미끼 묶음을 **참조**한다(끼운다고 가방에서 빠지지 않는다) — 192차와 같은 모델. 소모는 입질 때만.
- 192차 세이브의 카드 채비(`card_type` 갈래)는 그대로 동작하지만 반짝이가 아니다(아이템이 없으므로).
