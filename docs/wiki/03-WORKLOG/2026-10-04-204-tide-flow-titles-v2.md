## 2. 원인 — 무엇이 문제였나

기능 추가가 주이고, 조사 중 **버그 하나**를 찾았다.

- **조류 세기가 만조·간조와 어긋나 있었다** — `TidalCurrentEngine.tideFactor`는 `|sin(2π/12.5·h)|`인데
  1인칭 낚시가 `h`에 **벽시계 시각**(`hoursNow`)을 넣고 있었다. 실제 만조 시각과 무관하게 매일 같은 시각에
  물살이 세지고 약해졌다 — 물돌이(만조)인데 본류대 최대 물살이 나올 수 있었다.
- 확정 근거: 조사 에이전트가 두 함수의 위상을 비교했고, 같은 날 만조 ±30분에서 `tideFactor`가 0.9 이상이 나오는 경우를 확인.
- 수정: 물때 위상 시계 `tideClockHours()` = `6.25 × (지난 극치부터 경과 / 반주기)`를 넣는다 — 극치에서 0, 극치 사이 한가운데서 최대.
  엔진은 고치지 않았다(완료 시스템). 처음엔 단계별 물살 배율(`currentMult`)을 따로 곱했다가 **이중 반영**이라 걷어 냈다.

## 4. 구조상 위치 — 어느 계층의 무엇인가

- `낚시 → 물때` — **계약·판정은 core**(`TideFlowPhase` — `calculateTideInfo`의 극치만 쓴다, 순수 함수).
  입질(`computeFeedingActivity`)과 크기(`rollTieredLength`)는 **선택 입력**이라 안 넘기면 기존 수치 그대로.
- `진행 → 스킬` — 「물때 감각」은 데이터 1줄 + 클라 알림기(`TideFlowNotifier`) — 알림 상태는 모듈 단위라 씬을 옮겨도 이어진다.
- `진행 → 타이틀` — 데이터 모델이 바뀌었다(`goal` 1개 → `paths`). 세이브는 **누적 수만** 갖고 있어 조건이 바뀌어도 잃는 것이 없다.
  옛 `trophyCatch`는 로드 때 `trophyPts`로 백필(60cm↑ 1마리 = 1점 — 보수적).
- 장르 × 어종 공략(P1~P3)은 **계약 미정** — 스펙 §0의 결정 대기 항목.

## 6. 잔여 — 이번에 안 한 것

- **장르 × 어종 물때 공략(P1~P3)** — 사용자가 "방향 결정되면"이라고 했다. 스펙 [`TIDE_PHASE_STRATEGY_SPEC.md`](../../../.agents/TIDE_PHASE_STRATEGY_SPEC.md) §0 · 백로그 AT.
  착수 조건 = 어종별 단계 선호표 · 동해 감쇠 · 장르 조건(밑밥 누적 · 봉돌 구름 · 구멍 수위) 중 어디까지 넣을지 결정.
- **문턱 튜닝** — 실플레이 속도를 보고(백로그 AS). 목표만 바꾸면 되고 얻은 것은 지켜진다.
- **물때 단계 미니 표시(HUD)** — 지금은 스킬이 있을 때 채널 알림 + 1인칭 수심 패널 한 줄. 상시 HUD 칩은 겹침 감사가 필요해 보류.

## 7. 위험·부작용

- **입질 수치가 바뀐다** — 끝날물(×0.7)·물돌이(×0.8~0.85)는 전보다 덜 문다. 사리 강도로 스케일해서 조금 땐 차이가 줄어든다.
  체감이 너무 크면 `TIDE_FLOW_PROFILE.biteMult`만 조정.
- **물살 위상이 바뀌었다** — 같은 시각이라도 날짜마다 물살 세기가 다르다(의도). 조류 엔진에 다시 벽시계를 넣지 말 것(`fishing-loop.md` §6).
- 옛 세이브의 대물 점수는 1점/마리로 백필 — 70cm↑을 잡았던 사람은 손해를 보지만, 조건이 강화된 것과 같은 방향이라 수용.
