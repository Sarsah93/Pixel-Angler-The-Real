## 1. 배경 — 왜 했나

사용자가 캡처 2장(우리 항구 — 타일 이음매에 빨간 동그라미 / 타 게임 '세피리아'의 지형 타일)과 함께:

> "맵 지도 사실은 너무 정형화된 타일 체계가 아닌 것 같아서 … 실제 지형이라고 생각했을 때,
> 캡처화면처럼 **뜬금없이 벽돌지형에서 모래 지형으로 바뀐다**던가 하는 등 뭔가…
> **지형 경계간의 이음 부분? 그런게 전혀 고려되어 있지 않은 것 같아.**"
>
> "두 번째 캡처 사진은 타 게임 '세피리아'의 지형 타일 구성이야. 타일 간 연관성, 연결성,
> 지형과의 조화 등이 컨셉에 맞게 잘 설정되어 있어. **단, 저 지형도는 제작자가 임의로 설정
> 및 구조화한 지형에 가까워.** … 우리는 OSM 실측 기반으로 … 이 괴리감 부분을 어떻게 해결할 수 있을까?"

즉 **"손으로 그린 맵의 조화"를 "실측에서 자동 생성되는 맵"에서 얻는 방법**이 과제다.

## 2. 원인 — 무엇이 문제였나 (근본 3건)

실측으로 확정한 기전은 셋이고, 셋 다 "덜 만들어서"가 아니라 **구조가 그렇게 되어 있어서**다.

**① 지형 어휘가 8자뿐이고 `'.'`가 만능 통이었다.**
`. ~ # , r w s b` — 도로/광장/주차장/흙길/갯벌/농지/숲이 전부 `'.'`(기본 육지) 아니면 `'r'`(래스터 포장)로
뭉개졌다. 어휘가 없으면 전이도 없다: 모래(`s`) 옆이 보도(`w`)인지 광장(`r`)인지 구분이 안 되니
"벽돌에서 모래로 뚝 끊기는" 그림이 나온다.

**② 전이가 '쌍'이 아니라 '내 지형 테두리'였다.**
`edgeTex`는 **자기 그룹 키 하나**로만 캐시됐다(`grass_edge`, `tan_edge`…). 그래서 잔디는
누구와 만나든 같은 테두리를 썼다. 게다가 106차가 **모래 `'s'`를 전이에서 일부러 제외**해 두었다
(당시 톱니 경계가 더 나빠 보였다는 이유) — 사용자가 짚은 바로 그 경계다.

**③ 사진 셀은 전이 로직 앞에서 `continue`로 빠져나갔다.**
물·조도 갯바위·방파제 분류 타일은 렌더 초반에 자기 그림을 그리고 곧장 다음 타일로 넘어간다.
그래서 **실사 타일과 절차 타일이 만나는 선**에는 전이가 원천적으로 걸릴 수 없었다.

## 3. 변경 — 어디를 어떻게

| 구분 | 위치 | 내용 |
|---|---|---|
| 신설 | `packages/core/src/rules/TerrainTransition.ts` | `TerrainClass` 7종 · `TERRAIN_DEFS`(13 지형 × 칠하기 순서 `paint`) · **`seamBetween(self, other)`** → `{kind, seamCh?, strength}` · `needsInterstitial` · `terrainGroup` |
| 수정 | `packages/core/src/types/RegionMap.ts` | `RegionTerrain`에 **`p d t c f`** 추가(광장·흙길·갯벌·농지·숲) · `TERRAIN_BY_CHAR` · `isWalkableTerrain`(물·건물만 차단) · `isFishableStandTerrain`에 갯벌 편입 |
| 수정 | `packages/client-pc/src/scenes/SeamlessChunks.ts` | 지면 그룹 5종 추가 · 전이 세트 확장 · `outside()`를 `seamBetween` 기반으로 교체 · **`drawSeamGrains`**(쌍별 알갱이 전이) · `SEAM_GRAIN`/`SEAM_SPAN` 팔레트 · 숲 캐노피·농지 이랑 그리기 |
| 수정 | `tools/build_osm_tilemap.py` | OSM 태그 → 신규 5자 패스 · `PALETTE` 확장 · **후처리 순서 재정렬**(방파제 추론 → 항만 에이프런 추론 → 유기 경계 지터 → 지터 후 디노이즈) |
| 수정 | `tools/build_region_maps.py` | `OSM_PALETTE`·`OSM_WALKABLE`을 13자로 |
| 삭제 | (빌더의) 타일 단위 완충층 삽입 | 32px 흙 타일 한 줄이 **의도적인 흙길**로 읽혀 더 나빠졌다 — 런타임 알갱이 띠가 대신한다 |

### 전이 종류 (쌍으로 결정)

| kind | 언제 | 그림 |
|---|---|---|
| `blob` | 같은 유기질(잔디↔흙) | 16조합 블롭 오토타일 |
| `curb` | 포장↔포장(보도↔차도·광장) | 연석 선 |
| `spill` | 유기질↔입자(잔디↔모래·농지↔흙길) | 알갱이가 상대 쪽으로 번짐 |
| `revet` | 포장↔물·구조물 | 호안 단차 |
| `foam` | 물↔무엇이든 | 포말 |
| `none` | 같은 지형/무관 | — |

### 설계 결정

- ⚖ **어휘는 OSM 태그에서 자란다.** `landuse=forest → f` · `farmland → c` · `pedestrian/square → p` ·
  `track/path → d` · `tidal flat → t`. 어휘를 우리가 지어내면 다시 "임의 배치"가 된다.
- ⚖ **칠하기 순서(`paint`)를 지형 정의가 갖는다.** 누가 위에 덮이는지가 데이터라서,
  새 지형을 추가할 때 렌더 코드를 고치지 않는다.
- ⚖ **숲·농지에는 블롭 전이를 주지 않았다.** 잔디 블롭을 붙였더니 **갈색 테두리를 두른
  초록 사각형**이 되어 오히려 타일 티가 났다 — 유기 `spill`만 쓴다.

## 4. 구조상 위치

`S1 필드 → 심리스 타일맵 → 지형 어휘·전이`.
계층은 **데이터(빌더 산출 문자) + 계약(core 전이 규칙) + 렌더(SeamlessChunks)** 3층이고,
판정(어떤 전이인가)은 **core 한 곳**이 소유한다 — 레거시 `RegionFieldScene.renderTerrain`도 같은 규칙을 읽는다.

## 6. 잔여

- **`d`(흙길)·`t`(갯벌)는 속초에서 0타일** — 속초 OSM 캐시에 해당 태그가 거의 없다
  (`amenity=parking`·`landuse=industrial`도 마찬가지라 `'p'` 4,877타일 중 대부분은
  **구조 추론**(항만 에이프런)에서 왔다). 어휘 자체는 서고, 태그가 풍부한 지역에서 자동으로 채워진다.
- 건물 전면(문 쪽)의 에이프런·차양은 미착수 — 173차 B에서 가로 시설물만 처리했다.

## 7. 위험·부작용

- **⚠ 지형 문자가 늘어 `build_region_maps.build_seamless`가 terrain.png를 최근접 색으로 되읽는다.**
  신규 색을 `OSM_PALETTE`에 넣지 않으면 **JSON에서 조용히 사라진다**(실제로 한 번 밟았다).
  팔레트 색은 쌍거리² ≥ 1,668로 벌려 두었다 — 새 지형 추가 시 이 간격을 확인할 것.
- ⚠ 유기 경계 지터(±1타일·34%)는 **디노이즈와 한 쌍**이다. 지터만 켜면 고립 타일이 생긴다.
- 기존 맵 JSON이 전부 재생성되므로, patch.json(편집기 수정분)은 보존되지만 **미세 경계는 바뀐다.**
