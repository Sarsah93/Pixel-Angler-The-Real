## 1. 배경

사용자가 실사 사진 7장을 보내며 지시했다.

> 캡처 이미지 순서대로, 눈볼대(금태), 문절망둑, 문치가자미(참가자미), 강도다리, 도다리
> 인게임과 아티팩트 wiki에 매핑 & 업데이트 해줘.

이어서 두 장을 추가하며 **전제 조건이 다르다**고 못박았다.

> 순서대로 병어와 덕대인데, 얘네는 배경 투명이 아니야. 감안해서 배경 투명으로 적용해줘.
> (transparent 작업하려 했는데, 잘 안되서 그냥 우선 올려본다.)

7종 전부 **어종 DB에는 이미 있는데 그림만 없던** 종이다. 게임은 그림이 없으면
어획 팝업·인벤 아이콘·상세보기에서 speciesId 폴백조차 못 해소한다(42차 폴백 체계 참고).

## 2. 원인 — 「투명이 아니다」의 실제 형태

앞 5장(webp)은 **이미 진짜 알파**였다(테두리 표본 1,000여 점 중 불투명 0).
뒤 2장(jpg)만 문제였고, 그 형태는 단순 흰 배경이 아니라
**투명을 뜻하는 회색 체커보드가 실픽셀로 구워진 것**이었다.

실측:

- 체커 칸 크기 **약 11.9px**, 두 회색은 **L 34 / L 102**(전부 무채색 R=G=B).
- 피사체도 무채색에 가깝다 — 특히 덕대는 은백색이라 **밝기만으로는 배경과 못 가른다**.
- JPEG 압축이 칸 경계를 뭉개 **L 45~90의 중간 띠**를 만들었다. 이 띠가 벽이 되어
  순정 회색만 훑는 BFS는 칸 하나에 갇힌다(1차 시도 배경 제거율 **22.6%**).

## 2-1. 실패한 접근 (기록 — 다음에 같은 함정을 다시 밟지 않도록)

**① 밝기 밴드 BFS (L 12~128 무채색)** — 경계 띠를 흡수해 제거율 71%까지 올라갔지만,
**덕대 몸통으로 새어 들어갔다**. 어두운 윤곽선이 다리가 되어 회색 비늘까지 먹었다.

**② 격자 모델 판정** — 체커는 완전히 주기적이므로 칸 크기·위상을 추정해
「이 칸이 기대하는 회색」과 비교하면 같은 회색이라도 피사체는 패턴을 안 따른다.
피사체는 온전히 살았지만 **배경에 점점이 얼룩이 남았다**(모델 허용 오차 밖 칸들).

### 3-1. 배경 제거 — 최종 3단 파이프라인

②(격자 모델)의 피사체 보존력을 살리고 얼룩만 걷어내는 순서로 확정했다.

1. **격자 모델 BFS** — 칸 크기·위상·명암 반전을 자동 추정(`cell 11.9 / phase 6.7·2.9`)해
   테두리에서 배경만 벗긴다. 피사체 경계에서 정확히 멈춘다.
2. **최대 연결요소만 남기기** — 남은 얼룩은 전부 피사체와 떨어져 있다.
   불투명 연결요소를 세어 가장 큰 덩어리(= 물고기)만 보존
   (병어 1,163개 → 1개 · 덕대 799개 → 1개).
3. **실루엣 프린지 제거** — 윤곽선에 **붙어 버린** 칸은 ②를 통과한다.
   바깥(투명)에서 다시 BFS로 들어가 순정 체커 회색만 지운다(허용 오차 2회 확대).

스크립트는 일회성이라 레포에 남기지 않았다 — 절차·수치는 이 문서가 원장이다.

## 4. 구조상 위치

`S20 발견·위키 → 어종 그림` — **에셋 층**. 게임 로직·어종 DB는 한 줄도 바꾸지 않았다.
그림이 들어오면 `resolveFishTexture` → `FISH_TEXTURE` 폴백 체계가 어획 팝업·인벤
아이콘·상세보기·위키 카드를 **동시에** 해소한다(42차 전수 배선).

어종 ↔ 파일 대조:

| 사진 | 어종 id | 이름(DB) | 학명 |
|---|---|---|---|
| 1 | `blackthroat_seaperch` | 눈볼대(금태) | *Doederleinia berycoides* |
| 2 | `yellowfin_goby` | 문절망둑 | *Acanthogobius flavimanus* |
| 3 | `flounder` | 참도다리(문치가자미) | *Pseudopleuronectes yokohamae* |
| 4 | `starry_flounder` | 강도다리 | *Platichthys stellatus* |
| 5 | `frog_flounder` | 도다리 | *Pleuronichthys cornutus* |
| 6 | `silver_pomfret` | 병어 | *Pampus argenteus* |
| 7 | `korean_pomfret` | 덕대 | *Pampus echinogaster* |

⚠ 3번은 사용자가 **「문치가자미(참가자미)」**로, DB는 **「참도다리(문치가자미)」**로 부른다.
학명이 일치하므로 **매핑은 정확**하고, 표시명 변경은 사용자 확인 대상으로 남긴다.

## 6. 잔여

- **표시명 확인** — 3번을 「참가자미」로 바꿀지는 사용자 결정 대기(학명은 일치).
- **병어·덕대 해상도** — 원본 jpg가 542×475 / 498×418이라 다른 5종(1,400~2,000px)보다
  낮다. 카드 썸네일(360px)에서는 티가 안 나지만 **어획 팝업 대형 표시에서는 거칠다**.
  고해상 원본이 생기면 같은 파이프라인으로 교체한다.
- **광폭 어종 아이콘 비율** — 문절망둑 1999×731 등은 소형 아이콘에서 얇게 보인다
  (전 광폭 어종 공통 · 백로그 이월).

## 7. 위험·부작용

- **게임 밸런스 영향 없음** — 그림만 붙었다. 스폰·가격·판정 무변경.
- **구세이브 영향 없음** — `iconTexture`가 빈 구세이브 어획물도 `speciesId` 폴백으로
  이제 그림이 나온다(42차 폴백 — 개선 방향).
- ⚠ **위키 재발행은 4단계 순서를 지켜야 한다**(169차 규칙): core build →
  `py tools/gen_wiki_images.py` → `node tools/dump_wiki_items.mjs` →
  `node tools/gen_game_wiki_data.mjs --html`. 그림 단계를 빼면 **조용히 그림 없이 구워진다**.
- ⚠ **아티팩트 파일 수 118 / 상한 255.** 그림이 계속 붙으면 `used.txt` 기준 추림이 필수다.
- ⚠ **체커보드 배경은 육안으로 「투명」과 구별되지 않는다.** 에셋을 받으면
  테두리 알파를 실제로 찍어 볼 것 — `mode`가 RGB면 알파 자체가 없다.
