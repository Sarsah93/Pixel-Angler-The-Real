## 1. 배경 — 왜 했나

104차 잔여로 남긴 **"방파제(호안 캡)·갯바위 시트 = 사용자 제작 중, 도착 시 `'b'`·암반 렌더
교체"** 의 납품분이다. 104차까지 방파제 `'b'`는 Kenney pier 타일 + 절차 캡(4px 회색 띠)이라
"콘크리트 상판 + 사석 사면"이라는 실제 구조가 전혀 없었다.

## 2. 원인 — 세 시트의 성격이 서로 다르다 (실측)

| 시트 | 성격 | 확정 근거 |
|---|---|---|
| `돌 방파제 그리드.png` (747×291) | **실사 항공사진 + 사용자가 직접 그은 격자** | 열 16 · 행 6 선 실측(피치 46.7 × 48.3). 셀 96개 |
| `방파제 바위 및 바다 경계면 모서리.png` (556×196) | 검정 테두리 셀 = 타일, 나머지는 제목·라벨 | 바위 20 + Rock-Water 4 + 물 상세 7 |
| `부두 플랫폼 모서리.png` (221×99) | 검정 테두리 셀 4개 | 테두리 열 실측 14/64/114/164 · 행 42~86 |

⚠ **바위 셀의 "흰 배경"은 흰색이 아니라 알파 0이다** — 뷰어가 투명을 희게 보여줄 뿐.
처음 테두리 탐지를 `convert('RGB')`로 돌렸더니 투명이 (0,0,0)이 되어 셀이 통째로 "검정"으로
잡혔다(좌측 패널 전 열이 dark 25% 이상). 알파를 본 뒤 정상 검출.

세 장 모두 104차와 같은 압축 노이즈를 갖는다(부두 셀 43×44에 고유색 1,122개) — 그대로 쓸 수 없다.

## 4. 구조상 위치 — 어느 계층의 무엇인가

`S2/S7 필드 → OSM 심리스 → 지형 품질`. **파이프라인(에셋) + 클라이언트 렌더 층**만.
terrain 재빌드 없음, core 계약 변경 없음, 걷기·충돌 판정 무영향(`'b'`는 그대로 육상 타일).

## 6. 잔여 — 이번에 안 한 것

- **물 상세 7종 미적용** — `wd_caustic_*`(코스틱)·`wd_shallow/deep`(그라데이션)은 게임 수심
  버킷 절차 베이크와 팔레트가 달라 섞으면 색이 튄다. 등록만 했다.
- `submerged_0~2`는 바다 컷 후 남는 픽셀이 62~219개로 매우 성기다 — 오버레이로 쓰려면
  원본 셀 재선정이 필요.
- `head_0/1`(방파제 두부)·`rockwater_*`는 등록·부분 사용만 — 두부 전용 배치(끝단 판정)는
  미구현(현재 3면 물 = 사석).
- 부두 모서리 **코너 셀**(`pier_edge_0/2`)은 등록만 — 현재 두 방위 접경은 가장자리 셀 2장
  합집합으로 처리(104차 해변과 같은 방식).

## 7. 위험·부작용

- **`'b'` 외관이 전면 교체됐다** — 청회색 Kenney pier → 실사 탄색 상판. 방파제·부두·제방이
  전부 바뀌므로 타 지역 확장 시 육안 확인 대상.
- **사석/상판 분류는 `raysToOpenSea` 의존**(104차 마스크) — 마스크가 잘못되면 항내 안벽에
  사석이 깔린다. 청초호·항내 실렌더로 확인했으나 타 지역은 재검수 필요.
- 톤 정규화는 **군 단위 평균**이라 셀 내부 그라데이션은 남는다 — 근접 확대에서 미세한
  셀 경계가 보일 수 있다(현재 체감 허용).
- 청크당 draw 증가(방파제 접경·섬 둘레 바위) — 5초 이동 샘플 60 FPS 유지.
