## 1. 배경

87차 두족류 가이드 9경로는 근사값이었고, 89차에 좌표 기준이 도마 rect → **피사체 rect**로
바뀌면서 전량 재측정 대상이 됐다(백로그 1c). 사용자가 수동 실플레이 + dev F9로 실측을 시작했고,
**1~3단계(시메·개복·내장·연골) 측정본 + 구조 변경 지시 3건**을 전달했다.

4단계(껍질 분리)는 재구성 명세와 마무리 스윕 실측만 먼저 받았다 — "껍질이 온전히 붙은 몸통"
에셋이 없어 **에셋 입수 후 별도 차수**로 한다(사용자에게 요구 에셋 3종 전달 완료).

## 2. 원인 — "전체적으로 커버율 부족"의 기전 2가지

1. **근사 좌표 ↔ 실사 해부 위치 불일치** — 87차 근사값은 시트 SVG 기준이라 89차 실사 도트의
   실제 부위(연골 위치·내장 덩어리·개복선)와 어긋났다. 플레이어는 화면의 해부 구조를 따라
   긋게 되므로 잘못된 유도선 대비 커버율이 떨어진다. → 실측 좌표로 교체.

2. **시메(nerve_cut) 판정이 실측 선 길이와 충돌 (확정)** — 구 판정은 ① 경로 **중점** 반경
   (tapRadius 0.06 × 1.6 = 0.096) 안에서 시작 + ② 절대 길이 0.03~0.12 요구.
   실측 선은 길이 0.277~0.315라 **가이드가 그려주는 시작 링(끝점)에서 긋기 시작해도
   중점과의 거리 0.14 > 0.096으로 실패**하고, 선을 끝까지 따라 그으면 길이 초과로 실패한다.
   즉 "가이드를 그대로 따라 그으면 통과"가 성립하지 않는 판정이었다.

### C. 판정 — `evalNerveCut` 재작성 ([ButcheryProcess.ts](../../packages/core/src/simulation/ButcheryProcess.ts))

- 시작 정확도 = **유도선까지의 거리**(`distToPath`) — 선 위 아무 지점에서 시작해도 된다
  (끝점 시작이 자연스럽다. 구: 중점 고정).
- 길이 상·하한 = **유도선 길이 비례** (하한 `max(0.03, L×0.35)` / 상한 `max(0.12, L×1.8)`).
- "짧고 정확" 취지 유지 — 과도하게 길게 끌면 여전히 실패.
- nerve_cut은 두족류 전용(어류 시메 = tap) — **어류 무영향**.

### D. 연출 — 당김 계열에 칼 글리프 제거 (`playActionAnim`)

`drag_out`·`lift_flap`(내장 분리·연골 뽑기·부리 뽑기·껍질 들추기)은 칼 절삭이 아니다 —
칼 글리프 + 절개 스파크 + 여열 글로우 대신 **그립 링(잡은 손) + 당김 방향 뒤로 끌려 나오는
잔선**으로 교체. 절삭 계열(guided_cut·mantle_slit·vessel_cut·fin_cut)은 기존 칼 연출 유지.
