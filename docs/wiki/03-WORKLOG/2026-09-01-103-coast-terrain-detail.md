## 1. 배경 — 왜 했나

102차 맵 확정 검토에서 사용자 캡처 7장 리포트:

> "아직 타일이 부자연스럽게 깔려있어. 대각선으로 어긋나있는 타일들도 여전히 혼재하고 있어.
> OpenStreetMap 기준으로 도로 위에 건물이 배치되는 경우는 없어. 지도상에서는 도로와 건물,
> 땅과 도로, 도심과 해안가, 해안가와 바다 등 경계가 명확히 보이는데, 인게임 상황은 그렇게
> 디테일하게 적용되지 않았어. … 청호해수욕장은 모래 비슷한 질감 … 방파제 라인 … 학습이 안 됐네.
> 테트라포트가 적용된 방파제 … 조도(섬) 또한 섬 지역에 맞게 타일셋을 구성해야 해."

## 2. 원인 — 무엇이 문제였나 (데이터 실측으로 확정)

- **모래는 이미 깔려 있었다** — 사용자 지점(627, 596) terrain 실측 = 전부 `'s'`.
  문제는 **Kenney sand 셀(크림)과 tan 포장(베이지)이 육안 구분 불가** → "모래 미적용"으로 보임.
  "부자연스러운 대각 접경선"도 같은 색 지형(모래↔포장) 경계에 테두리만 떠서 생긴 착시.
- **해변-바다 단절** — coastline 장벽이 3타일 두께로 전부 `'.'`가 되어 `ssss..~~~` 띠 발생
  → 포말·젖은모래 접경 판정(`'s'` adjacent `'~'`)이 전혀 안 걸림.
- **방파제 데이터 부재** — OSM `man_made` 태그는 bbox 전체에 **way 3개**(pier 2 closed + 1 open).
  사용자 OSM 캡처의 방파제들은 태그가 아니라 **coastline으로 둘러싸인 가는 육지 조각**
  ('.' 렌더 = tan 막대). 구 `b` = 73타일뿐.
- **바다 직각 계단 밴드** — `computeWaterDistance`가 맨해튼 BFS → 마름모 등고선 + 버킷
  하드 경계 = 큰 직사각 스텝.
- **조도** — 소형 야생 육지가 `'.'` → tan 포장 광장으로 렌더.

## 4. 구조상 위치 — 어느 계층의 무엇인가

`S2/S7 필드 → OSM 심리스 → 지형 품질`. 파이프라인 = **데이터 층**(terrain 재분류 — 재빌드 필요),
클라이언트 = **렌더 층**(SeamlessChunks 베이크). core 계약 변경 없음 — `'b'`는 기존 지형 문자.
속초 재빌드 완료(patch 321타일 보존 · 스폰 OK · 걷기 컴포넌트 48).

## 6. 잔여 — 이번에 안 한 것

- **"도로 위 건물" 미재현** — 확인 지점(중앙로 골목)은 OSM 건물 폴리곤 자체가 성긴 지역.
  사용자 목격 위치 제보 시 재조사. 후보 기전: 도로 벡터 밴드(관대한 폭)가 건물 타일 밑을
  지나며 지붕 스프라이트와 겹쳐 보임 — 위치 확정 후 밴드 클리핑 또는 폭 조정 판단.
- **대각 어긋남 잔여 평가** — 모래 발색으로 착시 상당 해소. 남는 계단 경계(모래↔포장 사선)는
  5m 타일 양자화 본질 — 사용자 재확인 후 필요 시 모래 전용 블롭/삼각 확장.
- 도심 골목 도로 폭(관대 설정)이 밀집 지역에서 아스팔트 벌판이 되는 문제 — 사용자 결정
  (체감 폭 vs 실측 폭 트레이드오프).
- 갯바위 낚시 포인트로서의 조도(스폰·상호작용)는 배 출조 콘텐츠에서.

## 7. 위험·부작용

- **방파제 추론은 휴리스틱** — 폭 ≤ 10타일 + 양끝 바다 + 인프라 컴포넌트. 타 지역 확장 시
  오분류 가능(빌드 로그의 `[post] 방파제 추론 N타일` 확인 + terrain.png 육안 대조 절차에 포함).
- **재빌드는 terrain을 OSM 캐시에서 다시 굽는다** — 사용자 타일 편집은 patch.json이라 보존
  (이번 321타일 보존 확인). 단 patch가 구 지형 기준 편집이면 새 분류와 어긋날 수 있다.
- 챔퍼 거리로 waterDist 값이 미세하게 변함(대각 경로 짧아짐) — 암초 분포·배 배치가 소폭 이동
  (결정적이라 리로드 후 고정, 게임플레이 판정 무영향).
- 모래 틴트는 텍스처 키 `_t` 분리 — 구 키를 참조하는 코드 없음 확인.

## 후속 — 경계 파편·내부 경계선 정리 (사용자 캡처 X 표시 3건)

사용자 리포트: "경계 안쪽 타일이 뒤섞이는 느낌 · 안쪽 타일에도 경계선 · 경계 테두리에만
경계선이 보여야 · 대각선 타일 알고리즘 수정 필요".

**원인 2건 (terrain 실측으로 확정)**:

1. **지형 소금-후추 노이즈** — OSM 폴리곤 래스터화 가장자리에 고립 1타일(`..,`/`.,,` —
   잔디 안 점·점 안 잔디)이 흩어져 각각 엣지 셀·림을 발동 → "내부 경계선·파편"
   (팜트리 인렛 주변 실측 rows 608~610).
2. **삼각 셀 무테** — 45° 삼각에 경계선이 없어 [테두리 사각 셀] ↔ [무테 삼각]이 교대,
   경계선이 끊긴 파편으로 보임. 1:1 계단에서 빗변 끝점과 사각 테두리 끝점은 기하학적으로
   같은 점 — 빗변에 선만 그으면 연속된다.

**수정 3건**:

- 파이프라인 **디노이즈 다수결 필터**(`build_osm_tilemap.py` 3b→3c 사이) — `','`/`'s'`/`'.'`
  상호 간 직교 이웃 3/4 동화 ×2패스 (속초 72타일 동화 · 도로/보도/방파제/건물 불변). 재빌드.
- **삼각 빗변 경계선 베이크** — `bake(hypLine)` 신설: tan/sand `#ac9d83` · pier `#8b9ea6`
  (Kenney 테두리 실측 색). 사각 테두리 셀과 빗변 선이 이어져 경계가 한 줄이 된다.
- **잔디 방향 삼각 비활성**(`tri()`에서 `a === ','` 스킵) — 잔디 경계는 블롭 림 전담.
