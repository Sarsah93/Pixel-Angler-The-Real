## 1. 배경

사용자 실검증(인게임 + 아티팩트) 지시 5건.

> **1.** 아티팩트 수정 4건 — ① 챕터 헤드를 `제n장 · 챕터이름 — 지역` 순서로
> ② 왼쪽 색인을 **장별 드롭다운**으로("챕터 5를 찾으려면 한없이 스크롤바를 내려야하는데?")
> ③ `'임무 정보'`는 너무 군사적 → **`'퀘스트 정보 개요'`**
> ④ 인포박스와 아래 `대화` 창이 **서로 겹쳐진다**. "퀘스트 정보 개요가 길어지면 아래 '대화'가 밑으로 밀려나야 버그가 없을 것 같네."
>
> **2.** 선택지 510개 아직 한국어인 부분, 전부 영문으로 교체.
>
> **3.** 시드 낚싯대 기본 착용 — "착용 해제하면 되니까 관계없을 것 같네."
>
> **4.** 탑다운 NPC 대화 초상의 얼굴 확대가 제대로 반영됐는지 —
> "**단순 확대가 아니라, 픽셀 단위와 이미지 그래픽 퀄리티를 높여야 함.** 해당 캐릭터의 특징적인 것을 최대한 묘사하여 반영."
>
> **5.** "서브퀘스트가 가능하길래 눌러보니 **그냥 대화만 했을 뿐인데 재화를 지급해주는 퀘스트들**도 있더라? …
> 퀘스트가 어떤 난이도라는 게 존재해야 하는데, 전혀 없는 건 좀 이상하네. 잘 찾아보고 만약 버그라면 수정하고,
> 버그가 아니라면 **클리어 난이도**(유저 수행하는 특정 활동을 해야한다는 기준에서 난이도를 설정)라는게 있어야 할 것 같은데?"

3번은 사용자가 스스로 닫았다 — **조치 없음**.

## 2. 원인

### 2-1. "대화만 했는데 재화" — 버그가 아니라 134차 설계가 드러난 것

`StoryObjective.manual`(134차)은 **자동 추적기가 없는 목표를 대화 [다음 단계]로 닫는 장치**다.
`StoryStore.event()`가 `if (o.manual && ev.kind !== 'talk') return;`으로 실제 행위 이벤트를 전부 무시하므로,
라벨이 무엇을 약속하든 요구되는 조작은 **대화 한 번**이다.

실측(착수 조사):

| 항목 | 값 |
|---|---|
| 전체 목표 중 `manual` | **84건** |
| 그중 `kind: 'talk'`(어차피 talk 이벤트로 닫히므로 무해) | 77건 |
| **실제로 문제인 것**(행위를 약속하면서 manual) | **7건** |
| 라벨에 개발 상태가 노출된 것(`(대화로 완료)`·`(… 준비 중)` 등) | **112건** |

즉 **코드 버그는 없었다.** 다만 ① 난이도라는 개념이 없어 표기가 불가능했고 ② 라벨이 개발 상태를 노출했으며
③ 대화만으로 끝나는 임무가 조업 임무와 **같은 액수의 품삯**을 줬다. 셋 다 고칠 수 있는 것이다.

### 2-2. 아티팩트 겹침 — `float:right`가 원인

인포박스가 `float: right`라 뒤따르는 본문(`대화` 블록인용)이 **박스 아래로 흘러 들어가** 글자가 겹쳤다.
"길어지면 아래가 밀려나야 한다"는 사용자 요구는 float으로는 구조적으로 만족할 수 없다.

### 2-3. 초상 — 10x9 화소를 키운 것이 전부였다

150차 `ensureFacePortrait`는 게임 시트의 얼굴 창(16x16 아트 px)을 잘라 NEAREST로 확대했다.
그 격자에서 **실제 얼굴은 가로 10 · 세로 9줄**이고, 눈은 2x2 사각형 두 개, 코는 아예 없다.
몇 배로 키워도 인물이 구별되지 않는다 — 사용자 지적("단순 확대가 아니라")이 정확했다.

### 3-1. 난이도 계산 규칙 (⚖ 결정)

- **`manual` 목표는 0점.** 강제되지 않는 목표를 세면 표기가 거짓말이 된다.
- 점수는 **플레이어가 하는 일의 종류와 양**만 본다 — 요구 레벨·보상 크기는 넣지 않는다
  (레벨은 도달하면 사라지는 관문이고, 보상은 난이도의 결과지 원인이 아니다).
- 조건 한 겹(어종·크기·계절·조법·장소·자가어획·지정 물건·면허)마다 **+1**.
- 수량은 2~3회 +1 / 4~7회 +2 / 8회 이상 +3 (선형이면 20마리 목표 하나가 표를 다 먹는다).
- 기한(`deadline`)이 있으면 +1.

밴드: **대화**(0) · **수월**(1) · **보통**(4) · **까다로움**(8) · **고난도**(13).

### 3-2. 품삯 배율

표준 완료 선택지 '품삯'은 `payChoiceCoins(q) = round(xp x 12 x 배율 / 100) x 100`.
배율 = 대화 **0.25** / 수월 0.6 / 보통 1.0 / 까다로움 1.3 / 고난도 1.6.

⚖ **0으로 만들지 않는다** — 대화로 끝나는 임무도 이야기를 진행시키고 시간을 쓴다.
다만 **손을 쓴 임무와 같은 액수를 주지 않는다**. 이것이 사용자가 본 위화감의 직접 해소다.

## 6. 잔여

- **대화 전용 임무 70편(38%)** 은 여전히 대화로 끝난다. 이번 차수는 그것을 **정직하게 표기**하고
  **품삯을 낮춘 것**이지 전부 조업으로 바꾼 것이 아니다. 실시스템이 서는 순서대로(불요리 → 농장 → 좌판 운영)
  해당 목표를 `manual` → auto로 옮긴다.
- 초상 아트 폴리시 — 어두운 피부에서 얼굴 가장자리 음영이 세로 줄무늬처럼 읽히는 구간이 있다(계단식 음영의 성질).
- 얼굴형 3종은 턱선 표만 바꾼다 — 이마 폭·광대 위치까지 분화하려면 표를 한 겹 더 둬야 한다.

## 7. 위험 · 부작용

- ⚠ **품삯 금액이 전 퀘스트에서 이동한다**(난이도 배율). 세이브 스키마와 무관하고 이미 받은 돈에는 영향이 없다 —
  **앞으로 고를 선택지의 액수**만 달라진다.
- ⚠ **초상 텍스처 키가 `face_*` → `face2_*` 로 바뀐다.** 런타임 생성이라 세이브 무관이고,
  구 키를 참조하는 곳은 없다(호출부는 전부 `ensureFacePortrait` 경유).
- ⚠ **manual 해제 4건은 진행 중 세이브에 영향이 있다** — 해당 목표가 이제 실제 행위를 요구한다.
  네 건 모두 추적기 실재를 확인했고, N23-2·N20-3은 `placeKey`가 있어야만 닫히므로 함께 채웠다
  (**placeKey 없는 auto `visit`은 영원히 안 닫힌다** — 신규 작성 시 반드시 확인할 것).
- 아티팩트 템플릿의 `.dochead`는 2열 그리드다. 두 열 모두 `minmax(0,1fr)` 계열이어야 한다 —
  `1fr`(= `minmax(auto,1fr)`)로 되돌리면 151차의 390px 가로 넘침이 재발한다.
