## 1. 배경 — 왜 했나

래스터 보강 스펙 v2(`raster_uplift`)는 Antigravity 발주 직전인데, 107차 검토·실기 검증(§5-b)이
스펙에 반영해야 할 3건을 확정해 두고 문서화는 잔여로 남겼다. 스펙 v2 원본 파일은 **레포에 없다**
(Antigravity 발주측 보관 — 레포·상위 폴더·캐시 전수 탐색으로 확인). 개정 내용이 레포 어디에도
정본으로 남지 않으면 발주 시 유실될 위험이 있어, 레포 측 정본 문서로 확정했다.

   **diff 검증 + 정밀화**(폭·두부 형상·이안제·테트라포드 열)로, 우선순위는 Phase 2/오토타일 뒤.
2. **§6 병합 규칙** — "래스터 b vs 추론 b" 4케이스 표(태그 최우선 · 합의 확정 · 추론 단독 유지 ·
   래스터 단독은 103차 가드 통과 시만) + patch.json 최우선 + `raster_b_diff.json` 산출 +
   회귀 기준(바다 비접촉 b 성분 0 · 방파제 도보 도달).
3. **§8-7 개정** — 판정 "교체" 폐기(발판 7,593 → 1,584 = 79% 상실 · 새로 여는 발판 0 —
   107차 실측). 현행 유지 + b/s는 `isFishableStandTerrain` 스폰/입질 **보너스**로
   ([RegionMap.ts:47](../../../packages/core/src/types/RegionMap.ts#L47) — §0.5-2 예약 의도 그대로).

## 5-b. 후속(같은 날) — 스펙 원본 입수·레포 배치 + 블로커 1건 발견

- 사용자가 스펙 v2 전문을 제공 → [.agents/RASTER_UPLIFT_SPEC.md](../../../.agents/RASTER_UPLIFT_SPEC.md)로
  레포 배치. 상단에 **§0.5 개정 노트**(OSM 스펙 관례 — 본문보다 우선) 5항을 달아 개정안과 연결:
  §3-1·3-3·3-4·§9 step 4에 취소선 + 개정 포인터, §6에 4케이스 규칙 포인터, §0-2·§8 준비표에
  107차 완료 반영.
- ~~⚠ 블로커: 루트 `.env` 부재~~ → **같은 날 해소** — 사용자가 루트 `.env`에 CDSE 두 키
  실값 배치(gitignore 확인). "PC마다 .env" 이슈와 동일 맥락이었음(다른 PC 등록분).
- **발주 의도 확정(사용자 원문)**: *"현재 타일셋으로 적용중인 terrains가 부드럽지 않고, 실제
  지도 기반 픽셀이 아니어서 변화를 시도"* + *"내가 적용한 것들을 삭제하거나 제거하지 않고,
  차용할 것들은 차용"*. → 스펙 §0.5 노트 6 신설 + **§9 순서 재배열**(Phase 2 피복이 본체 —
  step 3으로 승격, Phase 1 b diff는 step 4로). 보존 원칙은 §6 병합(patch 최우선·추론 b 유지·
  그림 레이어 불가침)이 구조적으로 보장함을 명문화.
