## 1. 배경 — 왜 했나

조도는 OSM 윤곽으로 초지(`,`) 덩어리 두 개 + 둘레 절차 바위였다(113차에서 "갯바위로 재구현
예정"). 사용자가 **실제 조도 드론 사진**을 주며 "사진이 곧 지도 모양이니 그대로" 적용하라 했다 —
이 방식이 앞으로 섬 갯바위의 표준 문법이 된다.

## 2. 접근 — 무엇을 정했나

- **그리드 32×27** — 요청은 32×24 "정도". 사진 종횡비(2048/1716 = 1.19)를 32×24(1.33)에 맞추면
  왜곡되므로 세로 27로 보존. 타일 = 32px(TR 1:1) → 시트 1024×864.
- **타일셋 정합** — 2px 그레인(맵 규칙) · 팔레트 재채색: 암반은 해안 rock/head 셀 램프 7톤 ·
  초지는 Kenney 잔디 램프 5톤 · **물은 투명**(밑에 깔린 게임 물이 비친다 — 106차 오버라이드 규칙).
  첫 시도(분위 정규화)는 밝은 화강암이 램프 상단에 몰려 **암반 휘도 ≈ 175**로 해안 셀(101~149)보다
  훨씬 밝았다 → **휘도 순위 균등화**로 교체 → 중앙값 **124**.
- **경계 와이어링** — 셀 뭍 비율 ≥ 0.5 = `'.'`(걷기 가능 · 섬 `'.'`은 L1이 얕은 물 베이스) ·
  그 외 `'~'`. 뭍 픽셀 ≥ 5%인 셀은 그림만 얹는다(여·물속 바위). 초지도 `'.'`(`','`면 Kenney 잔디
  베이스가 투명 물 부분에 비친다).
- **본토 보호** — 사진 물이 본토 위에 오면 건너뛴다(68셀). 사진 뭍이 본토에 겹치는 셀 0.
- **시트 1장 + 런타임 슬라이스** — 셀 241개를 파일로 두면 부팅 요청이 241건 늘어난다.
  `ts_jodo_sheet` 1장을 `setTileTex`가 `ts_jodo_r{r}c{c}` 캔버스로 잘라 등록(`ensureSheetCell`).

## 4. 구조상 위치 — 어느 계층의 무엇인가

`S2/S7 필드 → 지역 데이터(patch.json) + 타일셋 시트 → 심리스 L1 오버라이드`. 지형 문자가 바뀌므로
걷기·섬 판정(`computeIslets` 184타일)·낚시 물가 판정이 사진 해안선을 따른다. 코드 변경은 시트
슬라이스 1건 + 절차 장식 3곳의 tileTex 가드뿐 — **다음 섬은 도구 실행 + 시트 이름 등록**으로 끝난다.

## 6. 잔여 — 이번에 안 한 것

- **초지 톤** — 5톤 균등화지만 뭉쳐 보인다(사진 캐노피가 균질). 나무 프롭 몇 그루를 얹으면 입체감.
- **주간 톤 확인** — 검증이 야간이라 램프 최상단(204,195,180)이 낮에 튀는지 사용자 육안.
- 섬 둘레 절차 바위 산포는 유지(사진 셀 밖 물에만) — 과하면 `nearIsletAt` 반경 2→1.
- 다른 섬(812,411 등)·갯바위 해안에 같은 도구 적용 — 사진만 있으면 `--name`·`--center`로.

## 7. 위험·부작용

- **patch.json이 정본** — 사진 블록 32×27 안의 기존 편집(있다면)은 교체된다(이번엔 0건).
  재빌드(`build_osm_tilemap.py`)는 patch를 보존하므로 안전.
- 사진 해안선과 타일 경계가 어긋나는 셀(뭍 30~50%)은 **보이지만 못 밟는다** — 낚시 발판 체감에 영향.
  임계 0.5를 0.35로 낮추면 밟는 면적↑ 대신 물 위를 걷는 느낌↑.
- HSV 분류 임계는 이 사진 기준 — 다른 사진(석양·탁한 물)은 `classify` 조정 필요.
