## 1. 배경

사용자 지시 2건 (스크린샷 1장 동반):

> 캐릭터 만들기 UI 인터페이스를 좀 더 세련되게 재정비(디자인 정합성 고려) 해주고,
> 스토리 아키텍처 V4로 업데이트해줘.
> 그 동안 캐릭터 변경 어떻게 할 지 좀 생각해볼게. (머리가 너무 크고, 얼굴의 눈, 입 표현이 귀엽지 않아서)

- 138차에 신설한 `CharacterCreateScene`은 **기능만 세운 초안**이었다.
- **캐릭터 아트(비율·얼굴)는 이번 차수 대상이 아니다** — 사용자가 검토 중이라 명시적으로 보류했다.

## 2. 원인 — 초안 UI의 실제 문제

실측(138차 화면):

| 문제 | 근거 |
|---|---|
| HUD와 다른 문법 | 패널이 `fillRect` 평면 사각형 2장. 게임의 모든 창은 `paintHudPanel`(외곽·베벨·그라데이션·스터드)를 쓴다 |
| 색을 숫자로 골랐다 | 피부·머리·눈동자·상의·하의가 `3 / 10` 표기. **픽셀 팔레트에는 이름이 없어** 무엇을 고르는지 알 수 없다 |
| 그룹이 없다 | 12행이 한 줄로 이어져 성별·얼굴·머리·복장의 경계가 보이지 않는다 |
| 우측 하단 공백 | 748×560 패널에서 행이 끝나는 y=572 아래가 비어 있고, 안내문은 한 줄로만 깔렸다 |
| 미리보기 빈약 | 바닥·발판이 없어 캐릭터가 공중에 떠 보였다 |

부수 결함: 미리보기 방향 회전(2.4초)마다 `refresh()` 전체를 돌려 **시트 재조회·12행 재계산**을 했다.

### 3-1. 캐릭터 만들기 UI

- **패널 3장을 `paintHudPanel`로** — 미리보기(40,88,430,540) / 외형(486,88,754,540) / 푸터(40,640,1200,64).
  모두 `headerH: 26` 밴드. 배경은 16밴드 그라데이션 + **2px 그레인 도트**(맵 격자와 같은 입자).
- **선택 강조는 색 + 좌측 금색 바**(메인 메뉴 관례). 폰트 교체·크기 변경 없음 → 레이아웃이 흔들리지 않는다.
- **색 견본 스트립** — 팔레트를 실제 색 칸으로 깔고 직접 클릭해 고른다.
  선택 칸은 금테 4변. 수염은 앞에 **'없음' 칸**(사선)을 둔다. 칸 폭은 `min(26, ⌊240/n⌋)`로 자동.
- **2열 5섹션** — 좌열 `체형`(성별·피부) · `얼굴`(눈동자·입·눈썹·볼 홍조) /
  우열 `머리`(모양·색·수염) · `복장`(상의·하의) · `이름`.
- **안내 홈** — 두 열이 끝나는 y 아래 전 폭(716px)에 홈을 파고 "옷 = 장착 아이템" 설명 3줄.
  이름 편집 중에는 입력 안내로 교체된다.
- **미리보기 스테이지** — 바닥 그림자 타원 + 발판 선, 배율 8 → **10**, 아래에 `이름 · 성별` 캡션.
  4방향 줄은 별도 홈 안에.
- **푸터 버튼 3개**는 `paintHudSlot`(호버 시 활성 프레임) + 우측 단축키 안내.
- 방향 회전은 `setFrame`만 교체(전체 리프레시 제거).
- 키보드 `←/→`는 견본 행에서도 동작 — `step()`이 `none` 칸(-1)을 포함해 순환한다.

## 7. 위험 · 부작용

- **없음(기능)** — 캐릭터 생성 씬은 새 게임 경로에서만 열리고, 확정 시 `GameState.setCharacter` 계약은 불변이다.
- 문서 링크 갱신으로 **v3를 가리키던 경로가 v4로 바뀌었다**. 코드 주석의 `STORY_SPEC_v3 §n` 표기는
  134차 당시 기록이라 그대로 두었고, v3 헤더 배너가 v4로 안내한다.
- ⚠ 앞으로 **퀘스트 수·XP·id를 바꾸면 v4 §2·§3 표도 같이 고쳐야 한다.** 코드가 정답이므로
  표가 틀리면 표를 고친다(반대 아님).
