## 2. 원인 · 판단

### 2-1. 이름표 겹침 (실측)

NPC 스프라이트는 `y + (CHAR_CELL − 1 − CHAR_FOOT_Y) × 2`에 원점 (0.5, 1)로 놓인다.
따라서 화면상 **셀 상단 = y − 58 · 머리 꼭대기 = y − 52 · 머리 하단 = y − 34**.
이름표는 `y − 40`(origin 0.5, 1)이라 **머리 사각형 안쪽 12px 지점**에 글자 밑변이 걸렸다.

같은 기전으로 플레이어 위 오브젝트 힌트(`py − 34`)·토스트(`py − 40`)도 머리를 물고 있었다
(플레이어 머리 꼭대기 = `py − 43`).

### 2-2. 시안 적용 가능 여부

**시트 직접 임포트는 택하지 않았다.** 생성 이미지를 확대·격자 측정한 결과
열 피치 97.5px / 행 피치 100px에 스프라이트 폭 49px·높이 91px — 열 기준 배율 3.05배,
행 기준 3.5배로 **격자가 서로 맞지 않는다**(사람이 다시 찍어야 한다). 그 위에

- 프레임마다 형태가 미세하게 달라 걷기 애니가 떨린다,
- 색 수가 수천 개라 2px 그레인 규약이 깨진다,
- **페이퍼돌을 입힐 수 없다**(138차에 해결한 문제로 되돌아간다),
- NPC 41인 결정적 분화가 불가능하다(고정 그림 2장).

→ **대안 채택: 절차 렌더러를 시안 룩으로 재튜닝.** 페이퍼돌·캐스트·생성 화면을 전부 유지한 채
"무엇이 시안을 시안처럼 보이게 하는가"만 옮긴다. 시안 클로즈업에서 읽어낸 네 가지다.

| 시안의 특징 | 141차 코드 | 조치 |
|---|---|---|
| 머리카락이 **이마를 완전히 덮고** 귀 옆까지 내려온다 | 정수리 2행만 덮어 이마가 훤히 드러남 | 덮는 행 4 + 옆머리 y0+5 |
| 머리 실루엣이 **둥글다** | 사각 블록 | 정수리 볼륨 행 + 2단 인셋 |
| 눈이 **검은 세로 바**(흰자 거의 없음) | 눈꺼풀 선 + 홍채 1px | 위 행 동공 / 아래 행 홍채 |
| 테두리가 **부위 색으로 물든다** | 전역 남보라 1색 | 이웃 색 혼합 아웃라인 |

## 3. 변경

| 구분 | 파일 | 내용 |
|---|---|---|
| 수정 | `packages/core/src/art/CharacterArt.ts` | 컬러드 아웃라인 · 머리카락 볼륨 · 눈 재설계 · 팔 폭 · 어깨 이음매 · 모자 왕관 인셋 · 수염 축소 |
| 수정 | `packages/client-pc/src/scenes/RegionFieldScene.ts` | `charTopFromFeet`/`playerLabelY` 신설 + 이름표·힌트 2종·토스트 재배치 |

### 3-1. 컬러드 아웃라인 (`Grid.outline`)

실루엣 바깥 1px을 전역 `OUTLINE` 한 색으로 두르던 것을, **이웃 4픽셀 평균색과 섞어**
(`OUTLINE_MIX = 0.68`) 부위마다 톤이 다른 테두리로 바꿨다. 머리카락 옆은 짙은 갈색,
피부 옆은 짙은 살구, 옷 옆은 짙은 옷색이 된다 — 시안의 부드러운 인상이 대부분 여기서 온다.

### 3-2. 머리카락 (`L_hairFront`)

```
r-1 = 정수리 볼륨(좌우 2px 인셋)   r0 = 본체(좌우 1px 인셋)
r1~r3 = 본체 전폭                  r4 = 앞머리 술 1px 2~3가닥
좌우 1열 = 옆머리(short y0+5 · bob y1−1 · long y1+1 · pony/braid y0+6)
```

`HAIR_CAP_ROWS = 4` · `EYE_ROW = 5` 두 상수가 얼굴 배치의 단일 소스다.
`buzz`만 예외로 이마가 드러나고, **이마가 드러나는 스타일에서만 눈썹을 그린다**.

### 3-3. 얼굴 (`L_face`)

- 눈 = 2px 폭 × 2행. **위 행 전체가 동공(검은 바) · 아래 행이 홍채**, 안쪽 1px만 본색으로 눌러 물기.
- 눈썹 행 폐기(앞머리가 덮는 것이 정상).
- 입은 `smile`도 2px + 입꼬리 1px. 홍조는 `mix(..., 0.32)`로 옅게.
- 수염은 **턱선 한 행**만(입 주변까지 칠하면 복면이 된다).

### 3-4. 몸 (`pose` · `armSeam`)

팔 폭 **3px → 2px**(어깨 폭 16 → 14 = 머리 폭의 1.4배). 팔과 몸통이 같은 색이라
정면/후면에서 한 덩어리로 뭉치던 것은 몸통 바깥 열 1px 그늘(`armSeam`)로 떼어 놓았다.

### 3-5. 라벨 배치

```ts
charTopFromFeet = charFootSink − CHAR_CELL × CHAR_SCALE     // = −58
labelY          = feetY + charTopFromFeet − LABEL_GAP(6)    // NPC: y − 64
```

머리 꼭대기(3행)가 아니라 **셀 상단**을 기준으로 잡았다 — 비니 방울·챙·곱슬 돌기가
머리 사각형보다 최대 3행 위로 나오므로, 머리 기준이면 모자 쓴 인물에서 다시 파묻힌다.

## 4. 구조상 위치

`S23 캐릭터 아트 → 렌더 층`. 계약(셀 32×32 · 머리 9행 · 발바닥 28행 · 정수 ×2)은 **한 글자도 바꾸지 않았다** —
레이아웃·충돌·그림자·자전거 합성은 전부 그대로다. 바뀐 것은 같은 격자 안의 **그리기 규칙**뿐이다.

## 7. 위험 · 부작용

- ⚠ **아웃라인 색이 바뀌므로 모든 캐릭터 텍스처가 새로 구워진다.** 키(`chr_<hash>_<scale>`)는
  설정 해시라 그대로지만, 이전 세션의 구운 텍스처와 픽셀이 다르다(런타임 생성이라 세이브 무관).
- ⚠ **캐스트 해시 규칙은 건드리지 않았다** — 기존 세이브의 NPC "누가 누구인지"는 불변이고,
  같은 인물이 같은 규칙으로 더 예뻐졌을 뿐이다.
- ⚠ 팔이 1px 좁아져 **장갑·소매 렌더 폭도 함께 좁아진다**(같은 앵커를 참조하므로 자동).
  장비 아이콘·페이퍼돌 패널은 같은 렌더러를 쓰므로 어긋남 없음.
- 라벨은 이제 캐릭터에서 6px 위 — 두 NPC가 세로로 아주 가까우면 위 인물의 발치와 아래 인물의
  이름표가 근접할 수 있다(실측 배치에서는 발생하지 않음).
