## 1. 배경 — 왜 했나

111차(주차장 차량 열)가 남긴 밀도 트랙 잔여 4건. 사용자 지시 순서 = ① 열 방향 주축 판정 →
② 도로 밖 `'r'` 지면 톤 → ③ 항만 디테일 → ④ 도로변 평행 주차. 4건이 서로 의존하지 않아
(①④ 차량 배치 규칙 · ② 지면 베이크 · ③ 항만 프롭) 순서대로 한 세션에 처리했다.

부수: 공공데이터 API 키는 사용자 결정으로 **Mock 유지**(급하지 않음). CDSE는 사용자가 새 값으로 교체.

## 2. 원인 — 무엇이 문제였나

- **① 가로 행 고정** — 111차는 행 `r%4`로만 배치해 세로로 긴 주차장에서 열 방향이 틀렸다.
  성분 PCA를 보류한 이유(청크 경계 결정성)는 **전역 1회 계산**으로 풀린다.
- **② tan 베이스** — 도로 밖 `'r'`(109차 래스터 광장)이 Kenney tan 베이스 그대로라 흙바닥으로 보였다.
- **③ 항만 프롭 부재** — `'b'`에만 계선주가 있고 어선은 수동 프롭뿐. 그런데 **항만 광장·부두 상판은
  109차 이후 대부분 `'r'`**이라 안벽 판정에 `'r'`이 빠지면 규칙이 통째로 침묵한다(실측: 어선 1척·크레인 0).
- **④ 길가 주차 없음** — 참고 이미지의 연석 라인 차량이 없었다.

## 3. 변경 — 어디를 어떻게 ([SeamlessChunks.ts](../../../packages/client-pc/src/scenes/SeamlessChunks.ts))

| 구분 | 위치 | 내용 |
|---|---|---|
| 신설 | `computeLotAxis` (`lotAxis`) | 도로 밖 `'r'`을 **5×5 침식** → 4-연결 성분 bbox 종횡비(h ≥ 1.35w = 세로 행) → 반경 2 팽창. 침식이 폭 ≤ 4 도로 회랑을 지워 성분이 도로에 끌리지 않는다. 지형 로드·`invalidateTiles`에서 재계산 |
| 수정 | 주차장 차량 열 | `lotAxis==2`면 열 `c%4`·칸 `r%2` + **측면 프레임(left/right)**, 아니면 기존 행 `r%4`·칸 `c%2` + 정면/후면 |
| 신설 | `ensurePlazaTextures` (`kn_plaza_0/1`) | 콘크리트 톤 2px 그레인 2변형(`COL.plaza/plazaAlt/plazaStain` + 셀 좌/상 이음 1줄). **L1이 `'r'` 위에 얹고 벡터 밴드가 회랑을 덮는다** → 밴드 밖 `'r'`만 콘크리트 |
| 수정 | `drawRoadBands` 아스팔트 반점 | `roadBand` d ≤ halfW인 `'r'`만 — 광장에 아스팔트 반점 금지 |
| 신설 | `computeHarbor` (`harbor`) | `waterDist ≤ 6` 물 중 4방향 광선(14타일)이 **3개 이상 뭍에 닿는** 둘러싸인 물 = 항 내측·석호. 외해 쪽은 제외 |
| 신설 | 정박 어선 열 | 항만 수역 ∧ 안벽(`.`/`b`/`w`/**`r`**) 인접 ∧ 바다 쪽 2타일 여유. E-W 안벽 3타일 간격 접현 · N-S 안벽 2타일 간격 선수 접안 · 점유 0.55 · 좌우 반전 해시 · `free`(충돌 없음) |
| 신설 | 하역 크레인 `smx_crane` + `PROP_DEFS 'crane'` | 44×66 절차 베이크(받침·마스트·노란 지브·후크·카운터웨이트). 안벽 위 `(c+r)%9` ∧ 해시 0.35 ∧ 이웃 뭍 ≥ 3 ∧ 밴드 밖 |
| 수정 | 계선주 | `'b'`뿐 아니라 항만 수역에 면한 `'.'/'w'/'r'` 안벽에도 4타일 간격 |
| 신설 | 도로변 평행 주차 | w ≥ 3 · 비회전교차로 · **축 정렬 세그먼트만**(3/4 시점 회전 금지) · 끝단 3타일 물림 · 2.8타일 간격 · 점유 0.25 · 연석 안쪽 `halfW−0.6` · 차량 중심이 속한 청크가 배치 · 바닥 앵커 유지(y-sort) |

## 4. 구조상 위치 — 어느 계층의 무엇인가

`S2/S7 필드 → 심리스 렌더 → 프롭 자동 산포 + L1 베이스`. 렌더 층만 — 지형 데이터·판정 무변경.
파생 맵 2종(`lotAxis`·`harbor`)은 `waterDist`·`islet`과 같은 층(로드 시 전역 1회, 편집 시 재계산).

## 6. 잔여 — 이번에 안 한 것

- 주차선(흰 칸 라인) 마킹 — 차량만으로 충분한지 육안 후 결정(111차 이월).
- 광장 이음선이 **1타일 격자**로 읽힐 수 있다(5m 슬래브) — 거슬리면 `kn_plaza` 이음 알파를 낮추거나 4타일 주기로.
- 어선 정박은 항만 수역 판정(광선 3/4)에 의존 — 좁은 만입부·하구는 누락될 수 있다. 수동 프롭으로 보완.
- 크레인 밀도(≈14기)는 어항 기준으로 잡았다 — 상업항 확장 시 상향.

## 7. 위험·부작용

- **도로변 주차 차량은 주행 차량(TrafficSystem)과 시각적으로 겹칠 수 있다** — 연석 차로가 곧 주행 차로인
  주택가(w3)에서 특히. 점유 0.25로 낮췄고, 거슬리면 w ≥ 4로 제한.
- 주차·크레인 = 충돌 프롭. 어선은 `free`(충돌 없음 — 물 위).
- 파생 맵 계산이 로드에 추가됨(76만 타일 × 5×5 + 광선) — 체감 지연 없음.
- `'r'`을 안벽으로 인정하므로 래스터 광장에 면한 항만이면 어디든 어선이 선다(사용자 편집 `'r'` 포함).
