## 1. 배경 — 왜 했나

사용자 리포트 원문:

1. *"조도(섬)에는 왜 차가 있는 거지? … 갯바위 지형으로 할 거니까, 차는 없애."*
2. *"도로 위에 차가 정지해있는데, 이건 다 없애줘. 차량의 배치는 도로가 아니어야 해."*
3. *"너무 많은 차들이 배치되어 있어. 실제 랜더링되는 화면(seamless 기준)에서 1대 정도만 보이도록."*
4. *"주차장 같은 공간으로 인식되는 부분이 있다면, 거기에는 차량이 40~70% 정도로 랜덤하게."*

## 2. 원인 — 무엇이 문제였나

- **①은 차가 아니라 어선이었다** — 조도(274,532) 실렌더 확인: 차량 0대, 대신 **112차 정박 어선이 섬
  육지 위로 올라타 있었다**. `computeHarbor`가 섬 둘레 물도 "둘러싸인 물"로 잡고(광선 4방향이 섬 자신에
  닿는다), 앵커 오프셋이 N-S 안벽에서 **36px를 뭍으로 밀어 넣었다**(선체 88×52px · 바닥 앵커).
  섬 타일 지형 분포도 실측: `,` 251 · `b` 80 · `w` 34 · `.` 19 — **`'r'`은 0개**라 주차 규칙은 애초에 무관했다.
- **②** 112차에 넣은 **도로변 평행 주차**가 원인. 연석 안쪽(`halfW−0.6`)은 곧 주행 차로라
  "도로 위에 정지한 차"로 보였다.
- **③ 진짜 주범은 주차장 열 규칙의 적용 범위** — 112차는 **도로 밖 `'r'` 전부**(실측 16,630타일)에
  점유 0.66으로 열을 깔았다. 광장·매립지·항만 에이프런이 전부 주차장이 되어 화면이 차로 뒤덮였다
  (실측: 동명항 35대 · 항만 24대). 성분 크기 분포에서 2,174타일(78×82)·1,253타일(16×90) 같은
  **비(非)주차장 대형 면**이 상위를 차지했다.
- **④** OSM 캐시에 `amenity=parking` 태그가 **0건**(fetch 쿼리에 없음) → 휴리스틱 검출이 필요.

## 3. 변경 — 어디를 어떻게 ([SeamlessChunks.ts](../../../packages/client-pc/src/scenes/SeamlessChunks.ts))

| 구분 | 위치 | 내용 |
|---|---|---|
| 신설 | `computeParkingLots` (`parkLot`·`lotFill`) | 도로 밖 `'r'` 코어(3×3 ∧ 밴드 밖 ∧ **섬 제외**) 4-연결 성분 중 **주차장처럼 생긴 것만**: 40~700타일 · bbox 채움률 ≥ 0.5 · 최소 변 4 · 5타일 내 차도(진입로). 성분마다 **목표 점유율 0.40~0.70** 해시 배정 |
| 수정 | 주차장 차량 열 | `parkLot === 0`이면 배치 안 함 · 점유율은 `lotFill[id]`(구역별) |
| 삭제 | **도로변 평행 주차**(112차) | 지시 2 — 연석 안쪽 = 주행 차로라 도로 위 정차로 보였다 |
| 수정 | 건물 옆 주차 | 섬 제외 + 확률 **0.03 → 0.04**(주차장 열이 빠진 만큼 노상은 유지 — 실측 후보가 화면당 0~37개로 편차가 커 이 값이 "가끔 한 대") |
| 수정 | 정박 어선 | **섬 둘레 2타일 제외** · 앵커 재계산(E-W `r+0.5`/`r−0.1` · N-S `r+0.3`) — 안벽에 ≤ 8px만 물리고 선체는 물 위 |
| 수정 | 생성자 초기화 순서 | `computeParkingLots()`를 **`indexRoads()` 뒤로** — `roadBand`가 `roadsByChunk`를 쓰므로 앞에 두면 접근성 판정이 전부 false(구역 0개·차량 전멸). 실측으로 발견 |

## 4. 구조상 위치 — 어느 계층의 무엇인가

`S2/S7 필드 → 심리스 렌더 → 프롭 자동 산포`. 렌더 층만 — 지형·판정 무변경.
`parkLot`/`lotFill`은 `lotAxis`·`harbor`와 같은 **전역 파생 맵**(로드 1회 + `invalidateTiles` 재계산).

## 6. 잔여 — 이번에 안 한 것

- **조도 갯바위 재구현** — 사용자 예정(바위 지형 + 중앙 고지 초지). 현재는 초지 + 둘레 실사 바위.
- OSM `amenity=parking` 재fetch — 있으면 휴리스틱을 데이터로 대체할 수 있다(현재 캐시엔 0건).
- 주차선(흰 칸) 마킹 · 대형 광장(2,174타일)의 용도 부여(공터로 둘지 다른 프롭으로 채울지).

## 7. 위험·부작용

- 주차장 판정이 **휴리스틱**이라 실제 주차장인데 크기·형상 기준을 벗어나면 비게 된다(대형 항만
  주차장 등). 반대로 창고 앞 포장 마당이 주차장으로 잡힐 수 있다 — 육안 확인 대상.
- 112차에서 만든 도로변 주차가 사라져 **길가가 비어 보인다**(사용자 지시대로). 필요하면 연석
  **바깥**(보도 쪽) 배치로 되살릴 수 있다.
- 파생 맵이 하나 늘었다(로드 시 성분 라벨링 1회) — 체감 지연 없음.
