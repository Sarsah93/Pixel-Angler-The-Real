## 1. 배경 — 왜 했나

사용자 원문:

> "물때 단계 HUD 칩도 추가해줘.
> 너무 밑걸림 확률이 높아 퀘스트 원할 진행이 어려움. 퀘 최초 1회 진행 시 고려해달라는 QA 요청이 있었음.
> 채비손실정도 어떻게 반영되고 있는 지 점검해줘. 밑걸림에서 바늘만 잃을 확률, 봉돌과 바늘 다 잃을 확률 등.
> 채비트리 변경에 따른 교차 검증 필요."

- 205차 잔여였던 물때 단계 HUD 칩을 넣는다.
- 낚시 어획 목표가 있는 퀘스트를 **처음** 진행할 때는 밑걸림을 줄인다.
- 밑걸림·줄 터짐·복어 절단에서 채비가 실제로 무엇을 잃는지 192차 채비 트리와 맞대어 점검한다.

## 2. 원인 — 무엇이 문제였나

### 2-1. 채비 손실이 트리를 몰랐다

손실은 평면 9칸(트리의 투영값) 이름 목록(`loseRigParts(['leader','sinker','hook','bait'])`)으로 처리됐다.
192차 트리 도입 뒤로 칸의 부모·자식 관계와 간편 채비(묶음추·카드·타이라바·루어)를 보지 못했다.

확정 근거: 하네스 `scratchpad/r206loss.cjs` — 채비 7종 × 원인 7종(밑걸림 4 · 목줄 터짐 · 찌 위 터짐 · 복어 절단),
가방 수량 변화와 비워진 칸을 기록(`r206loss_before.json`).

| 채비 | 수정 전 실측 | 문제 |
|---|---|---|
| 루어(메탈) | 도래 아래 · 통째로 · 줄 터짐 · 절단 → **목줄 스풀만** 잃음 | 목줄 칸을 먼저 비우면 그 아래 루어 칸이 풀려, 뒤이은 `loseLureRig()`가 `_lure` 없음으로 **루어 무손실** |
| 전 채비 | 목줄이 터질 때마다 **150m 스풀 1개** 소모 | 묶는 길이만 잘려야 한다 |
| 원투(유동 봉돌) | 「도래 아래」에서 **유동 봉돌**도 잃음 | 원줄에 꿴 봉돌은 도래 위다 |
| 묶음추 | 「바늘과 미끼」 = 미끼 1개만 · 키트 유지 | 다른 바늘 미끼는 공짜로 남았다(바늘은 키트에 고정) |
| 카드 채비 | **어떤 결과에도 키트·미끼 무손실**(통째로 = 도래만) | 카드 채비를 쓰면 밑걸림 비용이 0이었다 |
| 타이라바 | 바늘 2개 중 1개 · 도래 아래에서도 헤드·스커트·넥타이 무손실 | 바늘 칸이 둘인 걸 몰랐다 |
| 전 채비 | 「통째로」에서 **원줄은 1m도 안 줄었다** | — |
| 전 채비 | 잃은 칸을 **재고가 남아도 비움** → 매번 다시 채비 | 155차 잔여 「채비 고정 중 부품 손실」과 같은 뿌리 |

> 지그헤드·웜 채비는 상점 품목이 없어 수정 후 감사에서 뺐다(수정 전에는 목줄 스풀만 잃었다).

### 2-2. 밑걸림 확률 모델(변경 없음 — 점검 결과)

- 발생: 여 밭에서 채비를 세워 둔 채(견제 없음) 위험 배율 `risk`만큼 타이머가 쌓이고,
  5초(유예)를 넘으면 초당 `0.25 × risk`로 걸린다(`BiteProbabilityEngine`).
- 기대 시간 ≈ `(5 + 4) / risk` 초 — 보통 자리 9초 · 위험 자리(×1.6) 5.6초 · 테트라포드 구멍치기(×2.2) 4.1초.
- `risk` = 자리(0.6/1.0/1.6) × 루어 × 강수 × 구멍치기(테트라포드 2.2 · 사석 1.7) × 원투 봉돌 구름(205차) × **퀘스트 첫 진행(206차)**.
- 대처 선택(136차 `GearDurability`):

| 대처 | 결과 | 확률 |
|---|---|---|
| 끌어당기기 | 통째로 빠져나옴(무손실) | 10% |
| | 미끼만 | 10% |
| | 바늘 + 미끼(끝채비) | 30% |
| | 통째로 뜯김 | 50% |
| 끊기 | 도래 아래 | 50% |
| | 통째로(원줄) | 50% |

「바늘만」 · 「봉돌과 바늘 다」 잃을 확률(206차 손실 규칙 기준 — 밑걸림 1회):

| 채비 (봉돌) | 대처 | 미끼만 | 바늘(+미끼)만 · 봉돌 남음 | 봉돌 + 바늘 |
|---|---|---|---|---|
| 찌 (좁쌀봉돌) | 끌어당기기 | 10% | 0% | 80% (끝채비 30 + 통째로 50) |
| | 끊기 | 0% | 0% | 100% |
| 원투 (유동 봉돌 — 도래 위) | 끌어당기기 | 10% | 30% | 50% |
| | 끊기 | 0% | 50% | 50% |
| 묶음추 · 카드 (봉돌 = 키트) | 끌어당기기 | 10% | 0% | 80% |
| | 끊기 | 0% | 0% | 100% |
| 타이라바 (헤드) | 끌어당기기 | 10% | 30% | 50% |
| | 끊기 | 0% | 0% | 100% |

- 나머지는 무손실(끌어당기기 10%).

**손실 규칙(원인 → 떨어져 나가는 범위)**:

| 원인 | 범위 |
|---|---|
| 미끼만 | 걸린 바늘의 미끼(없으면 맨 아래 미끼 칸) |
| 바늘 + 미끼 | 단품 바늘 = 바늘 전부 + 그 미끼 + 같은 목줄 끝 좁쌀봉돌 · 타이라바 = 바늘 2 + 미끼 · 묶음추/카드 = **한 벌 전부**(키트 + 미끼) · 루어 = 루어 |
| 도래 아래 · 목줄 터짐 · 복어 절단 | 도래(없으면 매듭) 아래 전부 · 목줄은 **1.5m만** |
| 통째로 · 원줄 터짐 | 원줄 부속(찌 · 수중찌 · 유동 봉돌 · 도래)부터 아래 전부 · 원줄 **8m** · 목줄 1.5m |

- 줄은 쓴 길이(`lineUsedM`)를 쌓고 스풀 길이(기본 100m · 품목 `lineLengthM`)에 닿으면 그 스풀 1개가 사라진다.
- 손실 뒤 `syncTreeWithItems()` — **재고가 남은 칸은 그대로 끼워져 있다**(다시 채비하지 않아도 된다).

**퀘스트 첫 진행 완화**: 진행 중 퀘스트 중 `everDone`에 없고, 낚시(`method` 없음/`rod`)로 잡기·놓아주기 목표가
열려 있으면 1인칭 `snagRiskMult × 0.3`. 기대 밑걸림 시간 9초 → 30초 · 테트라포드 4.1초 → 13.6초.
퀘스트를 한 번 끝내면 반복 진행에서는 원래 값.

**물때 칩**(상태 패널 바로 아래 · 상태이상 띠는 그 아래로):

- 누구나 — 물결 아이콘 + 단계 이름(물때표로 알 수 있는 정보) · 회색 테두리 · 툴팁 = 물 방향.
- 「물때 감각」 — `만조 물돌이 · 25분 뒤 초날물` · 테두리 = 입질도 별 색(4.5↑ 금 · 3.5↑ 초록 · 3↑ 파랑) · 툴팁 = 단계 한마디 + 남은 분.
- 좁은 단계(소)에서 넘치면 `High-water slack · 23 min`처럼 다음 단계 이름을 뺀다(말줄임이 숫자를 먹지 않게).
- 홈타운은 숨김(물때가 없다).

## 4. 구조상 위치 — 어느 계층의 무엇인가

- `낚시 → 채비 손실` — **판정은 core**(`planRigLoss` · 순수 함수 · 트리만 본다), 적용은 client `InventoryStore`(가방 · 재장착).
  1인칭의 3경로(밑걸림 · 줄 터짐 · 절단)가 같은 계획기를 탄다.
- 확률표(`SNAG_PULL_UP`·`SNAG_BREAK_OFF`)와 발생 모델은 **바꾸지 않았다** — 무엇을 잃는가만 고쳤다.
- 퀘스트 완화는 **1인칭 위험 배율 한 항**(`snagQuestMult`) — 확률표는 그대로라 「잃으면 무엇을」은 같다.
- 물때 칩은 HUD 렌더 층 — 판정은 204차 `tideFlowStateAt` · 스킬 게이트는 204차 `fish_tide`.

## 6. 잔여 — 이번에 안 한 것

- **끌어당기기 「통째로 50%」** — 136차 사용자 확정값이라 두었다. 원줄 8m가 함께 사라지는 지금은 체감이 더 클 수 있다.
  실검증에서 무거우면 F8 없이 표 값만 바꾼다(`SNAG_PULL_UP`).
- 퀘스트 완화 0.3은 초안 — `TUNING.snag.questFirstMult`(F8).
- 지그헤드 · 웜 채비 손실은 상점 품목이 생기면 감사 하네스에 다시 넣는다(규칙은 `lure` 범위로 이미 처리).
- 스풀 남은 길이가 캐스팅 비거리를 막지는 않는다(원줄 92m 남아도 100m 던질 수 있다) — 원투 비거리 상한과 묶을지 결정 필요.

## 7. 위험·부작용

- **카드 채비 · 묶음추 손실이 커졌다** — 전에는 사실상 무손실이었다. 이제 바늘이 뜯기면 한 벌을 버린다(현실과 같음).
- 루어도 이제 실제로 사라진다 — 루어 낚시 비용이 처음으로 생겼다.
- 목줄 · 원줄은 스풀째가 아니라 길이로 줄어 **줄 비용은 크게 줄었다**(150m 목줄 = 100번 터짐).
- 퀘스트 완화는 진행 중 퀘스트가 하나라도 조건에 맞으면 켜진다 — 퀘스트를 받아 두고 다른 곳에서 낚아도 0.3.
- 칩은 상태 패널과 따로 움직이지 않는다(같은 `statusOffset`) — 패널을 끌어도 따라온다.
