## 1. 배경 — 왜 했나

사용자 원문:

> "우선, 실내 2단계 인물 집부터 진행해줘."
>
> "NPC가 밖에서 상점처럼 상호작용 되고 있는 부분들 + 탑다운 땅바닥에 날 것의 'o' 표시와 함께,
> 상호명이나 건물명이 붙어있는 경우들이 있는데, 그걸 좀 개선하고 싶어. 어떻게 하면 좋을까?"
>
> "주점 POI가 없다고 하는데, OSM 상 찍히지 않는 것인지 확인할 필요가 있을 것 같아. 실제로는 속초에 주점들이 많이 있어.
> 내가 어떻게 POI 정보를 주면 되?"

214차 §6에서 확정한 실내 공간 3단계(① 가게 · 보건소 · 위판장 → ② 인물 집 → ③ 아파트) 중 2단계다.
뒤의 두 질문은 **조사 + 제안**만 했다(구현은 사용자 결정 뒤).

## 2. 원인 — 조사에서 확정한 것

### 2-1. 인물 집

| 항목 | 조사 결과 |
|---|---|
| 집 문 | 214차 `buildNpcDoor` — 집에 있으면 문 위 채광창이 켜지고 [F] 「문 두드리기」 → `openDialogue(id, 까닭)` |
| 집이 있는 인물 | 7명(정옥선 · 어촌계 사무실 · 도현수 · 강두철 · 탁만수 공방 · 탁새벽 살림채 · 배누리 민박). 바람 · 오세찬은 24시간 밖 |
| 어촌계 사무실 | 214차 대사가 「당직 계원이 문을 연다 — 계장님은 퇴근하셨어요」라 **안으로 들이면 대사와 어긋난다** → 문 앞 유지 |
| 일과 재평가 | `updateFieldNpcs`는 실내에서도 돈다 → 손님이 안에 있을 때 일과가 바뀌면 주인이 밖에도 생긴다 → 막아야 한다 |

### 2-2. 바닥 점 · 밖의 상인 (서브에이전트 조사 — 코드 수정 없음)

- **바닥의 「o + 상호명」 = OSM POI 마커 하나**(`loadChunkPois` `RegionFieldScene.ts` 1926~1944) — `add.circle` 반지름 3.5 + 9px 이름표.
  - 설정 「장소 이름표」(기본 꺼짐)를 꺼도 **거래 가능하고 그림이 없는 가게 167곳**에 이름 없는 노란 점이 남는다
    (음식점 54 · 카페 45 · 편의점 40 · 생활용품 12 · 마트 11 · 약국 5). 켜면 상호명 + 거래 불가 장소 89곳의 하늘색 점.
  - 설정 변경 이벤트(`field-labels-changed`)를 받는 곳이 없어 지역에 다시 들어가야 반영된다.
- **「밖에서 장사하는 NPC」로 보이는 것** — 실제로 NPC가 거래창을 여는 경로는 0이다.
  - 대화창의 「물건을 볼 수 있을까요?」는 `shopId`를 채운 인물이 0명이고 `onTrade` 콜백도 늘 비어 있다(죽은 코드).
  - 원인은 **노점 그림 + 문 옆 장식 상인 + [F] 들어가기** 조합이다. 다이소 2곳 · 제이마트 · 활어센터 3곳 등 10곳이
    길가 **노점 그림**(`ts_gem_popup_*`)으로 서고, 옆에 `vendor` 장식 인물이 서며, [F]는 「상호 — 들어가기」 → 실내 방.
    노점에 「들어가기」를 하면 방이 열리는 의미 불일치다. `market`인데 위판장 이름이 아니면 낚시점 실내가 열린다.
- 구 타일맵 `drawPois`(부산 8맵)는 종류를 돌려가며 가짜 배정 + 이름표를 늘 그린다.

### 2-3. 주점 POI 0곳

| 단계 | 누락 |
|---|---|
| 수집 `tools/fetch_region_osm.py:43` | Overpass amenity 목록에 `pub|bar|biergarten`이 없다 — **캐시에 들어오지도 않는다** |
| 변환 `tools/build_osm_tilemap.py` `POI_TAGS` · core `PoiType` | pub · bar 매핑 없음 |
| 클라 `poiBuildingKind` | `shop=alcohol|beverages|pub`만 `pub` — amenity 쪽은 없음 |

- 레포 캐시 실측: `amenity=pub/bar` 0건(질의에서 빠져서 — 「속초에 없다」의 근거가 아니다) · `shop=alcohol` 0건(실제로 없음).
- 술집 성격 후보는 `restaurant`로 들어온 「현이네포차」 · 「용신포차」, 치킨집 2곳뿐. 호프 · 이자카야 · 투다리 0건.
- Overpass 재질의는 원격 컨테이너에서 403(프록시) — 129차 병원 backfill과 같다.
- 영업시간은 가게별이 아니라 종류별(`BUILDING_HOURS`, pub 10~22시)이고, 자정을 넘는 시간(17~02시)을 처리하지 못한다.

## 4. 구조상 위치

`월드(필드) → 건물 실내 → 2단계 인물 집`. 층으로 보면 **렌더 + 판정**이다.

- 대화 · 의뢰 · 일과 계약은 바꾸지 않았다 — 집 안은 같은 대화창을 여는 새 자리다(R12: 일과는 만나는 곳만 바꾼다).
- 세이브 필드 없음(불러오면 문 앞).
- 3단계(아파트)는 같은 `home` 틀에 호수별 변형을 더하는 순서다.

## 5. 검증

하네스: `scratchpad/r216.cjs`(ko/en) · `cap216.cjs`(그림) · `annot216.py`.
일과 시각은 `devRoutineClock`으로 고정(화요일 20:30 = 쉬는 시간 · 23:10 = 잘 시간).

| 대상 | 결과 |
|---|---|

| 문 앞 선택지 23:10 | 정옥선 「— 문 두드리기」(잘 시간은 들이지 않는다) |
| 집 6곳 입장 | 이름판 = 집 이름 · `interiorAt.npcId` · 액자 392~912 × 158~582(공방 344~960 × 134~606) |
| 말 걸기 | 6곳 모두 `nearNpc` = 주인 · 힌트 「[F] 말 걸기」 · `DialoguePanel` `atDoor 'inside'` · 첫마디 = `NPC_HOME.talk` |
| 앉기 | 방석 · 의자 · 소파 6곳 모두 `seated` true |
| 일과 고정 | 집 안에 있는 동안 10:00으로 돌려도 주인 `atHome` 유지(일하러 나가지 않는다) |
| 첫 입장 가이드 | `interior_home` 1/2 — 주인 하이라이트 + 말풍선 |
| 겹침 · 오류 | `[ScreenOverlap]` · `[TextOverflow]` 0 · pageerror 0(ko · en) |
| 영문 | 이름판 「Jeong Ok-seon's house」 · 「[F] Talk」 · 첫마디 영문 |

- 1차 실렌더에서 민박 이불장이 할머니 집과 같은 자개장으로 그려졌다(「장판 방 = 자개장」 규칙) → 자개장은 정옥선 집만.
- 도움말 그림 1차는 내가 주인 바로 앞(아래)에 서서 주인을 가렸다 → 왼쪽 옆에 세워 다시 찍었다.
- `visitHome`의 550ms 지연(똑똑 → 문 열림)은 헤드리스에서 돌지 않아 하네스는 `enterNpcHome`을 바로 부른다.

## 6. 잔여

- **바닥 점 · 노점 그림 정리(제안 — 사용자 결정 대기)**:
  - ① 바닥 점 167곳 폐지 → 가게는 **건물 앞 작은 간판(픽셀 아이콘 판)** 으로, 상호명은 다가갔을 때 [F] 안내에만. 「장소 이름표」 설정은 미니맵 · 전체 지도 핀만 바꾼다.
  - ② 노점 그림은 **진짜 노점 · 좌판만**(시장 안 좌판 · 활어센터 앞 좌판) — 다이소 · 마트 · 편의점은 건물 그림 + 문.
  - ③ 노점에서는 「들어가기」 대신 **좌판 앞 [F] = 바로 거래**(상인이 있는 곳 = 사람과 말하는 흐름), 실내가 있는 건물만 「들어가기」.
  - ④ 대화창의 죽은 「물건을 볼 수 있을까요?」는 ③을 할 때 좌판 상인에게 배선하거나 지운다.
- **주점 POI**: 사용자가 CSV(상호 · 위도 · 경도 · 종류 · 영업시간)를 주면 → 수집 질의 · 변환 매핑 · 클라 매핑 3곳에 pub/bar를 넣고
  `pois.json`에 병합(129차 병원 backfill 방식). 가게별 영업시간(자정 넘김 포함)은 `RegionPoi.hours` 신설이 필요하다.
- **아파트(3단계)**: 착수 조건 = 사용자 지시.
- 다른 지역 인물의 집(무대가 열릴 때). 집 안 창 · 조명은 시각을 따르지 않는다.

## 7. 위험 · 부작용

- 문 앞 [F]가 이제 바로 들어간다 — 214차 「문 두드리기」 문구는 잘 시간 · 어촌계 사무실에만 남는다.
- 손님이 집 안에 있는 동안 그 사람의 일과는 멈춘다(나오면 다음 5초 재평가에 일터로).
- 집 안에서 장면(컷씬)이 시작되면 215차 규칙대로 겹층을 걷고 밖에서 진행한다 — 주인은 `npcStepOut`으로 문 앞에 선다.
- 대화 중 의뢰를 받거나 끝내면 방 안 머리 위 표시도 600ms 안에 바뀐다(`refreshQuestMarkers` 동기화).
