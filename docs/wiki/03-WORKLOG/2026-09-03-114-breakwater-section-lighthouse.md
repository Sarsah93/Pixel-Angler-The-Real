## 1. 배경 — 왜 했나

사용자: *"캡처 1(인게임)과 캡처 2(위성) 간 차이를 최대한 없애고 싶어. 테트라포드 방파제 + 등대."*
인게임 방파제는 **넓은 콘크리트 판 + 갈색 사석 블록**으로만 보였고, 위성 사진은 **좁은 상판 양쪽에
테트라포드 피복, 둥근 두부에 등대**다. 청호동뿐 아니라 속초의 모든 방파제가 대상.

## 2. 원인 — 무엇이 문제였나

- **지형에 단면 정보가 없다** — 방파제는 `'b'`(+상판 자리 일부 `'.'`) 한 문자. 106차가 자동
  사석/테트라포드 규칙을 폐기한 뒤로는 `coastPierKey`가 상판 셀만 깔아 **전부 콘크리트 판**이었다.
  `'.'` 상판 자리는 Kenney tan 벽돌이라 방파제 위에 보도가 얹힌 것처럼 보였다.
- 청호동 지형 실측: 폭 ≈ 10타일(위성 ≈ 8) — **기하는 대체로 맞고 표현이 문제**였다. `waterDist`는
  물 타일 전용(뭍은 0)이라 단면 거리로 못 쓴다.
- **등대가 없었다** — `pois.json`은 이름 있는 `man_made=lighthouse`만 수록(속초등대·조도등대).
  방파제 두부 등대 3개는 이름 없는 `seamark:type=light_minor` 노드라 파이프라인에서 빠졌다.
- 105차 자동 규칙(`raysToOpenSea`)을 106차에 사용자가 폐기한 건 **"방파제 한 문자에 시트 전체가
  쏟아져 난잡"**했기 때문 — 이번엔 시트가 아니라 **단면 거리**로 3종만 배정한다.

## 4. 구조상 위치 — 어느 계층의 무엇인가

`S2/S7 필드 → 심리스 렌더 → L1 베이스 + 프롭 자동 산포`. `bwClass`는 `harbor`·`parkLot`과 같은
**전역 파생 맵**(로드 1회 + `invalidateTiles`). 지형 문자·판정은 무변경(피복 위도 걷기 가능 =
테트라포드 낚시). `lights.json`은 `pois.json`과 같은 층의 지역 데이터.

## 6. 잔여 — 이번에 안 한 것

- **방파제 안 모래(`'s'`)·tan 패치** — 래스터 분류 잔존(동방파제·대포항 두부). 흡수 규칙에 `'s'`를 넣으면
  뿌리 쪽 해변이 먹힐 수 있어 제외. 편집기로 `'b'` 덧칠이 안전.
- 두부 **원형 확장**(위성의 둥근 테트라포드 마운드) — 지형 기하에 의존. 필요하면 파이프라인에서 두부 팽창.
- 등대 **야간 발광**(회전 광선·글로우) — 씬 조명 체계(`lightBuildings`)에 프롭 연동 자리 없음.
- 피복 타일 2변형(a/b) 반복감 — TTP 시트에 셀이 더 오면 확장. 좌우 반전은 RT `batchDraw`가 미지원.
- 다른 지역: `py tools/extract_lights.py <region>` + `SEAMLESS_REGIONS[].hasLights` (add-region 스킬에 추가).

## 7. 위험·부작용

- 방파제 판정이 **외해 비율 휴리스틱** — 항 내측 안벽인데 외해에 많이 면하면 피복이 생기고, 반대로
  항만 안쪽 방파제(외해 비율 < 0.35)는 상판만 남는다. 육안 확인 대상.
- 상판 `'.'` 흡수는 8이웃 b/./물 조건으로 막지만, 방파제 뿌리의 포장 광장이 `'.'`뿐이면 몇 타일이
  상판으로 바뀔 수 있다(청호동은 정상).
- TTP 타일은 TR 32 전용(`ttpReady`) — legacy 20px 맵은 상판 폴백.
