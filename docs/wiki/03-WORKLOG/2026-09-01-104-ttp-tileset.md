## 1. 배경 — 왜 했나

103차 잔여로 남겨둔 **"테트라포드 변형·갯바위 시트·호안 캡 = 사용자 제작 중 (도착 시
`pixelazed/tileset/` 등록 + 교체)"** 의 1차 납품분이 도착했다.

103차의 테트라포드는 Gemini 생성 원본(`ts_gem_tetra`, 124px)을 1.75타일로 **최근접 축소**해
타일당 1장씩 흩뿌린 것이라, 실사(소형 유닛이 겹겹이 쌓인 사면)와 거리가 있었다.

## 2. 원인 — 두 PNG는 타일 시트가 아니다

두 파일은 **라벨이 붙은 목업 스크린샷**이지 격자 시트가 아니다. 실측으로 확정:

- 셀 크기가 불균일 — sheet1은 55×60 / 55×50, sheet2는 64×64 (테두리 1~2px 포함).
- JPEG류 압축 노이즈 — 72×72 스프라이트 1장에 **고유색 1,531개** (실제 도트는 5~7색).
- 유일하게 깨끗한 원본은 sheet2의 **투명 TTP**(알파 이진 0/255) — bbox (679,34)-(750,105).
- sheet1은 제목이 "TTP Base"지만 실제 육지 색은 **모래 베이지**(219,197,148) = 해변↔물 접경.
  콘크리트 베이스(144,145,140)는 sheet2에 따로 있다.

따라서 "크롭해서 그대로 쓰기"는 불가 — **경계 실측 → 크롭 → 리샘플 → 팔레트 양자화**가 필요했다.

## 4. 구조상 위치 — 어느 계층의 무엇인가

`S2/S7 필드 → OSM 심리스 → 지형 품질`. **파이프라인(에셋 생성) + 클라이언트 렌더 층**만
건드렸다 — terrain 재빌드 없음, core 계약 변경 없음, 걷기/충돌 판정 무영향.

## 6. 잔여 — 이번에 안 한 것

- **콘크리트 베이스·해변 모래 타일 미적용** — `ts_ttp_base_concrete`·`base_sand`는 굽고
  등록만 했다. 방파제 표면(`'b'`)·모래(`'s'`) 지면 교체는 **사용자가 방파제·갯바위 시트를
  제작 중**이라 그 납품 후 한 벌로 결정한다(지금 바꾸면 두 번 갈아엎는다).
- **물 타일 3종**(`water_still/ripple/splash`) 미적용 — 현재 물은 수심 버킷 절차 베이크라
  통짜 교체는 수심 표현을 잃는다. 변형 풀에 섞을지는 사용자 판단.
- `corner_land`·`corner_se`는 등록만 — 코너 전용 조합 렌더는 필요성 확인 후.
- 접경 셀은 축 4방위만 — 45° 대각 스텝 전용 셀은 없다(계단 경계는 5m 양자화 본질).

## 7. 위험·부작용

- **외해 마스크는 휴리스틱** — `waterDist ≥ 8`(뭍에서 40 m) 폭 이상의 수역만 외해로 본다.
  타 지역 확장 시 좁고 긴 만(灣)이 외해에서 빠질 수 있다. 확인 지점 = 방파제 외해면에
  테트라포드가 안 깔리는지 육안 대조.
- **타일 32px는 TR 1:1 전제** — `ensureTtpTextures`가 `tr !== 32`면 조기 반환한다(legacy TR 20
  지역은 구 절차 렌더 유지). TR을 바꾸면 파이썬 `TTP_TILE`도 같이 바꿔 재추출해야 한다.
- **웜 틴트 값이 두 곳에 있다** — 파이썬 `TTP_SAND_TINT`와 `ensureGroundTextures`의 `'s'` 틴트
  `#f6d47c`. 한쪽만 바꾸면 접경 셀 모래와 지면 모래의 색이 갈린다(양쪽 주석에 명시).
- 청크당 draw 호출 증가 — 방파제 인접 물 타일마다 최대 3, 두 번째 밴드 1. 60FPS 유지 확인.
