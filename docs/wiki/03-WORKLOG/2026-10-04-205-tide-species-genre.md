## 1. 배경 — 왜 했나

204차에 장르 × 어종 물때 공략을 조사 보고서([`TIDE_PHASE_STRATEGY_SPEC.md`](../../../.agents/TIDE_PHASE_STRATEGY_SPEC.md))로 남기고
P1~P3 중 어디까지 넣을지, 동해 감쇠(0.3)를 둘지 물었다.

사용자 원문:

> "전부 그대로 하면 좋겠어. 우선 적용하고 이후에 실검증 해봐야 겠지만.
> 그리고 동해 감쇠 적용하면 좋을 듯."

- P1(어종 표) · P2(장르 조건) · P3(대물 · 해루질 · 통발 · 발견 기록)를 전부 넣는다.
- 동해(속초·포항·울릉)는 물때 효과를 0.3배로 누른다.
- 수치는 실검증 뒤 조정한다 — 전부 `TUNING.tidePhase`(F8)로 뺀다.

## 2. 원인 — 무엇이 문제였나

기능 추가. 검증 중 버그 하나를 찾아 고쳤다.

- **1인칭 씬 인스턴스 재사용으로 지역 계수가 남았다** — 물때 캐시(`tideNowCache` · 30초)를 클래스 필드 초기값으로만 두었다.
  Phaser는 같은 씬 인스턴스를 다시 `create()`하므로 부산 캐스팅 직후 속초로 가면 캐시의 계수 1.0이 그대로 쓰였다.
- 확정 근거: 하네스 `r205.cjs` — 부산 → 속초 순으로 띄웠을 때 속초 `k=1`(수정 전) → `k=0.3`(수정 후).
- 같은 이유로 쌓인 밑밥(`chumBank`)도 다음 캐스팅에 남았다 — `create()`에서 함께 비운다.

## 4. 구조상 위치 — 어느 계층의 무엇인가

- `낚시 → 물때` — **데이터·판정은 core**(표 + 순수 함수 · 수치는 `TUNING`), 씬은 곱셈 자리에서 부르기만 한다.
- 오라클 입력은 **선택 필드**라 안 넘기면 기존 수치 그대로(홈타운 = 물때 없음).
- 완료 시스템(`TideCalculator` · `TrapSystem` · `NightHuntingEngine`)은 건드리지 않았다 — 수위는 물때 흐름에서 잇고,
  통발 배율은 클라이언트에서 수확물 무게에 곱한다.
- 전역 피딩의 동해 지수(조류 기여 0.45)는 그대로 두고, 동해 감쇠 0.3은 **새로 넣은 층에만** 건다(같은 것을 두 번 깎지 않는다).
- 어종 선호는 화면에 미리 보이지 않는다(R2) — 잘 무는 물때에 잡아 봐야 기록·도감 줄이 생긴다. 위키에는 전부 공개.

## 6. 잔여 — 이번에 안 한 것

- **수치 조율** — 사용자 실검증 후(백로그 AT). 전부 F8 `tidePhase.*`.
- **선상 드리프트**(물돌이 = 배가 안 흐름) — 선상 낚시가 아직 없다.
- **물때 단계 HUD 칩** — 지금은 「물때 감각」 알림 + 1인칭 수심 정보 한 줄. 겹침 감사가 필요해 보류.
- 실제 입질 빈도 체감 — 헤드리스는 rAF가 느려 실시간 입질 수를 재지 못한다(배율만 확인).

## 7. 위험·부작용

- **남해(부산) 입질 분포가 바뀐다** — 참돔은 물돌이에 0.6배까지 떨어진다(조금이면 0.76). 체감이 크면 `speciesScale`로 전체를 줄인다.
- 원투 가벼운 봉돌(94g 미만)은 남해 사리 중물에 밑걸림이 늘어난다 — 의도(장비 선택의 의미). 동해는 물살이 약해 거의 안 생긴다.
- 해루질 수위가 물때 흐름 기반으로 바뀌어 스팟 밀도가 전과 다를 수 있다(동해는 0.3으로 눌러 변화가 작다).
- 씬 재사용 함정 — 1인칭에 새 캐시 필드를 더하면 `create()` 리셋 줄에 같이 넣는다(`fishing-loop.md` §6-18).
