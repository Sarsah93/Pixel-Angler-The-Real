## 2. 원인

**확정된 기전**:

1. 고등어 프로필은 `hasScales: false`다(`ButcheryProfiles.ts` — 잔비늘이라 비늘을 치지 않는다).
   `buildButcheryStages`는 비늘 있는 어종에만 비늘치기 세 단계(`scale_base` · `scale_flip` · `scale_wash`)를 만든다 — 고등어 공정은 27단계다.
2. 손질 창의 섹션 트리(`WHOLE_FISH_SECTIONS`)는 원형어 한 벌이라 밑손질에 늘 「비늘치기」 작업이 있다.
3. 「비늘치기」를 누르면 `selectTask` → `process.jumpTo('scale_base')`가 **false**(공정에 없는 단계)인데 결과를 보지 않았다.
   공정은 직전 작업이 끝난 자리(`gut_open` — 배따기)에 그대로 있다.
4. 화면은 「비늘치기 1/3」인데 칼질은 공정의 지금 단계(배따기 → 내장 → 핏줄 → 세척 → 꼬리 칼집 → 1면 · 2면 뜨기)를 차례로 통과했다.
   `onStageComplete`는 활성 작업(비늘치기)을 찾아 「작업 단계가 아직 남았다」로 보고 화면만 다시 그렸다 — 섹션은 2/11에 머물고 필렛 수만 2/2가 됐다.
5. 2면 뜨기 다음 단계가 갈빗대 제거(`rib_a` — 방향 「살 위로(필렛)」)다. 이 뷰는 작업을 고를 때 `jumpTo`가 스냅해 주는 뷰라
   좌우(F) · 상하(V) 뒤집기로는 갈 수 없다(`doFlipLR` · `doFlipUD`가 필렛 뷰를 건너뛴다) → **진행 불가**.

**확정 근거**: core 모의(`scratchpad/butcher_sim.mjs`) — 22종(어류 17 · 두족류 5) 중 고등어만 「작업 t_descale: 단계 scale_base로 못 감 — 공정은 gut_open에 남음」.
캡처의 「필렛 2 / 2」 · 갈빗대 안내 글 · 필렛 뷰 안내가 이 경로의 끝과 그대로 맞는다.

300차 D-7(고등어 방어류 흐름 배선)의 검증은 「손질 창이 열린다 · 프로필 chub_mackerel」까지만 봤다 — 끝까지 손질하지 않아 못 잡았다.

## 4. 구조상 위치

`손질 → 어류 손질(B1) → 자유 순서 섹션 컨트롤러`. 판정(공정 · 프리미티브)은 그대로고 **섹션 트리 ↔ 공정 단계 목록의 정합**을 한 곳(core)에서 맞춘다.
트리는 체형 단위, 공정은 프로필 단위라 프로필 옵션(비늘 · 앞으로의 생략 분기 `skipDescale` 등)이 트리를 바꾸는 길이 이것 하나다.

## 6. 잔여

- 이미 막힌 손질은 창을 닫으면(✕ · ESC) 원물이 그대로 돌아온다(체크포인트 전 이탈 = 아무것도 지급하지 않고 원물 보존) — 새 빌드에서 다시 손질하면 된다.
- 비늘 없는 어종이 더 열리면(쥐치 · 갈치 프로필은 `hasScales: false` — 아직 손질 미구현) 같은 길로 비늘치기 작업이 빠진다. 시험이 손질 가능 어종 전부를 끝까지 돈다.
- 밑손질 안내 글 「우측 상단 작업 목록에서 다음 작업을 선택하세요」는 작업 목록이 도마 위 가운데에 있어 자리 말이 틀리다 — 손대지 않았다(R11 조작 안내 문구 정리와 함께).

## 7. 위험 · 부작용

- 섹션 객체가 어종마다 새 배열일 수 있다(비늘 없는 어종만). 섹션 id · 작업 id는 그대로라 재장착(`resumeAtSection`) · 체크포인트 · 부산물 yields는 바뀌지 않는다.
- 안전망 `jumpTo`(작업 안 어긋남)는 방향을 스냅한다 — 정상 흐름에서는 일어나지 않는다(시험이 작업 안 단계가 이어져 있음을 지킨다).
