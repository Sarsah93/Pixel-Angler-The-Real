## 1. 배경 — 왜 했나

129차 말미에 사용자가 갈라 둔 4건이 이번 차수의 범위다(P7 이후 별도 차수로 묶기로 한 것):

- **(a) 생활 스킬 최대치 증가** — 허기·수분·피로의 **그릇**을 키우는 노드.
- **(c) 저확률 행동력 미소비** — 행동 1회가 아예 비용을 안 쓰는 확률.
- **(d) 스킬 해제 조건 경우의 수** — 선행 랭크 말고 다른 관문.
- **(e) 시너지 히든 스킬** — 조합을 채우면 열리는 숨은 노드.

넷 다 **트리 구조를 건드리는 변경**이라, 124차가 세운 두 제약과 정면으로 부딪힌다:

1. **Σ 등식** — `SKILL_TREE_TOTAL_PT = 200` ("만렙 = 전 스킬 마스터").
2. **티어당 ≤6노드** — `SkillTreePanel.nodePos`가 7노드부터 겹친다.

## 2. 원인 — 무엇이 문제였나

### ① 등식을 그대로 두면 세이브가 깨진다

(a)(c) 노드를 넣으면 Σ가 200을 넘는다. 200에 맞추는 방법은 **기존 노드 비용을 깎는 것**뿐인데,
세이브는 **랭크만 저장하고 포인트는 레벨에서 파생**한다(`skillPointsSpent`가 DB 비용으로 매번 재계산).
비용을 깎으면 **이미 찍어둔 세이브의 사용 포인트가 소급해서 바뀐다** — 남는 쪽이면 공짜 포인트,
모자라면 마이너스다. 그래서 **좌변이 아니라 우변(예산)을 늘리는 쪽**을 택했다.

### ② 티어 압축은 간격만 줄여서 7노드부터 겹쳤다

124차 `nodePos`는 `dy`(행 간격)만 줄이고 **노드 높이(NODE_H 72)는 고정**이었다.
실측: 가용 높이 464px에서 7노드면 `dy = (464−72)/6 = 65.3 < 72` → **6.7px씩 겹친다**.
(e)로 `fishing:3`이 6 → 7노드가 되므로 실제로 터지는 문제였다.

### 설계 결정

- **등식 재정의: Σ(유료) = 만렙 포인트(200) + 면허 보너스(15) = 215.**
  늘린 예산을 **면허**에 붙였다 — (d)가 면허를 해금 조건으로 쓰는 것과 같은 방향이라
  "면허를 따면 스킬도 열린다"가 두 기능에서 같은 문장이 된다.
  새 표어는 **"만렙 + 전 면허 취득 = 전 스킬 마스터"**.
- **히든 시너지는 비용 0 · 자동 습득.** 보상이지 구매가 아니다 →
  예산 등식 밖에 두면 (e)를 몇 개 늘려도 Σ가 흔들리지 않는다. `canLearnSkill`은 히든을 거절한다.
- **최대치는 그릇이지 회복이 아니다.** `setVitalsCaps`는 상한을 올려도 **현재값을 올리지 않는다**
  (스킬을 찍자마자 배가 부르면 '최대치'가 아니라 '회복'이다). 내릴 때만 클램프한다.
- **임계 20%는 절대값이 아니라 비율.** 최대치를 130으로 키우면 저지표 경계도 26으로 같이 올라간다
  (그릇이 커진 만큼 여유도 커져야 한다).
- **(c)는 비용 절감이 아니라 확률적 면제.** 소수점 소모를 만들지 않으려는 이유는
  129차 재료 절약(`materialSaveChance`)과 같다.
- **티어는 여전히 0~3.** 5열은 패널 폭(788px)에 물리적으로 안 들어간다(`14 + 4×196 + 172 = 972`).
  세로로만 확장했다.

## 6. 잔여 — 이번에 안 한 것

- **면허 7종은 아직 발급 불가**(`plannedNote`) — 지금 도달 가능한 실예산은 200 + 8이다.
  만렙과 마찬가지로 **장기 등식**이고, 해당 면허 시스템이 열릴 때 자동으로 채워진다.
- **`action_free`는 `applyVitalsAction` 한 곳에만 적용**. 제작 재료·미끼 소모 등 다른 자원에는
  붙이지 않았다(그쪽은 `materialSaveChance`가 따로 있다).
- **히든 시너지는 5종**. 카테고리마다 하나씩 놓았고(운전·농사 제외), 농사는 카테고리가 잠겨 있어
  뺐다 — 농장 착수 시 함께 추가한다.
- **패널 세로 수용은 8노드까지**. 9노드부터는 높이 하한(46px)에 걸려 다시 겹치므로,
  그때는 열 스크롤이 필요하다(무결성 검사가 경고한다).
- 스킬 툴팁의 실효과 수치 표기(현재 설명 문구만)는 종전대로 잔여.

## 7. 위험·부작용

- **예산이 늘었다** — 면허를 이미 여러 개 딴 세이브는 로드 즉시 **여유 포인트가 생긴다**(의도).
  반대로 줄어드는 경우는 없다(면허는 회수되지 않는다).
- **`VitalsState`에 필드 2개 추가** — 세이브에는 `hunger`/`hydration` 현재값만 들어가고 상한은
  스킬에서 파생하므로 세이브 스키마 변경은 없다. core를 직접 쓰는 외부 호출은
  `normalizeVitals`로 백필한다.
- **`isVitalsLow` 의미 변경** — 절대 20 → 최대치의 20%. 기본 상태(최대 100)에서는 **완전히 동일**하다.
- `applyVitalsAction`이 `boolean`을 반환하게 됐지만 기존 호출부는 값을 무시하므로 무해하다.
- **리스펙이 히든도 지운다** — 조건이 그대로면 같은 호출에서 즉시 다시 열리므로 체감 손실은 없다.
