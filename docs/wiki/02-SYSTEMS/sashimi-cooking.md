# S4. 회썰기 · 플레이팅 · 요리

> 상태 **🟢 운영**(회·접시·**불요리**) / **⬜ 미착수**(스시).
> 관련 차수 65·66·68·69·73·74·75·154·**156**

---

## 1. 목적·범위
손질 산출물(순수 필렛·엔가와)을 **회 조각 → 접시 완성품**으로 만들고 값을 매긴다.
**불요리(154차)** = 화구(조합 설치·집 주방)에서 어획물·부산물·채집물·식자재를 실시간 시뮬로 조리해 **맛 별 5개** 요리 아이템을 만든다.
**요리 개체화(156차)** = 같은 레시피라도 **주재료 어종**이 이름·회복치·효과·판매가에 남는다(`DishInstance`).
정본 스펙 `.agents/FIRE_COOKING_SPEC.md` · 확장 `.agents/FIRE_COOKING_EXPANSION_SPEC.md`.

## 3. 동작 구조
```
순수 필렛 ─드래그→ 도마 ─[일반/고급 회뜨기]→ SashimiPanel(모달)
   컷 = 머리쪽(우) → 왼쪽 순서 · 성공 시 조각 분리 팬아웃
   → 회 조각 N개(inv_sashimi_cut_…) : 원물 가치 승계
도마 조각 스테이징 ─한 점씩 드래그→ 접시(소/중/대/특대)
   4방위 × 방위당 4~7점 · [접시 돌리기]로 방위 전환 · 만석 시 안내
   → [사시미 완성] : 2종 이상 = 모듬(고정가+g 하한) / 1종 = 단품(kg시세식)
```
- **가치 규칙**: 조각·필렛 체인은 **원가 승계**, 부가가치는 **접시 완성 시점**에만 실현.
- 완성 접시는 **0.6 매입 할인 미적용**(책정가 그대로 판매).

```
인벤 [화구 설치] → 스토브 + 캐니스터(소모) + 용기(선택) → 뭍 3타일 클릭 → 화구(탑다운 배지)
   [F] CookingPanel: 용기 → 레시피(용기 종류별) → 재료 스테퍼/[넣기] → 불 0~3 → 단계 안내
   wall-clock 시뮬(실 10초 = 조리 1분) : 온도 → 익음/탐 → 완성(final +90s) → 방치 시 과조리/졸아붙음
   [불 끄고 내리기] → inv_dish_<recipe>_<seq> (dish: 기준 점수·재료·조리 시각) — 별점은 조회 시 감쇠 계산
```
- **별 5개** = 간(염도·당도) · 온도 · 식감 · 신선도 · 완성도(앞 넷 조화 × 구성 × 순서 × 불 조절 × 스킬, 넷 중 하나라도 < 0.6이면 0.55 캡).
- **가치** = `base × (0.3 + 0.9·total/100)` · 탄 요리 0 · 섭취 배율 `0.45 + 0.75·total/100`.

## 5. 잔여·차기
- **회썰기 유도선 실측** — 편집기(F9)·오버라이드 테이블은 준비됨(86차), **값은 비어 있음** → 사용자 측정 대기.
- **U 패널 destroy 시 인벤 완전 만석**이면 조각이 여전히 사라질 수 있다(61차 안전망의 한계).
  미완성 접시는 **1칸**만 필요해 위험은 크게 줄었지만 0은 아니다.
- ~~불요리 시스템~~ ✅154. 잔여 = 요리 후보 확장(데이터 1건) · 탑다운 화구 실사 에셋 · `TUNING.cook` F8 조율 · 요리 계열 스킬 추가 배선.
- ~~사시미 완성도 모델~~ ✅155(별 5개). 잔여 = 식감 축이 칼·컷에서만 오고 **두께 균일성**은 여전히 판정 없음(65차 잔여).
- ~~요리가 재료를 반영하지 않는 문제~~ ✅156(매운탕 3종). 잔여 = **나머지 7개 레시피 변형**(`VARIANT_RECIPES`에 id 추가 + 어종 프로필 확장) ·
  아이템 라이브러리 · `TUNING.cook.{ingredientQuality, dishEffect, naming, pricing}` 실플레이 조율(mockup 값) ·
  포만감 외 효과 7종은 **표시만**(실기전 없음 — 기획서 §0.5 결정).
- 스시는 여전히 스텁(`p-sushi` planned). 레거시 `CookScene`은 불요리와 무관하게 남아 있다(폐기 후보).

## 6. 함정·불변조건
1. **접시/조각은 패널 파괴 시 전량 반환** — 아이템 유실 금지 규칙(61차 이후 공통).
   135차부터는 **미완성 접시 아이템 1개로 먼저 보관**하고, 그것도 실패할 때만 낱개 반환한다.
2. **완성 접시의 신선도는 담긴 조각 중 가장 오래된 것을 계승한다**(135차).
   구 구현은 항상 `'fresh'`로 굳혀, 판매 배율 0.10인 '나쁨' 조각 16점을 **정가 접시로 세탁**할 수 있었다.
3. **화구·용기는 설치 시 통째로 빠진다** — 회수는 `recoverPlaceable`이 `COOK_CORNER` 카탈로그에서 되살린다(154차 실측 —
   폴백이 없으면 회수 시 증발). 새 조리도구를 상점에 추가하면 반드시 `COOK_CORNER`에 넣는다.
4. **고형물 부피는 `solidVolumeFrac`(0.6)** — 1:1로 세면 코펠에 감성돔 한 마리가 안 들어간다.
5. **조리 패널은 레이아웃 키(`용기|레시피|status`)로 정적 층을 다시 그린다** — 세션은 패널 밖(동기화·다른 경로)에서도 바뀐다.
6. **연료는 되돌리지 않는다**(끼우는 순간 소모) — 설치 패널·회수 확인창이 고지한다.
7. **재료 판정은 `ingredientOfItem`** 한 곳 — 새 어종·부산물·채집물을 요리에 넣으려면 여기 매핑만 추가한다.
   비교 기준은 라벨 서열이 아니라 `msToSpoiled()`(상태 그래프의 종착까지 남은 시간)다 —
   냉동·냉장·활어가 섞이면 라벨 순서로는 틀린 답이 나온다.
3. **미완성 접시는 팔 수 없다**(`getSellPrice` → 0). 가격표가 만석을 전제하기 때문이다
   (모듬 = 크기별 고정가 + g 하한 / 단품 = 회중량 고정). 섭취는 되고, 이때 **식기는 회수**한다.
4. `SashimiFilletProfiles.ts`는 생성기 산출물 — 손으로 고치면 다음 재생성에 사라진다.
5. 도마 필렛 방향 규칙 = **꼬리 왼쪽·머리 오른쪽**(`MIRROR_KEYS`로 원본 반전).
6. **`SASHIMI_CUT_OVERRIDES`는 컷 수가 스펙과 다르면 조용히 무시**(warn 폴백) — spec.cuts 변경 시 오버라이드 동반 갱신(86차). 좌표는 필렛 표시 rect 정규화라 표시 rect 산출식 변경 시 재측정.

8. **완성 요리의 값은 개체가 갖는다**(156차) — `InvItem.dishInstance`가 있으면 이름·회복치·효과·판매가가
   전부 거기서 나온다. 카탈로그 `basePrice`를 고쳐도 이미 만든 요리는 안 바뀐다(개체에 굳는다 — 의도).
   `dishInstance`가 없는 154차 요리는 기존 분기를 그대로 타므로 **구세이브 호환은 유지**된다.
9. **어종 프로필을 바꾸면 앞으로 만들 요리만 바뀐다** — 이미 인벤에 있는 개체는 그대로다.
10. **수식어는 최대 1개**(탄 → 일품 → 싱싱한 → 기름진). 두 개를 붙이면 이름이 길어지고 무엇이 좋은지 안 읽힌다.
11. **변형 후보는 어류만**(`dishVariantCandidates` — 두족류 제외, 학명 중복 제거). 매운탕 기준 50종.
