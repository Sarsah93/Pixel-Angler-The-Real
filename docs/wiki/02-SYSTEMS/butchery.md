> 상태 **🚧 진행 중** — 어류 3어종군 마감, 두족류는 **무늬오징어·한치·문어 개방**(97차) · 갑오징어만 미착수.
> 최종 갱신 2026-08-13 (97차) · 관련 차수 14·20·41·43·45·47~63·65·67·70·74·75·78·80·82~97

## 1. 목적·범위

낚은 **원물 1마리 → 부위별 부산물 + 순수 필렛**으로 바꾸는 미니게임. 낚시 루프의 하위 시스템이며,
산출물은 [회썰기·플레이팅](sashimi-cooking.md)과 [경제](economy-data.md)로 넘어간다.

**책임지는 것**: 손질 공정 FSM · 컷 판정 · 부산물 지급/회수 · 도마 렌더 · 가이드 좌표 · 수율/등급.
**책임지지 않는 것**: 썰기(S4) · 조리(S15) · 어종 데이터(오라클) · 아이템 저장(S5).

## 3. 동작 구조

### 3층 모델 (52차 대개편)
```
섹션(순서 강제)  →  작업(섹션 안에서 선택)  →  스테이지(실제 조작 1회분)
  sec_prep            t_head (머리 제거)         head_base / head_flip
  ...                                            └ 프리미티브: tap / guided_cut /
                                                    drag_fill / scoop / wash / peel
```
- 섹션 완료 시 **부산물 팝업**([보관]/[버리기]) → **[확인] 즉시 인벤 지급**(63차).
- 체크포인트(`exitAfter`) 이후 이탈 = 그 시점 정산 / 그 전 이탈 = **원물 복구 + 지급분 회수**.
- 조작 축 3종: **좌우 뒤집기(F)** · **상하 뒤집기(V)** · **90° 회전(R/Shift+R — 80차 신설, 독립축)**.
  회전은 **생선만 돈다** — 도마·레이아웃은 가로 고정(83차 재설계, board rect / fish rect 분리).
- **넙치류 포 뜨기 = 반쪽마다 3단계**(84차 공정 재정의): (1/3) 지느러미 경계 칼길(꼬리→머리) →
  (2/3) 살·뼈 분리(머리→꼬리·더 안쪽) → (3/3) 거의 중앙선 — 필렛 분리. 회차마다 **독립 경로**.
  **칼 팔로우 연출**: 드래그 접점을 딜레이 후 사시미칼 스프라이트(칼끝 파묻힘)가 천천히 추종,
  칼이 지나간 구간부터 살이 들린다(**이동 힌지** — 경계→중앙선). 내장은 머리 S컷과 동반 배출.

### 판정
`evaluateCut(가이드 폴리라인, 그은 획)` = **커버율**(32샘플) + **평균 이탈**(tolerance 배수) → 품질·통과.
채움류(비늘·내장·박피)는 `sweepPath` 44샘플 **커버리지 게이지**(제자리 흔들기 차단).

### 수율·등급
```
yieldMass = 무게 × baseYieldRate × 칼계수 × 스킬 × 신선도
등급      = (방혈 × 시메 × 컷정확도평균 × 신선도) × 칼·스킬 보정 → 특/상/중/하
           ※ 막칼은 '특' 캡 = '상'  ※ 활어가 아니면 '특' 불가
```

### 재장착 체인 (중간 산출물을 도마에 다시 올림)
```
inv_filletribs_ → sec_rib(갈빗대)   inv_filletpin_ → sec_pin(지아이)
inv_filletskin_ → sec_peel(박피)    inv_filletengw_ → sec_engawa(엔가와)
inv_engwskin_   → sec_peel → 순수 엔가와
```

## 6. 함정·불변조건 (건드리면 깨진다)

1. **도마 스프라이트는 구운 스냅샷** — `public/fish/*.png`를 바꿔도 `gen_*_sprites.cjs`를 다시 돌리지 않으면 반영 안 된다(어획 팝업/인벤은 PNG 직접 로드라 자동 반영 — 이 비대칭이 반복 함정).
2. **유도선은 도마 rect 고정 매핑** — 스프라이트를 갈아끼우면 좌표가 어긋난다. 그래서 **온마리 원형 틀 고정 + 부위 영역 삭제**(55차) 방식이다. 개복 이후 전용 뷰는 예외(뷰 자체 스케일).
3. **연출이 끝나기 전에 다음 상태를 그리지 않는다** — 액션/뒤집기 재생 중 완료 처리는 `pendingAfterAction` 큐로 미룬다(53차).
4. **부산물 지급 경로는 3개**(버튼·ESC·destroy) — 새 종료 경로를 만들면 반드시 정산/회수를 태운다(59~63차에서 3번 재발).
5. **F9 [복사] 스니펫은 `opts`(strong·tolerance)를 포함하지 않는다** — 붙여넣을 때 기존 opts를 보존할 것.
6. **좌표 반영은 core 리빌드 필요** — F9 편집은 런타임 전용.
6-b. **두족류 표시 회전은 `renderedRotation`**(92차) — `process.rotation`은 advance()가 즉시 스냅하지만
  화면·좌표(rotNorm/subjectRect)는 연출이 끝날 때(doRefresh)까지 옛 회전을 유지한다.
  새 표시 로직에서 `process.rotation`을 직접 읽으면 연출 중 스프라이트/유도선이 어긋난다.
  peel 진행 프레임(`peelDragT`)도 마찬가지 — **subjectRect에는 절대 넣지 않는다**(시작 프레임 = 캐노니컬).
6-c. **파이프라인 캡처 입력 함정**(95차 — `pixelize_butchery.cjs`): ① `ERASE_POLY`를 불투명 배경
  캡처에 쓰면 투명 비율 3% 초과 → **알파 경로 오판** → 배경 제거가 통째로 꺼진다. ② 목업 캡처
  PNG는 투명 여백 때문에 애초에 알파 경로 — 도마색이 남으므로 **파생 단계 보더 플러드**로 걷어낸다
  (색 근접 + 따뜻함(r−b) 병용 — 거리 단독이면 몸통 회색까지 먹는다).
7. **넙치 필렛 아이콘 — 구 `trim_fillet_engw_halibut_1/2` 로드를 지우지 말 것**(85차) — 구세이브 기지급
   아이템의 iconTexture 문자열 호환용. 신규 지급은 `_upper/_under`(내장 유무)가 담당한다.
8. **`clipSpan`(개방 클리핑)은 headCutPath의 y 단조를 전제**(85차) — S컷 좌표 재측정 시 위→아래 순서 유지.
7. **`submitTap`은 거리(number) 인자** — 좌표 객체를 넘기면 quality가 NaN이 된다(하네스 함정).
8. **두족류 스펙은 §0.5(v3.1)가 본문보다 우선** — v3 본문은 레포 접근 없이 작성돼 speciesId·심볼이 실제와 다르다.
9. **넙치류 내장은 머리 S컷과 함께 딸려 나온다** (사용자 확정 2026-08-06 → 84차 반영) — 별도 내장 스테이지 없음,
   viscera는 `t_head` yields로 지급. (해부 참고: 내장은 머리 뒤 앞쪽 주머니에 국한 — 심장·위·유문수·장 → 항문까지.
   장축으로 뒤집으면 위/아래 가장자리가 바뀐다 — 배면 위 = 내장 위쪽 / 등면 위 = 아래쪽.)
10. **실사 도마 렌더 정책은 어군별로 다르다 — 통합하지 말 것.**
   - **어류(넙치류 포함)**: 실사 = 참고자료, 도마 = 자체 픽셀 + 파라메트릭 연출 (사용자 지시 2026-08-06 → 84차).
   - **두족류**: 실사 사진이 **곧 도마 그림**이다 (사용자 지시 2026-08-10 → 89차). 84차 결정을
     두족류에 적용해 사진을 걷어내면 안 된다.
   파이프라인 규약(가로 기준 굽기 + `ROTATE_KEYS` — 렌더에서 또 돌리면 이중 회전)은 양쪽 공통.
   두족류 방향 규약은 **다리·입구 = 왼쪽 / 외투막 끝 = 오른쪽**(세로 원본은 `cw`).
11. **넙치류 벌어짐은 이동 힌지** (84차) — 힌지 = 경계 + (중앙선−경계)·깊이. 노출은 [경계..힌지],
   플랩은 힌지 미러. **중앙선 고정 힌지(구 78차)로 되돌리면 공정 방향과 어긋난다.**
12. **ButcheryPanel의 rect는 2종이다** (83차): **생선 위에 그리는 것**(유도선·트레이스·핸들·화살표 큐)은
   반드시 `toPanelPx`(회전 변환) 경유 — `fishX + x·fishW` 직접 매핑은 90° 회전에서 자국이 가로로 눕는다.
   **오버레이/버튼/목록/플래시**는 board rect(`boardX/Y/W/H` — 가로 고정) 앵커 — fish rect에 앵커하면 회전 시 밀린다.
13. **`jumpTo`는 방향·회전을 모두 스냅한다** (83차) — dev 항법·재장착 재개가 조용히 입력 차단되지 않게 하기 위함.
   수동 정렬을 기대하는 코드를 jumpTo 뒤에 두지 말 것.
15. **프리미티브 분기는 `primitiveInput()`으로** (87차) — 프리미티브는 19종인데 조작은 5가지(tap/path/fill/peel/button)다.
   패널에서 `stage.primitive === 'guided_cut'` 식으로 이름을 직접 비교하면 종류가 늘 때마다 15곳을 손봐야 한다.
   ⚠ **새 프리미티브를 추가하면 `primitiveInput`의 switch에 반드시 등록할 것** — 빠뜨리면 조용히 `'path'`로 떨어진다(default).
16. **두족류는 뷰를 자동 스냅한다** (87차) — 어류의 "수동 뒤집기" 원칙과 **반대**다. 개복→펼침→껍질면→살코기면 전이는
   뒤집기 버튼으로 도달할 수 있는 자세가 아니라 공정 자체다. `advance()`의 `cephalopod ||` 조건을 지우면 첫 전이에서 입력이 죽는다.
   같은 이유로 패널의 뒤집기·회전 버튼은 두족류에서 숨긴다.
17. **`ButcherySectionYield`는 어류 키 + `CephByproductId` 유니온** (87차) — 두 집합에 같은 문자열이 생기면 조용히 오매칭된다.
   어류는 카멜케이스, 두족류는 `ceph_`/`octo_` 접두를 유지할 것.
18. **체크포인트는 `exitAfter` 기준 일반 규칙이 있다** (87차) — 구 구현은 어류 섹션 id만 나열해 두족류가 항상 `'none'`이었고,
   중도 이탈 시 지급분이 전부 회수됐다(부산물 소실 계열 재발). 새 트리를 추가할 때 id 매핑을 잊어도 `exitAfter`가 받아준다.
19. **도마 온마리는 어종별 스프라이트** (87차) — `SPECIES_WHOLE[speciesId]`. 실사 색이라 **틴트 금지**(`wholeNative`)지만,
   개복 이후 단계 뷰는 여전히 어종군 공용이라 어종 색 틴트를 유지한다. 두 값을 하나로 합치지 말 것.

14. **knifeFx와 actionAnim은 한 쌍** (84차) — 칼 완주(finishing) 동안 `actionAnim` 가드가 서고 `completeKnife`가
   해제 + `runPendingAfterAction`을 실행한다. 칼 세션을 우회 종료하는 경로는 반드시 `stopKnifeFx()`를 태울 것
   (playFlipAnim·destroy 편입됨). **칼 텍스처 규약 = 가로·칼끝 오른쪽·칼날 아래** — 어기면 crop/flipY가 반전된다.

20. **좌표 정규화 기준은 `subjectRect` 하나** (89차) — 유도선(`toPanelPx`)·입력(`toNorm`)·F9 드래그가 전부 이걸 쓴다.
   **어류 = 생선 rect 그대로**(회귀 없음), **두족류 = 스프라이트가 실제 차지하는 rect**.
   두족류를 생선 rect로 되돌리면 ① 뷰마다 종횡비가 0.27~2.6이라 좌표 0~1이 빈 도마까지 덮고
   ② `tolerance`(정규화 단위)의 실제 관대함이 뷰마다 달라진다. 세 경로 중 하나만 바꾸면 즉시 어긋난다.

20b. **완료(`finished`) 도마도 스프라이트를 지정해야 한다** (69·84차 어류 / 89차 두족류) —
   완료 시점엔 `process.stage`가 `null`이라 스테이지 기반 조회가 실패하고, 그대로 두면
   **결과 오버레이 뒤에 구 파라메트릭 그림이 남는다**(같은 증상이 어류에서 1회, 두족류에서 1회 재발).
   규칙: **완료 도마 = 최종 산출물** — 어류 `pure_fillet_{fam}`(순수 필렛) / 두족류 `squid_clean`(손질된 몸통).

21. **두족류 스프라이트는 정확 맞춤 셀** (89차 — `drawStageSprite`) — 어류의 정수 셀 하한
   `max(2, floor(...))`을 두족류에 쓰면 128×127급 세로 뷰가 254px로 그려져 **도마(210)를 44px 이탈**한다.
   반대로 어류를 정확 맞춤으로 바꾸면 도트가 흐려진다 — **두 경로를 통합하지 말 것**.

22. **세로 원본은 굽는 시점에 눕힌다** (89차 — `ROTATE_KEYS` cw) — 두족류 사진 11장 중 7장이 세로다.
   렌더에서 돌리면 유도선 좌표계와 어긋난다. 새 사진 투입 시 **긴 축 기준 다운샘플**(`FIT_LONG_PREFIX`)도 함께
   확인할 것 — 가로 기준이면 bbox가 좁은 세로 원본이 다운샘플 없이 수백 행으로 구워진다(실측 449행).

23. **`evalNerveCut`은 유도선 길이 비례 판정** (90차) — 시작 = **선 위 아무 지점**(`distToPath` ≤ tapRadius×1.6) ·
   길이 = `max(0.03, L×0.35) ~ max(0.12, L×1.8)`. 구 "중점 시작 + 절대 길이 0.03~0.12"로 되돌리면
   실측 시메 선(L 0.28~0.32)에서 **가이드의 시작 링에서 그어도 실패**한다. F9로 선을 재실측해도 판정이 자동 적응.

24. **당김 계열(`drag_out`·`lift_flap`)은 칼 연출 금지** (90차 — `playActionAnim` isPull 분기) —
   내장 분리·연골/부리 뽑기·껍질 들추기는 손으로 뜯는 동작이다. 새 프리미티브를 path 입력으로 추가할 때
   절삭이 아니면 이 분기에 편입할 것 (사용자 지시 "칼로 절삭하는 행위가 아님").

25. **peel 판정은 스테이지 데이터 기반** (91차 — `onPointerDown/Up` peel 분기) — 잡기 = `tapPoint` 반경 ·
   당김 품질 = **`sweepPath` 방향 성분 투영**. "x>0.72 잡기 + 좌로 당김" 하드코딩으로 되돌리면 대각 스윕
   (껍질 뜯기 ② — q 0.687 → 0.084)이 가이드를 그대로 따라도 실패한다. primitive 'peel'은 두족류 전용
   (어류 박피는 peel_grip/insert/pull 별개 경로) — 어류 걱정 없이 수정 가능.

26. **연출 중간 프레임은 `cephAnimOverride`로** (91차 — 내장 뽑기 lift1→lift2) — 액션 연출 동안
   `drawFish()` 경량 재드로우로만 갈아끼우고, `doRefresh`가 항상 해제한다. **`subjectRect`에는 절대
   반영하지 말 것** — 유도선·입력 좌표가 연출 프레임을 따라가면 스테이지 좌표계가 흔들린다
   (연출 중 입력은 actionAnim 가드로 차단되므로 렌더만 바뀌는 게 정답).

27. **합성 스프라이트는 파이프라인 파생 함수로** (91차 — `deriveSkinOver`, 84차 `deriveLiftA` 전례) —

   빗살이 나고(전역 경계 + 청크 지터로), 전역 휘도 영역은 피사체 전체를 얼룩지게 한다(공간 한정 + 국소 톤 샘플링으로).
