## 1. 목적·범위

## 3. 동작 구조

### 신선도 상태 그래프 (21차 재설계 — 선형 체인 아님)
```
활어 ─10분→ 신선 ─3h→ 보통 ─5h→ 나쁨 ─2h→ 부패
냉동 ─상온 3h→ 해동 ─1.5h→ 나쁨          냉장 ─상온 1h→ 보통
```
- 계산은 **절대 시각(`conditionSinceMs`) lazy** — 열람/판정 시점에 경과분만 진행.
- **오프라인(게임 종료) 구간은 정지**(39차) — 로드 시 갭만큼 기준 시각을 밀어준다.
- 쿨러 매질: 해수 = 활어 시계 정지(만료 시 강제 '보통') / 얼음 = 활어 1h 유지 후 정지(만료 시 '해동').

### 장비 (72차)
```
착용 = 인벤 그리드에서 이탈(slot = SLOT_EQUIPPED −1) → 소켓 확보
해제 = 빈 소켓 필요 → 없으면 EquipResult{ok:false, reason:'아이템 창 공간이 부족합니다.'}
배치 = 머리4 · 좌6 · 우6 · 다리(좌3/우3) — * 표시는 예약 슬롯
장착 = 인벤 → 장비창 드래그(`inventory-drop` 씬 이벤트, 수신자 없으면 조용히 무시)
```

### 세이브
- 슬롯 3개(`tra_save_slot_{n}`) + 레거시 단일 키 호환.
- **저장 지점은 집 침대뿐** — 다른 씬은 `markDirty()`만. 일시정지 '저장하기'는 위치 안내.
- 직렬화 대상: 인벤(아이템·퀵슬롯·채비·편대·루어) · 쿨러 · 냉장고 · 월드 오브젝트 · 플래그.

## 5. 잔여·차기

- **찌는 아직 묶음이다**(백로그 DA ②) — 찌도 고장 · 부력 변성(쓴 횟수 300)이 있지만 282 범위(장비 · 루어) 밖이다. 개체로 하려면 `isInstanceItem`에 한 줄.
- 거래 창 · 상점 판매 목록은 개체마다 한 줄이다(같은 스푼 5개 = 5줄) — 묶어 보일지는 UX 결정(DA ③).

아이템 타입이 늘어날 때마다 **예약 슬롯 매핑만 추가**하면 장비창은 자동. 냉장고 UX(드래그)·보존 곡선은 요리 시스템과 함께.

- ⚠ **시드가 기본 25칸을 넘는다** — `tackle` 29개라 slot 25~28(쿠션고무 · 고리/구멍/묶음추 봉돌)이
  용량 밖에 앉는다. **148차부터 '잠긴 칸'으로 그려져 꺼낼 수 있으므로 사라지지는 않지만**,
  기본 상태에서 4칸이 잠긴 채 시작하는 것은 그대로다. 시드를 줄일지 가방을 전제할지는 데이터 결정
  (`createSeedItems`의 dev 경고 유지).
- **탭별 용량 차등**(`BACKPACK_SPECS.slotsPerTabRatio` — 134차 core 모델)은 여전히 미배선이다.
  실경로는 `bagSlots` 단일 축이고 `resolveSlotsPerTab`/`canUnequipBag`은 소비처가 0이다.
  두 모델을 합칠지 core 쪽을 걷어낼지는 별도 결정.

## 6. 함정·불변조건

- **정리는 칸(`slot ≥ 0`)만 다시 놓는다(277)** — 장착(`SLOT_EQUIPPED`) · 퀵슬롯 · 채비 트리는 아이템 id를 가리키므로 그대로다. 칸 번호로 무엇을 가리키는 새 기능을 만들면 정리에 깨진다 — id로 가리킨다.
  무리 차례 표는 `InventorySort.ts` 한 곳(표에 없는 소분류는 뒤에 소분류 이름 순). 이름 비교는 보이는 이름(영어 설정이면 번역)이다.

- **채비 창 토스트는 패널 자식이다(273)** — `flashBoardToast`가 `bodyContainer`에 글자를 넣으면 바로 뒤의 `renderBody()`(`removeAll(true)`)가 지운다.
  155차 채비 고정 · 193차 비권장 미끼 토스트가 그래서 채비 탭에서 한 번도 보이지 않았다. 도마 사각형은 요리 탭을 그리기 전에는 0이라 탭별 자리(체인 · 본문)를 따로 잡는다.

- **묶음 · 포장은 미끼가 아니다(267)** — `isBaitItem`이 `unpack`(곽크릴) · `isBundlePack`(청갯지렁이 1갑)을 뺀다. 묶음째 꿰이면 한 번 쓰고 20마리가 통째로 사라진다(사용자 리포트).
  새 미끼 묶음은 상점 `bundle`로만 판다 — 산 자리에서는 `handleBuy`가 바로 풀고, 묶음째 든 것(옛 세이브 · 보상 · 줍기)은 「열기」가 푼다.
- **미끼 판정은 두 곳이다 — 낚시 중 고르기(`isBaitItem`)와 채비 칸(`RigParts.partKindOf`)**(279) — 267은 앞쪽만 막아 채비 창 미끼 칸에 곽 · 갑이 꿰였다(QA 「팩 덩어리를 바늘 아래 '미끼'에」).
  곽 · 갑 판정은 `RigParts.isPackItem`(`unpack` 또는 상점 `bundle`) 하나다. 칸 판정은 화면 후보(`nodeAccepts`) · 스토어 넣기(`setRigNode` — `RIG_SLOTS[slot].accepts`) · 로드(`syncTreeWithItems`)가 같은 분류를 본다.
  core `setRigValue`는 칸 종류를 따지지 않는다 — 클라이언트에서 막지 않으면 무엇이든 꿰인다.
  상점 `bundle`은 불러올 때 저절로 풀린다(188 세트 정리 루프 — 미끼 갑 포함 · 백로그 CW).

- **같은 물건에 id를 둘 만들지 않는다**(256) — 시작 아이템을 상점에 올릴 때는 시작 아이템 id를 그대로 판다(구멍찌 0.8호 · 합사 원줄 관례).
  따로 `shop_*` id를 만들면 위키 · 도감에 같은 이름이 둘 뜨고 가방에서 따로 쌓인다(뜰채 5m 등 4쌍 — `ItemIdAlias`로 정리).
  이미 퍼진 옛 id는 `ITEM_ID_ALIAS`에 한 줄을 더한다 — 로드 · `addItem` · 즐겨찾기 · 도감이 같이 정본으로 바꾼다.
  id에서 수치를 읽는 아이템(지그헤드 `lure_jighead_<g>` — `jigHeadWeightById`)은 숫자 없는 id를 만들면 0으로 읽힌다.
- **그림을 바꿀 때 아이템의 `iconTexture`를 고치지 않는다**(255) — 옛 키(`art_*` · `px:*`)를 그대로 두고 그림 표(`ItemImages.ts` — `node tools/item_cards.cjs`가 생성)로 잇는다.
  세이브에 굳은 키가 그대로 맞으므로 이전이 필요 없다. 요리처럼 **키 자체가 계열 그림**이던 것만 불러올 때 바꾼다(`refreshDishPhoto`).
- **장비 그림 키는 아이템 정의에 손으로 적지 않는다**(249) — 대 · 릴 · 줄은 `rodArtKey(id, name)` · `reelArtKey` · `lineArtKey`로 고른다.
- **봉돌 그림은 생김새가 곧 종류다**(272) — 구멍봉돌(`sinker_pillar`)은 몸통을 줄이 관통하는 원통(고리 · 도래 · 소켓 없음), 고리봉돌(`sinker_ring`)은 위에 고리.
  Gemini 생김새 설명에 「고리 없음」을 명시하지 않으면 고리가 달려 나온다. 묶음으로 파는 소모 채비의 `basePrice`는 한 개 값이다(구세이브는 불러올 때 정정 — `PACK_UNIT_IDS`).
  새 낚싯대는 core `rodSpecFor().use`가 맞으면 그림이 따라온다. 옛 세이브는 불러올 때 빌려 쓰던 키(`item_spinning_rod` · `px:it_rod` · `line_spool_saiso` 등)일 때만 바꾼다.

- **[234] 「넣다 실패하면 사라지는」 지급을 만들지 않는다** — `addItem`이 false를 돌려줄 수 있는 모든 지급(퀘스트 보상 · 거치대 회수 · 거래 반환)은
  ① 미리 `slotShortfall`로 자리를 보고 거절하거나 ② 넘친 것을 발밑(`GroundItemStore.drop`)에 둔다. 반환값을 버리는 `addItem` 호출을 새로 쓰지 않는다.

### [178차] 「내려놓기」는 「버리기」가 아니다

바닥의 물건(`GroundItemStore`)은 **지역·타일에 남고 세이브에 실린다**. 놓여 있는 동안 신선도 시계는
멈추고 집는 순간부터 다시 흐른다(쿨러와 같은 규칙). 메뉴는 **심부름 칸 물건과 이야기가 준 물건**에만
붙인다 — 전 아이템에 열면 '버리기'와 뜻이 겹쳐 유저가 둘을 구분할 수 없다(사용자 지시).
홈타운 설치물(`MapObject` + `WorldObjectState.placed`)과는 **다른 층**이다(그쪽은 충돌·기능을 갖는 구조물).


> **136차** — `fault`/`useCount`는 `serialize`의 full spread로 **자동 영속**된다.
> 135차 시드 백필은 누락 필드만 채우므로(`?? seed`) 덮어쓰지 않는다 — 구세이브는 `undefined` = 정상.
> `setFault`는 **이미 고장난 장비를 덮어쓰지 않는다**(먼저 고쳐야 다음 고장이 난다).

1. **세이브는 항상 과거 스키마일 수 있다** — 정적 필드 추가 시 `deserialize` 시드 백필(`?? seed`), **유저 상태(qty/condition/equipped/slot)는 절대 덮어쓰지 않는다**. → 스킬 `save-migration`
2. **마이그레이션은 로드 시점에만 실행** — 라이브 세션은 재로드해야 반영된다(53차에서 "안 고쳐졌다"로 두 번 소모).
3. 어획물은 **개체마다 고유 id**(`inv_catch_{종}_{seq}`) — 병합하면 크기/가격이 첫 개체로 굳는다(16차 실버그).
4. dev 하네스에서 스토어를 조작하려면 **`globalThis.__INV` / `__GS`** 를 쓴다. `import('/src/…')`는 게임과 별개 인스턴스다.
5. 아이템 유실 금지 — 패널 파괴·강제 종료 경로에도 반환/정산을 태운다.
6. **루어 소켓은 미끼 채비와 별도 필드**(117차) — 구세이브는 null이라 `setRigMode('lure')` 첫 전환 때 미끼 채비 줄로 시드한다.
   손실 규칙(`loseLureRig`)도 루어 소켓을 비운다 — 미끼 채비 `_rig.mainLine/leader`를 건드리지 말 것.
7. 줄·바늘처럼 **잃을 수 있는 소모품은 반드시 상점에 있어야 한다** — 없으면 "소켓을 선택할 수 없다"는 리포트로 온다.
8. **인벤 용량은 `InventoryStore.gridCapacity()` 하나뿐**(135차) — `GRID_CAPACITY` 상수를 루프 상한에 직접 쓰면
   확장 행이 안 그려지거나 히트가 안 잡힌다. 행 간격은 가방 착용 시 7 → **4px**로 좁혀 한 화면 6행을 만든다
   (7px면 5행 — 뷰포트 416px 기준 실측).
9. **가방 조작으로 칸이 줄면 `bagShrinkBlocked`를 먼저 돌린다**(135차 벗기 → 148차 교체까지 일반화).
   가드는 `returnToGrid`보다 **먼저** — 벗는 중에도 용량은 아직 큰 값이라 반환 아이템이 확장 칸으로 들어가 버린다.
10. **인터랙티브 그리드에 마스크를 쓰지 말 것**(148차·54차) — Phaser는 마스크로 **입력을 클립하지 않아**
   스크롤아웃된 셀의 히트가 그대로 남는다. 보이는 행만 생성하고, `slotAtPointer`는
   `(scrollRow + 화면행) * 열수 + 열`로 실 슬롯을 계산한다. **뷰포트 밖은 −1**을 돌려줘야 팬텀 히트가 없다.
11. **용량 밖 칸은 그리되 넣지는 못하게 한다**(148차) — 조용히 안 그리면 아이템이 사라진 것처럼 보이고
   (135차 실측: 시드 4건), 넣을 수 있게 하면 가방을 벗는 순간 또 갇힌다. `moveItem`은 이미 거부하므로
   패널은 **안내 문구**만 책임진다.
12. **i18n 사전을 고쳤으면 dev 서버를 재시작하고 검증한다**(120차 · 148차 재현) — HMR `?t=` 분화로

   `blendCondition`(수량 가중 「부패까지 남은 시간」)으로 섞는다 — 한쪽 상태로 통째로 바꾸면 상한 1 + 새것 8 = 전부 상함 · 묵은 것 + 새것 = 전부 싱싱(되살리기)이다.

   `qty`를 직접 깎는 코드를 새로 만들지 않는다.
