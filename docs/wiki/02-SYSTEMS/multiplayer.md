# S24 — 싱글/멀티플레이

> 상태 🔶 **부분** (143차 신설) — 로비·세션·이름 유일성·같은 지역 이름표까지.
> 세계 상태(퀘스트·인벤·설치물)는 아직 각자의 것이다.

## 1. 목적·범위

**책임진다**

- 플레이 방식 선택(혼자 / 여럿이)과 그 진입 순서
- 세션(= 한 세계) 열기·참가
- **세션 안 캐릭터 이름 유일성**
- 같은 지역에 있는 사람의 위치·이름표

**책임지지 않는다** (아직)

- 세계 상태 동기화(퀘스트·우호도·인벤·재화·설치물·어획)
- 충돌·밀림, 거래, 채팅
- 서버 권위 판정(치트 방지)

## 2. 구성

| 층 | 파일 | 역할 |
|---|---|---|
| 계약 | `packages/core/src/types/Multiplayer.ts` | 코드 규격·이름 정규화/검사·DTO·진행 문구. **클라이언트와 서버가 같이 읽는다** |
| 서버 | `packages/server/src/multiplayer/SessionRegistry.ts` | 인메모리 세션·이름 선점·위치·자리 비움 정리 |
| 서버 | `packages/server/src/multiplayer/routes.ts` | `/mp/*` REST |
| 클라 | `packages/client-pc/src/net/MultiplayerClient.ts` | 접속 상태 싱글턴 · 1초 폴링 · `peersInRegion` |
| 클라 | `packages/client-pc/src/scenes/MultiplayerLobbyScene.ts` | 로비 화면 |
| 클라 | `scenes/MainMenuScene.ts` | 방식 분기 · 로비 복귀 시 슬롯 직행 |
| 클라 | `scenes/CharacterCreateScene.ts` | 이름 중복 검사 + 진행 문구 4단계 |
| 클라 | `scenes/RegionFieldScene.ts` | 위치 보고 · 다른 사람 스프라이트·이름표 |

## 3. 동작 구조

```
메인 메뉴 ─ 게임 시작 ─┬─ 혼자 하기 ─────────────→ 슬롯(새로/이어) ─→ (새로면) 캐릭터 만들기
                       └─ 여럿이 하기 ─ 로비 ─ 방 열기/코드 참가 ─→ 슬롯 3칸 ─→ 캐릭터 만들기
```

캐릭터 만들기 `[이대로 생성하기]`

| 단계 | 화면 문구 | 하는 일 |
|---|---|---|
| 1 | `중복 여부 확인중` | `POST /mp/session/:code/name-check` |
| 2a | `중복 여부 통과` | 통과 |
| 2b | **빨간 글씨** `캐릭터 이름이 중복되어 생성할 수 없습니다! 이름을 변경하세요.` | 중단(재시도 가능) |
| 3 | `생성 중 로딩` | `POST /mp/session/:code/join` (이름 선점) |
| 4 | `접속중` | 필드 진입 · 위치 폴링 시작 |

싱글이면 3단계만 짧게 지나간다.

**REST 목록**

| 메서드 | 경로 | 하는 일 |
|---|---|---|
| POST | `/mp/session` | 방 열기 → 6자리 코드 |
| GET | `/mp/session/:code` | 방 조회(인원·이름 목록) |
| POST | `/mp/session/:code/name-check` | 이름 형식 + 중복 |
| POST | `/mp/session/:code/join` | 이름 선점 + playerId 발급 |
| POST | `/mp/presence` | 내 위치 올리고 남의 위치 받기 (1초) |
| POST | `/mp/leave` | 나가기 |

## 5. 잔여·차기

착수 순서는 **"세계에 물건이 놓이는 것"부터** — 설치물 공유 → 공용 시드 → 외형 → 채팅 → 권위.
자세한 근거는 워크로그 143 §8.

선행 조건: 설치물 공유는 `SaveData.worldObjects`를 세션 저장소로 올려야 하므로,
**세션에 영속 저장이 생긴 뒤**에 한다(지금은 프로세스 메모리).

## 6. 함정·불변조건

- **`types/Multiplayer.ts`는 양쪽이 같이 읽는 계약**이다. 여기 모양을 바꾸면 서버와 클라이언트를
  같이 고쳐야 한다 — 한쪽만 고치면 조용히 어긋난다(응답 필드가 `undefined`가 될 뿐 에러가 안 난다).
- **이름 유일성은 세션 범위**다. 세션이 다르면 같은 이름이 있을 수 있다.
  `characterNameKey`는 공백·대소문자만 접는다.
- **서버가 없어도 게임이 멈추면 안 된다** — `MultiplayerClient`의 모든 요청은 실패 시 `null`을
  돌려주고 `offline` 플래그만 세운다. 새 호출을 추가할 때 이 규칙을 깨지 말 것.
- **`reportPosition`은 `RegionFieldScene.update`에서만 부른다.** 1인칭 낚시·상점은 필드를
  `pause`하므로 그 사람은 마지막 자리에 서 있는 것으로 보인다(사라지지 않는다) — 의도된 동작이다.
- **다른 사람에게 충돌 바디가 없다.** 추가할 때는 `poiWalls`처럼 별도 그룹으로 만들고
  폴링 주기(1초)와 위치 보간을 함께 넣어야 한다 — 지금 좌표를 그대로 바디로 쓰면 1초마다 순간이동한다.
- **헤드리스 검증 함정**: 두 번째 탭은 소프트웨어 WebGL로 떨어져 ≈5fps다. Phaser `delayedCall`은
  게임 루프 델타로 진행하므로 대기 시간이 실시간 몇 배로 늘어난다. 하네스 대기를 넉넉히 잡을 것.
