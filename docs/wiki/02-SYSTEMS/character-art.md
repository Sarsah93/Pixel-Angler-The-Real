# S23 — 캐릭터 아트 (바닐라 베이스 + 페이퍼돌)

> 상태 🟢 운영 · 최근 142차(2026-09-16)
> 정본: `core/src/art/CharacterArt.ts` · `core/src/art/CharacterCast.ts` · `client/src/ui/CharacterSprite.ts`

---

## 1. 무엇인가

캐릭터·NPC 그림을 **코드가 소유한다.** 외부 이미지를 런타임 축소해 쓰지 않는다.

- 아트 셀 **32 × 32 아트 px**, 몸 26행(머리끝 y=3 ~ 발바닥 y=28)
- 게임 표시는 **정수 ×2** → 64 × 64 화면 px · 몸 52px
- **그레인 2px** = Kenney 지면(16px ×2)·해안 시트와 동일 격자

---

## 2. 규격 (바꾸면 전부 어긋난다)

| 상수 | 값 | 의미 |
|---|---|---|
| `CHAR_CELL` | 32 | 셀 한 변(아트 px) |
| `CHAR_HEAD_TOP` | 3 | 머리 꼭대기 행 |
| `CHAR_FOOT_Y` | 28 | 발바닥 행(포함) |
| `CHAR_SCALE` | 2 | 표시 배율 — **정수 고정** |
| 시트 | 160 × 128 | 열 = 프레임 5(대기 + 걷기 4) · 행 = 방향 4 |
| 머리 | **9행 × 10px**(정면) / 9px(측면) | 140차 — 구 10×12는 어깨(10)보다 넓었다 |
| 다리 | 10행 | 머리에서 뺀 1행 |
| `FaceShape` | oval · round · square | `L_headShape`가 살·머리카락·모자를 한꺼번에 깎는다(턱선에서 읽힘) |

배치 y 보정: 원점 (0.5, 1)이므로 `y + (CHAR_CELL − 1 − CHAR_FOOT_Y) × scale`을 써야 발이 지면에 닿는다.

## 3. 레이어 (아래 → 위)

```
hairBack → skin → underwear → pants → shirt → outer
→ shoes → gloves → edges → pack → face → hairFront → hat → held
```

모든 레이어는 `pose(dir, frame, sex)`가 주는 **앵커 사각형만** 참조한다.
신규 장비 = 그리기 함수 1개 + `CharOutfit` 필드 1개.

`edges`는 같은 색 면이 덩어리로 뭉치는 것을 막는 1px 분리선(팔 안쪽·다리 사이·목 그늘)이다.
픽셀아트에서 실루엣을 읽게 하는 가장 값싼 1px이라 **빼면 캐릭터가 통나무로 보인다**.

### 3.1 룩 규칙 (142차 — 시안 정합)

사용자 시안(스타듀 계열)을 **시트로 들여오지 않고 그리기 규칙으로** 옮겼다.
격자·앵커 계약은 그대로이고, 아래 네 가지가 인상을 결정한다.

| 규칙 | 값 | 왜 |
|---|---|---|
| 머리카락이 이마를 덮는 행 | `HAIR_CAP_ROWS = 4` | 이마가 드러나면 아무리 다듬어도 "어른 얼굴"로 읽힌다 |
| 눈 행 | `EYE_ROW = 5` · 2px × 2행 | 위 행 = 동공(검은 바) · 아래 행 = 홍채. 흰자를 크게 넣으면 멍해진다 |
| 눈썹 | `buzz`·`topknot`만 | 앞머리에 가리는 것이 정상. 9행 얼굴에 어두운 띠 2줄은 험상궂다 |
| 아웃라인 | 이웃 색 + `OUTLINE_MIX 0.68` | 머리카락 옆은 갈색, 피부 옆은 살구 — 단색 테두리는 도트를 납작하게 만든다 |

정수리는 `r-1` 볼륨 행 + `r0` 1px 인셋으로 **둥글게** 깎고, 모자 왕관도 같은 인셋을 따른다
(안 그러면 머리보다 넓은 가로 막대가 공중에 뜬 것처럼 보인다).
팔은 2px 폭이고 몸통 바깥 열 1px 그늘(`armSeam`)로 떼어 놓는다 — 어깨 폭 14 = 머리 폭의 1.4배.

## 4. 바닐라 규약

**베이스 = 나체 + 언더웨어**(여성은 상의 속옷 포함). 상의·하의·신발은 **전부 장착 아이템**이고,
캐릭터 생성 직후 `starterOutfit()` 한 벌이 입혀진다. 자료구조상 "옷을 벗은 상태"가 정상 상태다.

## 4.5 착용 반영 (151차 — `data/EquipOutfit.ts`)

138차가 페이퍼돌을 세웠지만 **인벤토리의 착용 상태를 읽는 곳이 한 군데도 없었다**
(`refreshCharacterLook()` 호출측 0). 그 배선이 여기다.

- `characterLook()` = **지금 화면에 그려야 할 설정.** 모든 렌더 호출측은
  `GameState.character` 대신 이것을 쓴다(장비창·필드 스프라이트·혼잣말 초상·멀티 외형).
- ⚖ **덮어쓰기지 대체가 아니다.** 생성 때 고른 옷차림이 **기저**로 남고 착용분만 위에 덮는다.
  전면 파생으로 만들면 시드 옷이 기본 미착용이라 **새 캐릭터가 벗고 시작한다**(실측).
- ⚖ **기저는 절대 수정하지 않는다.** 매번 기저에서 다시 덮으므로 여러 번 불러도 결과가 같다.
  기저를 갈아치우면 두 번째 호출부터 "벗은 장비가 안 벗겨지는" 상태가 된다.
- 매핑 기준은 **아이템 id 표**(`ITEM_LOOK`)가 먼저 — 표시명은 로케일·개명으로 흔들린다.
  미등재 장비는 `subCategory` + 이름 낱말로 추론한다(`비니|털모자` → beanie · `조끼|베스트` → outer vest 등).
- 손 도구는 `InvItem.tool`이 `held`를 정한다(rod / net). 회칼처럼 레이어가 없는 도구는 빈손.
- 재굽기 훅: 씬의 `inventory-changed` + 장비창 `onChanged` → `refreshCharacterLook()`.

## 4.6 대화 초상 (152차 — `art/FacePortrait.ts`)

대화창·일지·혼잣말의 얼굴 초상은 **필드 시트를 자르지 않는다.** 같은 `CharConfig`로
**32x32 전용 격자에 처음부터 다시 그린다**(`renderFacePortrait()`).

왜 갈랐나 — 필드 격자(셀 32x32 아트 px · 몸 26행)에서 **실제 얼굴은 가로 10 · 세로 9줄**뿐이다.
150차는 그 창(16x16)을 잘라 NEAREST로 키웠고, 몇 배로 늘려도 눈은 사각형 두 개, 코는 없고,
인물끼리 구별이 되지 않았다. 사용자 지적("단순 확대가 아니라 픽셀 단위와 그래픽 퀄리티를 높여야 함")이 정확했다.

초상 격자에서 처음으로 각자 화소를 갖는 것:

- 눈 — **흰자 · 홍채 · 동공 · 하이라이트 · 윗눈꺼풀선 · 눈초리**(+ 여성 속눈썹)
- 코 — 콧대 그늘 + 반대쪽 하이라이트 + 콧방울 + 코밑 그림자 + 인중
- 입 — 윗입술(어둡게) / 아랫입술(밝게) 2행 + 입꼬리
- 귀 · 턱 그늘 · 목 · 어깨 · 광대 하이라이트 · 볼 홍조
- 머리 — 정수리 볼륨 · 윤기 띠 · **앞머리 술**(들쭉날쭉한 끝단) · 스타일별 옆/뒷머리
- 수염 — 턱선 두 칸 + 안쪽 체크 무늬(성글게) + 콧수염
- 모자 — 왕관 + 종류별 챙(cap/sun/beanie/bandana/visor)

부위 행은 한 곳에서만 정한다(`BROW_Y` · `EYE_Y` · `NOSE_Y` · `MOUTH_Y`) — 서로 밀리면 곧바로 이상한 얼굴이 된다.
얼굴형 3종은 **행별 반폭 표**(`JAW`)로만 갈린다(턱선에서 읽힌다 — 이마~정수리는 머리카락이 덮는다).

⚠ **필드 스프라이트(`CharacterArt.ts`)는 한 줄도 건드리지 않았다.** 몸 격자·레이아웃 불변.
⚠ **표시 크기는 150차와 같다** — 호출부가 넘기는 `scale`(16px 창 기준)을 32 격자 배율로 환산한다
(`ensureFacePortrait`). 환산을 빼면 초상이 두 배로 커진다.
⚠ 텍스처 키가 `face_*` → **`face2_*`**. 런타임 생성이라 세이브 무관.

**155차 — 필드 시트와 문법 정합.** 사용자: *"초상화와 캐릭터가 안맞음"*. 초상이 필드와 **다른 규칙**을 쓰고 있었다:
눈썹을 항상 그렸고(필드는 앞머리가 이마를 덮어 `buzz`·`topknot`만 눈썹), 눈이 흰자+홍채 2행이었고(필드는 **동공 바 + 홍채**),
수염에 콧수염이 붙었고(필드는 턱선 한 행), 모자 왕관이 머리 행을 덮지 않았다. 네 가지를 필드 규칙에 맞췄다 —
눈썹 조건 · 눈 3행(동공 바 / 홍채+하이라이트 / 홍채+밑그늘) · 턱수염만 · 스타일별 앞머리 하단·옆머리 깊이 · `crown(bot)` 모자.
⚠ 여전히 **같은 `CharConfig`에서 두 렌더러가 따로 그린다** — 필드 룩 규칙(§3.1)을 바꾸면 초상도 같이 본다.

`applyBlush`(입 상자 기준 좌우 위 타원)다 — 216장(약 1만 3천 원) 대신 크레딧 0. 치환 전에 기준 피부 위에서 하고 키에 `_m_<입>` · `_b`가 붙는다.

**(기록 · 주인공 24장 · 치환 자리 규칙은 271에서 폐기 — 인물 42장 · 앵커 규칙은 그대로) 268차 — 그림 66장이 들어왔다.** 인물 42 · 주인공 24(`public/faces/` · 목록 66키). 화풍 · 도트 밀도는 **앵커 한 장**(`--ref` — 첫 정옥선 그림)으로 고정한다 —
앵커 없이는 한 장은 128칸급, 다른 장은 32칸급으로 밀도가 갈렸다. 뒤에 얼굴을 더 뽑을 때도 같은 앵커(없으면 `public/faces` 두 장 자동)를 쓴다.
주인공 치환(`FacePhoto.recolorFace`)은 **색 + 자리**다 — 머리 = 머리색 픽셀의 8-연결 성분 40픽셀 이상 → 1픽셀 선 가지치기 → 둘러싸인 하이라이트 → 어두운 갈색 3번 번짐 ·
눈동자 = 흰자(L > 170 · 퍼짐 < 45) 3픽셀 안 · 눈 띠(세로 0.36~0.52) · 머리 밖(색조 허용 0.45) · 머리에서 버려진 그늘은 피부로. 색조만(0.13)으로는 코 · 입 · 목 그늘이 머리색이 됐다.

**267차 — 그림 초상이 먼저다.** `ensureFacePortrait(scene, cfg, scale, who)`는 `who`(인물 id · `'player'`)가 있으면 `ui/FacePhoto.ts`의
`photoPortraitKey`를 먼저 묻는다 — `face_<id>` 텍스처가 있으면 그것, 주인공은 층을 합성한(271)
`face_player_<성별>_<얼굴형>_<머리 모양>_v_<피부>_<머리>_<눈>[_bd_<수염>][_m_<입>][_b]` 텍스처(한 번만 굽는다). 없으면 아래 32×32 절차 초상 그대로다. 호출부는 넷(대화창 · 혼잣말 · 일지 2곳)이고 전부 `setDisplaySize`로 칸에 맞춘다.

## 5. 캐스팅 (NPC 41인)

`CAST_TRAITS`에 **성별·연령·역할**만 표로 두고, 나머지(피부·머리색·머리모양·눈·입·복장)는
**id 해시로 결정적 분화**한다. 손으로 굳히려면 `CAST_OVERRIDE`에 한 줄.

- 역할 18종 → 복장 원형(`outfitOfRole`)
- 연령 → 머리색 풀 + 수염 여부
- 검증: 41인 `charCfgKey` **고유 41 / 중복 0**
- **166차 — 마을 사람 `amb_<지역:맵>_<n>`**: 역할만 풀에서 뽑고 성별·연령은 해시. 속초 120명 텍스처 고유 120.
  구 gem NPC 5종(`ts_gem_npc_*`)은 로드조차 하지 않는다 — 필드의 모든 사람이 이 렌더러다.

## 6. 함정

- ⚠ **비정수 배율 금지.** `setDisplaySize`로 크기를 맞추면 그레인이 무너진다 —
  구 캐릭터가 맵과 어긋나 보이던 **바로 그 원인**(×0.111 축소).
- ⚠ **idle과 walk를 다른 해상도 원본에서 가져오지 말 것.** 구 에셋은 idle ×0.111 / walk ×0.261이라
  걷기 시작하면 스프라이트가 또렷해지고 폭이 3px 널뛰었다.
- ⚠ **캐스트 해시 규칙을 바꾸면 기존 세이브의 NPC 얼굴이 전부 바뀐다**(외형을 저장하지 않고 id로 재생성).
- ⚠ 접지 프레임 2장(walk1·walk3)은 **좌우 체중 이동(sway)** 으로 구분한다. 안 그러면 같은 그림이 된다.
- ⚠ 텍스처 키 = 설정 해시(`chr_<hash>_<scale>`). 장비를 갈아입으면 **새 시트가 자동으로 구워진다** —
  캐시가 무한히 늘 수 있으므로 변형이 많아지면 LRU가 필요하다(현재 미구현).
- ⚠ **착용 반영은 기저를 덮어쓰지 말 것**(151차). `characterLook()`은 매번 기저에서 새로 덮는다 —
  `GameState.character.outfit`을 직접 바꾸면 그다음 호출이 이미 덮인 것을 기저로 삼아 **벗기가 동작하지 않는다.**
- 검수 PNG는 `tools/render_char_preview.mjs`가 **게임과 같은 함수**를 호출해 뽑는다.
  별도 프리뷰 렌더러를 만들면 "여기선 예쁜데 인게임은 다른" 상태가 된다.
- ⚠ **외부 생성 시트를 그대로 임포트하지 말 것**(142차 판단). AI 생성 시트는 격자가 안 맞고
  (실측 열 3.05배 ↔ 행 3.5배) 프레임 일관성이 없으며, 무엇보다 **페이퍼돌을 입힐 수 없고**
  NPC 41인 결정적 분화가 불가능하다. 스타일은 그리기 규칙으로 옮긴다.
- ⚠ **그림 초상 치환은 색만으로 머리와 피부를 못 가른다**(268차). 밤색 머리와 주황 피부는 색조가 같고 밝기만 다르다 — 피부 그늘(L ≤ 150)이 머리 밝기 범위에 든다.
  머리 밝기 상한을 올리면(1.7배 → 2.0배) 얼굴에 흰 조각이 생긴다. 자리(연결 성분 · 흰자 거리 · 눈 띠)로 가르고, 눈 띠는 설치 틀(96칸 · 어깨 바닥)에 묶여 있으니
  틀이 바뀌면 흰자 행을 다시 잰다(scratchpad `face_white_probe.cjs` 패턴).
  **270차** — 곱셈 칠하기(고른 색 × 밝기 비)는 밝은 색에서 255에 잘려 하얗게 뜬다 → 두 톤 모델. 씨앗을 깎았다가 **안 깎은 성분을 통째로 되살리면** 코 옆 그늘 · 콧수염까지 머리가 된다 —
  되살리지 말고 번짐에 맡긴다. 피부 씨앗 하한을 전역으로 내리면(100 → 40) 머리 하이라이트의 피부색조 덩어리가 피부가 되어 머리 위에 갈색 얼룩이 생긴다(얼굴 상자 안에서만 40).
  수염 구역 아래 끝을 「어두운 픽셀이 N개 이상인 마지막 줄」로 잡으면 뺨 폭 안에 늘어진 포니테일 · 목 양옆 윤곽선 때문에 목까지 내려간다 — 턱 윤곽선(가운데 띠 어두운 비율 ≥ 0.5)으로 잡는다.
- ⚠ **설치 배경 벗기기는 갇힌 흰 배경에 못 닿는다**(270(2)). 테두리 BFS라 머리카락 · 목 · 어깨가 에워싼 순백 조각(판마다 8~228px)이 남아 어두운 대화창에서 흰 배경으로 보인다 — 치환과 무관하게 모든 색에서.
  `--install`이 96칸으로 구운 뒤 `fillWhitePockets`를 부르고 로그에 「흰 주머니 Npx」를 찍는다. 새 판은 어두운 바탕 위에 놓고(scratchpad `pocket_view.mjs` 패턴) 머리 뒤 · 목 옆을 본다.
  순백(≥ 246)만 지우므로 배경이 회색인 판은 못 잡는다. 눈썹을 머리 라벨로 두면 흰 머리에서 눈썹이 하얗게 뜬다 — 머리색의 색조만 따르고 밝기는 원래 눈썹까지(`LABEL_BROW`).
- ⚠ **층 원판은 앞 판을 같은 인물 앵커로**(271). 앵커 없이 따로 뽑은 판(268의 24장)은 서로 다른 사람이라 차이로 층을 뜰 수 없다.
  기본판을 다시 뽑으면 그 성별 머리 · 수염 층 전부를 다시 뽑고 같은 폴더에서 다시 굽는다(틀 = 성별마다 하나 · 합집합 상자라 판 하나가 바뀌면 틀이 바뀐다).
  마스크가 틀린 자리는 라벨 규칙이 아니라 `tools/face_layer_fixes.json` 사각형 한 줄로 고친다(규칙을 다시 만지면 다른 판이 틀어진다). 순백 칸은 층에서 비운다(머리칼 사이 갇힌 배경).
  틀은 기본 · 머리 판으로만 잡는다(271(2)) — 뒤에 뽑은 수염 판을 넣으면 어깨선 1~3px 차이로 틀이 밀려 설치된 층 전부가 바뀐다.
- ⚠ **머리 위 라벨은 머리 꼭대기가 아니라 셀 상단을 기준으로** 잡는다. 비니 방울·챙·곱슬 돌기가
  머리 사각형보다 최대 3행 위로 나오므로, 머리 기준이면 모자 쓴 인물에서 글자가 파묻힌다
  (`RegionFieldScene.charTopFromFeet` — 142차).

## 6.5 생성 화면 (`CharacterCreateScene`) — 139차 재정비

- 패널 3장은 **`paintHudPanel`**(미리보기 / 외형 / 푸터) — HUD와 같은 문법. 버튼은 `paintHudSlot`.
- **색은 숫자가 아니라 견본**으로 고른다. 픽셀 팔레트에는 이름이 없어 `3 / 10` 표기로는
  무엇을 고르는지 알 수 없다. 수염은 팔레트 앞에 **'없음' 사선 칸**(인덱스 -1)을 둔다.
- 12행은 **2열 5섹션** — 좌 `체형`·`얼굴` / 우 `머리`·`복장`·`이름`.
- 선택 강조는 **색 + 좌측 금색 바**만 바꾼다(메인 메뉴 관례) — 폰트 교체는 레이아웃을 흔든다.
- 미리보기는 **실게임 시트**(`ensureCharSheet`) 그대로, 배율 10. 방향 회전은 `setFrame`만 교체한다.
- 견본 칸 폭은 `min(26, ⌊240 / n⌋)` — 팔레트가 늘어나도 조작 영역(240px)을 넘지 않는다.

### 6.5.1 프리뷰 조작대 (144차)

미니어처 4종(정면·좌·우·후면)을 폐기하고 **큰 프리뷰 하나를 돌려 보는** 방식으로 바꿨다 —
네 장을 작게 늘어놓는 것보다 실제 인게임 크기와 같은 한 장이 판단에 쓸모가 있다(사용자 지시).

- 하단 인셋 `(56, 470, 398, **146**)` — 구 104에서 미니어처 자리를 흡수했다.
- **회전 행**(`cy 515`) — `◀`(cx 167) · 방향명 텍스트(cx 255) · `▶`(cx 343), 각 48×30.
  순서 `TURN_ORDER = ['down','left','up','right']`, `◀` = +1(화면에서 왼쪽으로 돈다).
- **동작 행**(`cy 571`) — 정지 / 걷기 / 달리기, 각 116×32(cx 131·255·379).
  선택된 동작은 `paintHudSlot(active)`로 그린다.
- 실측 버튼 상단 **500** · 하단 **587** ≤ 인셋 616 ≤ 패널 628.
- **자동 회전(2.4초)은 폐기**했다 — 방향은 버튼이 전담한다.

⚠ **'기타 행동'은 존재하지 않는다.** 시트가 가진 모션은 대기(frame 0)와 걷기 4프레임뿐이고,
달리기는 **같은 걷기 프레임을 `TUNING.vitals.runSpeedMult`배로 돌린 것**이다.
